    Dokicraft — high-fidelity voxel survival game engine in C++¶

    Context¶

    Dokicraft is a from-scratch C++ game engine and survival game: Minecraft-like gameplay but at a higher fidelity level — smaller voxels, modern shaders and lighting, streamed worlds. Solo/small-team project targeting Windows x64 and high-end GPUs (primary dev/target machine has an RTX 5090). The user's stated tech preferences, honored unless research shows a clear winner elsewhere: open-source rendering API (Vulkan), open-source UI framework (Dear ImGui; web-tech HTML/CSS style highly preferred but only if high performance), and "Box3D" physics (no such library exists — read as "a 3D physics engine"; research evaluates Jolt / Bullet / PhysX).

    §3 — Engine core: window → Vulkan boot → frame loop (medium detail)¶

    • Window + input via SDL3 (SDL_WINDOW_VULKAN, SDL_Vulkan_CreateSurface), fly camera.
    • Vulkan 1.3 boot via volk: volkInitialize() → instance → volkLoadInstance() → device → volkLoadDevice(). Instance (validation optional — absent SDK; guard layer/extension absence), physical-device scoring that prefers the discrete GPU (see trap), VMA, swapchain, dynamic rendering + sync2, N frames in flight.
    • Runtime shader compile (shaderc) GLSL→SPIR-V with on-disk cache.
    • Dear ImGui overlay (debug HUD: device name, frame time).
    • imgui + volk trap (resolve here, not §2): the vcpkg imgui Vulkan backend is built without VK_NO_PROTOTYPES, but our engine uses volk (no static loader). Call ImGui_ImplVulkan_LoadFunctions(apiVersion, loaderFn) forwarding to vkGetInstanceProcAddr/volk so the backend resolves entry points through volk; otherwise link vulkan-loader. §2 doesn't touch the backend so it's inert until now.
    • Acceptance: smoke C1 (boot on RTX 5090, clean validation when layers present) + C2 (smooth fly camera) pass; conventions review clean.
