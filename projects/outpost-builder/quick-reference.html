Quick Reference - The Cheat Sheet

Keep this one open on the second monitor. It's the short page: keys, defaults, and the names of things, with no reasoning attached. Every section points at a page that explains itself properly, so follow the link when you want the why.

reference.html is the exhaustive one, every public method and property per class. This page is what you want while you're actually working.

Get It Running

git clone https://github.com/defessler/OutpostBuilder.git
mklink /J "YourProject\Plugins\OutpostBuilder" "path\to\OutpostBuilder"
Build.bat YourProjectEditor Win64 DebugGame

Then open the level editor's Modes panel and pick Outpost Builder. The plugin ships EnabledByDefault: true, so it should already be listed. The long version, including the build flags we use locally, is on index.html.

The Loop

  1. Place an outpost. Overview panel, Outposts tab, Add New Outpost, then Create, then click in the viewport. A UOutpostDefinition asset is created under /Game/Outposts.
  2. Add plots. Press N and click. Repeat.
  3. Assign buildings. Pick a palette tile with 1-9. The hot building auto-assigns to every plot you place next.
  4. Frame the camera. Press O, fly the viewport, press Enter.
  5. Fence the base. Press B to reshape the Outpost Volume.
  6. Stamp it again. Drag the definition from the Content Browser back into the level.

Hotkeys

Every chord below is rebindable under Editor Preferences > Keyboard Shortcuts > Outpost Builder. These are the shipped defaults. The in-viewport legend and the palette tile badges read the live chords, so they follow a rebind without you having to come back here.

While editing an outpost

Key What it does
N New Plot. Starts a plot placement.
O Position Overhead Camera. Pilots the viewport onto this outpost's camera.
B Edit Outpost Volume. Creates it if missing, then drops you straight into brush editing.
J Randomize Plots. One random eligible building per selected plot.
E Eyedropper. Loads the building on the plot under the cursor into Selected Building. An unassigned plot picks the Empty tile and says so.
1-9 Select palette building 1 through 9. A tenth is click-only.
0 Select the Empty tile, so the next plots are placed unassigned.
Ctrl + S Save every dirty outpost and building definition, then pass through so the editor's own level save still runs.

While placing

Input What it does
LMB Place. Refused while the plot ghost is red, and the click is eaten either way.
RMB tap or Esc Cancel the session. An RMB drag still orbits.
Ctrl held Plot placement only. Flips into the remove tool: LMB deletes the plot under the cursor. Release to carry on placing.

The remove modifier is configurable (Ctrl, Alt, or Shift) on the per-user settings. It isn't a rebindable chord, because a hold needs per-frame state rather than a key event.

While positioning the Overhead camera

Key What it does
Enter Done. Saves the framing to the definition and hands your viewport back.
Home Revert to the last saved framing for the current target, or the computed default when there's none yet.
Esc Cancel and restore the viewport.

Whether you're framing the whole outpost or one plot is decided by what was selected when you pressed O, not by what's selected when you press Enter.

Mouse, fixed and not rebindable

Gesture What it does
LMB double-click an outpost Enter editing on it, or leave editing when it's the one you're already on. One gesture, both doors. No modifier held.
LMB single click Select. Only outpost-family actors are selectable while the mode is active. Everything else clicks through.
Alt + LMB drag The editor's own orbit, untouched.

Where the Knobs Live

Surface What's on it Scope
Project Settings > Plugins > Outpost Builder One pointer, the Settings Asset. Nothing else. Project
The settings asset itself New-definition folder, exclusion distance, plot size dimensions, the four actor class overrides, the empty and preview meshes. Project, source-controlled
Editor Preferences > Outpost Builder Colors, sizes, timings, the remove modifier, the building grid's shape. Per user, never source-controlled
Editor Preferences > Outpost Builder > Outpost Utilities The companion utility switches, all off until you turn the master on. See "The Utility Modules" below. Per user
Editor Preferences > Keyboard Shortcuts > Outpost Builder Every chord in the tables above. Per user

Change a knob on either settings surface and the mode picks it up on the next draw. No rebuild.

Plot Sizes

Four native tags ship under OutpostBuilder.PlotSize. Every pad is a square.

Tag Default pad Stored half-size
OutpostBuilder.PlotSize.Small 400 x 400 cm 200
OutpostBuilder.PlotSize.Medium 800 x 800 cm 400
OutpostBuilder.PlotSize.Large 1200 x 1200 cm 600
OutpostBuilder.PlotSize.Heavy 1600 x 1600 cm 800

Retune any of them in the settings asset's Plot Size Tags map, which stores the half-size in cm. Add your own sizes as ordinary child tags of OutpostBuilder.PlotSize in your project's gameplay tag config, with no plugin change needed. A tag with no entry in that map falls back to Small's dimensions, and an unset tag reads as Small everywhere.

The Three Matching Rules

All three live on the building definition. All three treat an empty value as a wildcard, so a building with none of them filled in fits everywhere.

Field Tested against Empty means A mismatch
PlotSizeQuery the plot's PlotSizeTag fits every size Blocks. Assign refuses and the tooltip says why. Randomize drops it from the pool.
SupportedFactions the outpost's faction fielded everywhere Blocks. The building leaves the palette entirely rather than showing disabled.
PlotTagQuery the plot's PlotTags fits every plot Warns only. A tooltip line, a tile glyph, a plot list drift icon, an amber ghost. It still places.

Two rules a plain membership test would miss:

  • A Neutral outpost accepts every building, whatever that building's SupportedFactions lists. That's checked before the set is read at all.
  • A mismatch never auto-deletes or reassigns a building already sitting on a plot. It keeps its plot and keeps rendering.

The plot tag vocabulary is entirely yours. The plugin registers no native tags for it, unlike plot size. Author your own in DefaultGameplayTags.ini.

Reading the Plot Ghost

Three states, told apart by fill treatment rather than hue alone:

Ghost Meaning
Solid green plate Clear. The click places.
Hollow amber plate Legal. The Selected Building's PlotTagQuery just won't be satisfied by the plot this click creates. It still places.
Solid red plate with an X Refused. The click is consumed and nothing happens.

Three numbers print beside the ghost while you place a plot: distance to the outpost's center, the pad's size, and the clear gap to the nearest neighboring plot's edge. That last one reads "Overlap" once it goes negative, and it's omitted when there's no sibling to measure against.

Types at a Glance

Type What it is
UOutpostDefinition The template. Plot records, camera records, faction, display name.
UOutpostBuildingDefinition One building. Mesh, actor class, the three matching rules, category tag.
UOutpostBuilderSettingsAsset The project's shared knobs. One per project, pointed at from Project Settings.
AOutpost The anchor actor. Every other family actor keys off its definition id.
AOutpostPlot One buildable pad. Carries a runtime mesh component, so a stamped base renders in packaged games with no extra call.
AOverheadCamera Exactly zero or one per outpost, however many plots have a saved framing.
AOutpostVolume The exclusion fence. A brush volume, reshaped with the stock geometry tools.
UOutpostStampLibrary StampOutpost (forks the definition), PlaceDefinitionAt (doesn't), RestoreOutpostFromBaked (the recovery path).
FOutpostInstanceId Which placed outpost an actor belongs to, where the definition id says only what it was built from.
UOutpostRegistrySubsystem Answers about baked outposts with no level loaded.

The one structural fact worth carrying into every other page: plots and cameras are never attached to their outpost. They're flat actors that write records back to the definition. architecture.html covers why.

The Companion Utilities

These shipped for a while as their own OutpostUtilities and OutpostEditorUtilities pair, and now live in the two core modules: the runtime half in OutpostBuilder, the editor half in OutpostBuilderEditor. They stay purely additive. With the master switch off, the plugin behaves exactly as it did before they existed.

Turning them on

Everything except the registry bake is inert until you switch it on at Editor Preferences > Outpost Builder > Outpost Utilities. These are per-user workflow switches (config, not defaultconfig), so they don't travel in source control.

Setting Default What it does
Enable Companion Utilities Off The master switch. Everything below it is inert until this is on, the registry bake excepted.
Spawn Overhead Camera On An outpost entering the level brings an Overhead camera with it.
Spawn Outpost Volume On An outpost entering the level brings a bounds volume with it.
Defer Companion Spawn On Waits a tick so whatever else is mid-placement finishes first and its own companions get counted. Turning it off puts the outpost and its companions on one undo step, which is safe only when nothing else places outposts.
Cascade Group Delete On Deleting a blank-id outpost deletes the companions spawned with it. Blank-id outposts only, since the plugin's own cascade already owns every outpost that has a definition id.
Bake Registry On Save On Its own switch rather than riding the master, because a default install that baked nothing would answer every unloaded lookup with silence.
Propagate Definition Id On Setting the definition id on any family actor sets it on the rest of its group.
Enable Placement Actor Factory Off Registers a second drag-drop factory that places one outpost bound to the dropped definition, with no fork.

What runs on its own

FOutpostBuilderEditorModule installs five editor listeners at startup, deferring past a null GEngine when the module loads before UEngine::Init.

Listener What it watches for
ActorAdded An outpost entering the editor world by any route (a Place Actors drag, a paste, a duplicate, an asset drop), and brings its camera and volume along.
GroupCascade A blank-id outpost's deletion, taking its companions with it. Without this a bare outpost's volume outlives the delete, and a stray volume blocks placement around a base that no longer exists.
IdentitySync A definition id set on one group member, pushed out to the rest. It hooks the pre-change half too, because after the change the old id is the only thing still linking a group whose members were never tagged.
InstanceHeal A duplicate or paste, giving the copy its own instance id. A set copied together stays together, and a companion copied alone comes away alone.
RegistryBake Package saves, world saves, and map open. Two save hooks, because under One File Per Actor most outpost edits never touch the world package at all. The registry is marked dirty and never saved from inside the hook.

What you can actually call

Three namespaces carry OUTPOSTBUILDER_API:

Namespace Header What it's for
OutpostBuilder::Group Identity/OutpostGroupTag.h The group link: MakeGroupTag, ParseGroupTag, FindGroupId, FindOrAddGroupId, AddGroupTag, RemoveGroupTag, CollectGroupMembers.
OutpostBuilder::Identity Identity/OutpostIdentitySync.h Definition ids without caring which of the four classes you're holding: IsFamilyActor, GetDefinitionId, SetDefinitionId, CollectLinkedActors, PropagateDefinitionId.
OutpostBuilder::Companion Spawn/OutpostCompanionSpawn.h EnsureOverheadCamera, FindGroupOverheadCamera, ResolveCameraFraming.

The group link is an OutpostGroup.<Guid> entry in AActor::Tags, not a new property on the family. That's what lets it link an outpost to its companions before any of them carries a definition id, and it survives save, load, and copy/paste for free.

An actor belongs to one group only, so AddGroupTag returns false when the actor already carries a tag. EnsureOverheadCamera is idempotent and mints the group id when the outpost has none, so calling it twice hands back the same camera.

The editor half exports nothing at all. The registry bake, the volume build, the label helpers and the five listeners are all module-internal by design. You reach that behavior through the listeners and the console commands, not by linking.

To call the runtime half from your own module, add "OutpostBuilder" to its dependencies. The outpost family types come along with it.

Baking a partitioned map

The save-time bake only sees the cells the editor has loaded. It's honest about that (it upserts what it sees, leaves the rest alone, and records the pass as incomplete), but honest and partial isn't the same as correct. The full pass is a World Partition builder:

UnrealEditor-Cmd.exe <project> -run=WorldPartitionBuilderCommandlet ^
    -Builder=OutpostRegistryBuilder -AllowCommandletRendering -Map=<map>

It loads the entire world rather than one cell at a time, so the registry it writes is complete by construction. It works on ordinary non-partitioned levels too, where the answer is simply already complete. A non-zero exit is what a CI step gates on. With no CI step wired up, Outpost.DumpRegistry's incomplete warnings are your only signal.

Console

Command What it does
Outpost.BakeRegistry Bakes the open level's outposts into its registry asset. Marks the asset dirty without saving, so save to keep the result. On a partitioned map it bakes only the loaded cells and tells you so.
Outpost.DumpRegistry Lists every baked outpost with its handle, level, plot count, and verification state.
Outpost.CheckBounds Checks every outpost's bounds volume in the open level: missing or duplicate volumes, a brush that never got built, a stale cached box, a stale bake, and which plots sit outside their own volume. Lines marked ! are the ones to act on.
Outpost.CheckBounds X Y Z Answers one world-space point against all three containment rules at once - the volume's box, the actual brush, and the baked territory - so you can see where they disagree.
