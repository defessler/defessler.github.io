Reference - Public Surfaces, Hotkeys, and Testing

This page is the complete listing of OutpostBuilder's public surfaces, not a tutorial. Every other page on this site explains the why behind a piece of the plugin. This one just lists the what: every public method and property per class, the hotkey list, the test faction script, and where each file lives. Signatures over bodies.

If you want the reasoning, architecture.html, edmode.html, toolkit.html, prefabs.html, faction-visuals.html (faction identity/gating), and runtime-loadout.html cover the design decisions this page assumes. If you want the short version, quick-reference.html is the one-page cheat sheet.

Runtime Types

Header: OutpostBuilder/Source/OutpostBuilder/DataAssets/OutpostDefinition.h

FOutpostPlotRecord and FOutpostCameraRecord

These are the two record structs a UOutpostDefinition stores. Both transforms are relative to the owning AOutpost actor: World = RelativeTransform * OutpostActorTransform, composed against the outpost's unit-scale record basis (see AOutpost::GetRecordBasisTransform below).

  • PlotId - FGuid identifying one plot record.
  • RelativeTransform (on FOutpostPlotRecord) - the plot's transform relative to the owning outpost.
  • AssignedBuildingId - FPrimaryAssetId (allowed type OutpostBuildingDefinition) for the building assigned to that plot.
  • PlotSizeTag (on FOutpostPlotRecord) - FGameplayTag under OutpostBuilder.PlotSize, never authored unset. An empty tag reaching a consumer anyway resolves as Small via OutpostBuilder::PlotSizeTags::ResolveOrDefault. It's the size of that plot's pad, mirrored onto AOutpostPlot::PlotSizeTag exactly as AssignedBuildingId is.
    • The RECORD is what every stamp/place/restore/fork rebuilds a plot actor from, so a size held only on the actor would be dropped by all of them.
    • The ACTOR is what the live world reads without loading the definition asset.
    • Neither alone is sufficient. Both carry it, with the same write-through discipline.
  • PlotTags (on FOutpostPlotRecord, the placement rule matrix's PLOT half) - FGameplayTagContainer, arbitrary and PROJECT-OWNED (no plugin-registered vocabulary, unlike PlotSizeTag). Mirrored onto AOutpostPlot::PlotTags with the identical write-through discipline PlotSizeTag has.
    • An asset saved before this field existed simply deserializes to an empty container, with no default-resolution step needed.
    • Matched against a building's PlotTagQuery by OutpostEditorUtils::EvaluateBuildingPlotAdvisory (editor module), WARN-ONLY, never a placement/assign refusal. Not checked by ValidateRecordCoherence (that sweep is structural, never field-wise).
  • bIsSet (on FOutpostCameraRecord) - distinguishes "never positioned" from a zero transform.
  • RelativeTransform (on FOutpostCameraRecord) - same relative-to-outpost rule as the plot record.
  • FieldOfView - float, defaults to 50.

UOutpostDefinition stores TWO kinds of FOutpostCameraRecord: the single outpost-level OverheadCamera below, and a per-plot TMap<FGuid, FOutpostCameraRecord> PlotCameras keyed by FOutpostPlotRecord::PlotId. Both use the identical struct and the identical relative-to-outpost basis; see PlotCameras's own entry below for what's different about it.

UOutpostDefinition

  • PrimaryAssetTypeName - static FPrimaryAssetType, value "OutpostDefinition".
  • GetPrimaryAssetId() - { PrimaryAssetTypeName, GetFName() }.
  • GetAssetRegistryTags(Context) - exports hidden OutpostDisplayName/OutpostPlacedPath registry tags so the toolkit's Overview list renders name + placement cue from FAssetData alone (live object if loaded, tags otherwise, LoadSynchronous only for pre-tag assets). An empty OutpostPlacedPath value = never placed.
  • GetPlots() - read-only access to the plot record array.
  • AddPlot(const FTransform& RelativeTransform, FGameplayTag PlotSizeTag = FGameplayTag()) - appends a new plot record and returns its fresh PlotId. An empty tag resolves to Small inside, so a caller with no size to offer still produces a valid default record.
  • AddPlotRecord(const FOutpostPlotRecord& Record) - appends a FULLY-FORMED record, identity included: the rebuild-from-actors seam behind the Overview panel's Restore Definition action (UOutpostBuilderEdMode::RestoreDefinitionFromOutpostActors), where the live plot actors already carry their PlotIds and a freshly minted id would orphan every one of them from its own record.
    • Returns false (no Modify) for an invalid PlotId or one already present. That's the duplicate-id coherence invariant enforced on the way in, so a duplicated plot actor can never displace the first actor's record.
    • An unset PlotSizeTag resolves to Small exactly as AddPlot does.
  • SetPlotRelativeTransform(PlotId, RelativeTransform) - updates one plot's relative transform. False if PlotId isn't found or the value is unchanged.
  • SetPlotAssignedBuilding(PlotId, BuildingId) - same no-op discipline, updates the assigned building.
  • SetPlotSizeTag(PlotId, NewSizeTag) - same no-op discipline, updates the plot record's size tag. The RECORD half of the write-through pair; a caller resizing a live plot must also call AOutpostPlot::SetPlotSizeTag, in the SAME transaction.
  • SetPlotTags(PlotId, NewTags) - same no-op discipline, updates the plot record's general tags (FGameplayTagContainer). The RECORD half of the write-through pair; a caller retagging a live plot must also call AOutpostPlot::SetPlotTags, in the SAME transaction. WARN-ONLY consumer: nothing here enforces PlotTagQuery. See OutpostEditorUtils::EvaluateBuildingPlotAdvisory.
  • RemovePlot(PlotId) - removes a plot record, AND drops any PlotCameras entry keyed to the same PlotId via ClearPlotCameraView. A stranded per-plot camera record would otherwise outlive its plot forever. False if PlotId not found.
  • RegeneratePlotIds() - reassigns a fresh FGuid to every plot record, used on stamped forks so a fork's plots never collide with the template's ids.
    • It ALSO re-keys PlotCameras through the same old-id-to-new-id mapping (rebuilt into a fresh map, not mutated in place, while iterating the old one). That's required, since PlotCameras is keyed by PlotId: skipping this would orphan every per-plot framing on the fork.
    • No Modify/dirty when Plots is empty.
  • GetFaction() / SetFaction(EOutpostFaction) - the definition's persistent faction. Modify+Dirty; SetFaction returns false (no Modify) when unchanged. EOutpostFaction::Neutral is the default. The definition is the source of truth. The live actor syncs from it on edit-mode entry and immediately when the asset is edited directly.
  • GetOverheadCamera() - read-only accessor for the outpost-level FOutpostCameraRecord.
  • SetOverheadCameraView(RelativeTransform, FieldOfView) - updates the saved outpost-level camera view and sets bIsSet = true. False if unchanged and already set.
  • GetPlotCameras() - read-only access to the whole PlotCameras map, keyed by PlotId. Used by AOutpost::ReRelativizeOwnedRecords()'s anchor-move sweep (see architecture.html).
  • GetPlotCameraView(PlotId) - PlotId's saved camera framing, or a shared default-constructed (bIsSet == false) record when it has none. Never a dangling reference for an unknown id.
  • HasPlotCameraView(PlotId) - true iff PlotId has a saved (bIsSet) camera framing.
  • SetPlotCameraView(PlotId, RelativeTransform, FieldOfView) - updates PlotId's saved camera framing; adds the entry if PlotId has none yet. Same no-op discipline as SetOverheadCameraView: false (no Modify) if unchanged and already set.
  • ClearPlotCameraView(PlotId) - drops PlotId's saved camera framing. False (no Modify) if there was none. Called by RemovePlot.
  • RecordPlacement(const AActor& Outpost) - records Outpost as this definition's placed actor: soft path AND world transform together, always. The pairing is the invariant: RestoreOutpost respawns at PlacedOutpostTransform, so recording only the path would restore the base at world origin. (SetPlacedOutpostPath is private for exactly that reason; SetPlacedOutpostTransform below stays public for the anchor-move sync that updates the transform only.)
  • SetPlacedOutpostTransform(NewTransform) - updates the world transform of the placed outpost actor (FTransform::Equals, small tolerance). False if unchanged.
  • DisplayName - FText, editable. Shown (and editable) in the toolkit's Editing panel identity header.
  • Faction property - EOutpostFaction (mirrors AOutpost::Faction), runtime-readable source of truth; Neutral is the explicit no-faction value.
  • OverheadCamera - the outpost-level FOutpostCameraRecord: frames the base as a whole.
  • PlotCameras - TMap<FGuid, FOutpostCameraRecord>, keyed by PlotId: one saved framing per plot, independent of OverheadCamera. Same relative-to-outpost basis as OverheadCamera, NOT relative to the plot's own transform.
    • Deliberate consequence: moving a PLOT does not move its saved framing. Only moving the OUTPOST anchor does, via the ReRelativizeOwnedRecords() sweep.
    • Authoring-time only: StampOutpost/RestoreOutpost still spawn exactly one AOverheadCamera per outpost, from OverheadCamera alone. Nothing at runtime reads this map.
    • See toolkit.html's "The Contextual Overhead Camera" and edmode.html's Overhead camera positioning session for how a designer actually sets these.
  • PlacedOutpostPath - FSoftObjectPath, visible-only. Stays valid even when the actor's level isn't loaded.
  • PlacedOutpostTransform - FTransform, visible-only. Kept current alongside PlacedOutpostPath; RestoreOutpost respawns here.
  • IsDataValid(Context) (WITH_EDITOR) - one WARNING-severity (never Invalid) finding per stored plot assignment whose building's PlotTagQuery rejects the plot's PlotTags. Calls UOutpostBuildingDefinition::MatchesPlotTags directly rather than through OutpostEditorUtils::EvaluateBuildingPlotAdvisory.
    • That's the one documented exception to that function's one-composition rule, because this class lives in the RUNTIME module and cannot depend on OutpostBuilderEditor at all. It's safe because the editor-module function is nothing but this same call wrapped in an enum, with no additional logic to drift from.
    • Loads each assigned building synchronously, which is acceptable here since this is a one-shot editor validation pass, not a per-frame path.

Note: every mutator above follows the same discipline. Modify() runs first, and MarkPackageDirty() follows a successful change. A false return means a no-op: neither one runs.

UOutpostBuildingDefinition

Header: OutpostBuilder/Source/OutpostBuilder/DataAssets/OutpostBuildingDefinition.h

  • PrimaryAssetTypeName / GetPrimaryAssetId() - "OutpostBuildingDefinition".
  • DisplayName - FText, author-optional (empty is a valid, common state).
  • GetEffectiveDisplayName() - THE one display-name rule: the authored DisplayName when set, else MakeDefaultDisplayNameFromAssetName(GetName()).
    • Every surface that shows a building's name (the palette tile, the Assign row's building picker combo button, the plot list rows, and the Buildings browser rows) routes through this, or through the toolkit's load-free GetBuildingDisplayText(FPrimaryAssetId) mirror of the same rule, so a renamed building reads identically everywhere.
    • Palette-tile and browser-row TOOLTIPS deliberately keep the raw asset name instead. Two buildings can share a DisplayName, never an asset name.
  • MakeDefaultDisplayNameFromAssetName(AssetName) - static FString. The asset name with a leading "BD_" stripped (case-insensitive). Returns the name unchanged if there's no such prefix, or if stripping it would leave nothing (a building literally named "BD_" keeps "BD_").
    • Load-free and static so a caller holding only an FAssetData/FPrimaryAssetId (no loaded object) can apply the identical rule.
    • This is both GetEffectiveDisplayName's fallback AND the DEFAULT a freshly created building's DisplayName is stamped with. Both creation paths (the panel's "+ New Building" / CreateNewBuildingDefinitionInteractive, and the Content Browser's UOutpostBuildingDefinitionFactory::FactoryCreateNew) set it, so a building named BD_Barracks is born with DisplayName "Barracks".
  • BuildingActorClass - TSoftClassPtr<AActor>, the actor asset (e.g., a Blueprint actor) that IS the building, kept for a project's own gameplay spawns. GAME worlds never render from this field directly (buildings render mesh-only there).
    • In the EDITOR only, when set, the placement ghost and any editor-world plot with this building assigned both mirror this class's template (its static-mesh components) instead of BuildingMesh. See runtime-loadout.html and edmode.html.
  • BuildingMesh - TSoftObjectPtr<UStaticMesh>, what an assigned plot renders in GAME worlds, the palette thumbnail source, and the editor preview/ghost, specifically its FALLBACK when BuildingActorClass is unset or yields no static-mesh parts. The ghost's validation circle never measured either field (see GetPreviewFootprintRadiusCm in edmode.html); it's the plot's size class, not a mesh bounds.
  • PlotSizeQuery - FGameplayTagQuery, default EMPTY. Which plots this building fits, evaluated against the plot's PlotSizeTag. Empty = fits EVERY plot size (a wildcard, not "nobody"), the default for a newly created building and for one saved before this field existed, and the same wildcard convention SupportedFactions establishes.
    • A mismatch is the disabled treatment: the building is refused by the Assign button (with a tooltip saying so) and excluded from Randomize's pool.
    • A building already sitting on a now-mismatched plot is NEVER auto-deleted or reassigned. It keeps its plot and keeps rendering.
  • PlotTagQuery (the placement rule matrix's BUILDING half) - FGameplayTagQuery, default EMPTY. Evaluated against the plot's PlotTags by OutpostEditorUtils::EvaluateBuildingPlotAdvisory (editor module). Empty = fits every plot (the same wildcard convention PlotSizeQuery/SupportedFactions establish).
    • WARN-ONLY, the deliberate contrast with PlotSizeQuery/SupportedFactions (both BLOCKING, the disabled treatment): a mismatch never refuses assignment, never excludes a plot from Randomize's pool, and never greys out the Assign button. It only flags (a tooltip line, a palette-tile glyph, a plot-list drift icon, and a WARNING-severity IsDataValid finding).
    • VOCABULARY is entirely PROJECT-OWNED: this plugin registers no native tags for it at all (contrast PlotSize's four native tags). Author your own in DefaultGameplayTags.ini.
  • MatchesPlotTags(PlotTags) - UFUNCTION(BlueprintPure). THE one home of the plot-tag advisory match, MatchesPlotSize's WARN-ONLY counterpart. Rule: an EMPTY query fits everything, tested first. Unlike MatchesPlotSize, there is deliberately no ResolveOrDefault step: plot tags have no default vocabulary to resolve an unset value into, so PlotTags is evaluated exactly as given. Never call directly from a UI surface. Go through OutpostEditorUtils::EvaluateBuildingPlotAdvisory.
  • SupportedFactions - TSet<EOutpostFaction>, default EMPTY. The factions that field this building. Empty = supported everywhere (a wildcard, not "nobody"), which is exactly what an asset authored before this field existed deserializes to.
  • SupportsFaction(OutpostFaction) - UFUNCTION(BlueprintPure). THE one home of the faction rule; takes the outpost's faction, not the building's. Never test SupportedFactions directly.
    • Two rules live here that a membership test cannot express: (1) a Neutral outpost accepts EVERY building regardless of what it lists, checked first, before the set is read at all; (2) an empty list is a wildcard.
    • A call site that checked only .Contains() would silently hide every faction-tagged building from every default (Neutral) outpost in the project.
  • MatchesPlotSize(PlotSizeTag) - UFUNCTION(BlueprintPure). THE one home of the size rule, SupportsFaction's exact counterpart: may this building sit on a plot of PlotSizeTag? Never test PlotSizeQuery directly.
    • Two rules live here: (1) an EMPTY query fits everything, tested first; (2) an UNSET plot tag resolves as the default size (Small) before matching, via OutpostBuilder::PlotSizeTags::ResolveOrDefault, so an un-tagged plot behaves exactly like a Small plot.
  • BuildingCategory - FGameplayTag, meta = (Categories = "OutpostBuilder.BuildingCategory"). Purely a PALETTE grouping: it has no bearing on eligibility (contrast PlotSizeQuery/SupportedFactions, which gate what's offerable).
    • Empty = uncategorized, the default and fully valid. A project that never tags a building sees zero palette UI change, since the editing panel's category tab row hides entirely until at least one building is categorized. See toolkit.html's "Palette Category Tabs" section.
  • GetAssetRegistryTags(Context) - exports BuildingCategory's tag NAME as a hidden "BuildingCategory" registry tag (empty string when unset: FGameplayTag::ToString() on an invalid tag returns "None", not "", so the empty case is spelled out explicitly) so the palette's category tab row and filter gate can bucket an UNLOADED definition without loading it, the same live-else-registry rule used for display names.
  • OutpostBuilder::BuildingCategoryTags namespace (OutpostBuildingDefinition.h) - the building-category tag vocabulary, the palette-organization counterpart to OutpostBuilder::PlotSizeTags but deliberately smaller: it registers exactly ONE native tag, "OutpostBuilder.BuildingCategory", via UE_DEFINE_GAMEPLAY_TAG_STATIC, unlike PlotSizeTags::GetParentTag(), which resolves by name because its four children are the native ones.
    • BuildingCategory ships no native children to bring a name-resolved parent into the tag tree, so the root itself has to be native. That registration is the whole product: it's what gives the BuildingCategory field's meta=(Categories=...) picker a root to offer children under.
    • The namespace exposes no accessor, and the tag static is referenced by nothing. The palette's category census reads the tags off the definitions themselves (FOutpostPaletteModel::ComputeCategoryPresence) rather than querying the tag tree.
    • NO native children ship: the taxonomy belongs entirely to the project's own gameplay-tag config, exactly like PlotSize's project-added sizes.

UOutpostFactionDefinition - DELETED

This UPrimaryDataAsset and its Content Browser factory (UOutpostFactionDefinitionFactory) no longer exist. Faction is the fixed EOutpostFaction enum (OutpostBuilder/Source/OutpostBuilder/Core/OutpostFaction.h): pure identity/eligibility, with no banner mesh and no color. See faction-visuals.html for the full model.

Plot-Size Gameplay Tags

Header: OutpostBuilder/Source/OutpostBuilder/Core/OutpostPlotSize.h (namespace OutpostBuilder::PlotSizeTags)

Plot size lives on gameplay tags under OutpostBuilder.PlotSize. The plugin registers four NATIVE tags (OutpostBuilder.PlotSize.Small/Medium/Large/Heavy, the enum's 1:1 twins) via file-local FNativeGameplayTag statics in OutpostPlotSize.cpp; a project adds its own sizes as ordinary child tags of OutpostBuilder.PlotSize in its gameplay-tag config, no plugin change needed. Every consumer reaches the vocabulary through these free functions rather than the native statics directly:

  • GetParentTag() - OutpostBuilder.PlotSize, resolved by name (ErrorIfNotFound = false). Note the vocabulary's export split: GetDefaultTag/GetRegisteredPlotSizeTags/GetTagLeafText carry OUTPOSTBUILDER_API (the editor module calls them); GetParentTag/ResolveOrDefault/ ToNativeTag/IsNativeTag are runtime-module-internal. A downstream module cannot link them, and adding an export needs a real cross-module caller, not symmetry.
  • GetDefaultTag() - OutpostBuilder.PlotSize.Small. THE default size: an unset tag anywhere (older content, a hand-spawned plot) resolves as Small.
  • ResolveOrDefault(Tag) - Tag if valid, else GetDefaultTag(). The one home of the unset-resolves-as-Small rule.
  • ToNativeTag(EOutpostPlotSize) - the enum value's native-tag twin (Small -> OutpostBuilder.PlotSize.Small, etc.), used internally to name the four native tags for lookups like IsNativeTag and the settings asset's built-in dimension ladder.
  • GetRegisteredPlotSizeTags() - every registered tag under OutpostBuilder.PlotSize: the native four plus whatever the project's tag config added. The palette's Plot Size filter builds its option rows from this.
  • GetTagLeafText(Tag) - display text: the leaf segment ("Small" from "OutpostBuilder.PlotSize.Small"). An empty tag renders as the default tag's leaf.

Plot size is ONE feature, not two. The same tag vocabulary answers both halves: AOutpostPlot::PlotSizeTag/FOutpostPlotRecord::PlotSizeTag carry the size a plot HAS, UOutpostBuildingDefinition::PlotSizeQuery carries the sizes a building FITS (a query now, not a single required value), and a mismatch is a disabled treatment, never an auto-delete, never a reassignment.

EOutpostPlotSize

Same header. UENUM(BlueprintType) enum class EOutpostPlotSize : uint8 { Small, Medium, Large, Heavy } names the plugin's four native plot sizes for the handful of internal call sites that need to refer to one by value. ToNativeTag is how those four native gameplay tags get identified by lookups like IsNativeTag and the settings asset's built-in dimension ladder.

Live plot-size data is always the gameplay tag, never this enum. Don't type a new property against this enum, and don't extend it: a project's own plot sizes are tags added to the OutpostBuilder.PlotSize config, not new enum entries.

The Settings Asset - UOutpostBuilderSettingsAsset

Header: OutpostBuilder/Source/OutpostBuilder/Settings/OutpostBuilderSettingsAsset.h

A UPrimaryDataAsset (type name "OutpostBuilderSettings") in the RUNTIME module. It holds the project-SHARED knobs (runtime categories, asset-creation/placement config, and three placement-VALIDITY knobs). The per-user debug-draw/editor-UI-style knobs (colors, sizes, and timing, across Ghosts/Footprints/Selection/Hover/Beams/HUD/Overhead Camera/Input) live on a separate per-user class, UOutpostBuilderUserSettings (below).

A project authors ONE of this asset (Content Browser > Add > Miscellaneous > Data Asset > pick OutpostBuilderSettingsAsset) and assigns it once at Project Settings > Plugins > "Outpost Builder" > Settings Asset, the plugin's single Project Settings entry.

The class defaults apply for any value (or the whole asset) left unset. UOutpostRuntimeSettings is the host (below).

  • PrimaryAssetTypeName / GetPrimaryAssetId() - "OutpostBuilderSettings"; registered for scanning AND AlwaysCook in FOutpostBuilderModule::RegisterAssetScans exactly like the two definition types, which is what makes the cooker follow the soft mesh refs below out of the asset (and what fixed the latent never-cooked-DefaultPreviewMesh bug, covered in porting.html).
  • Get() (static) - THE read every consumer routes through: the configured asset when already loaded, else this class's CDO. Never loads (ResolveObject-only, weak-cached keyed by the configured soft path). Its dominant call sites are per-frame draw/HUD/Slate paths.
  • PreWarm() (static) - one-shot SYNCHRONOUS load of the configured asset so Get() never misses on a real project; called from exactly three sites: RegisterAssetScans (module startup / post-engine-init, the packaged-game site, which also roots the asset in cooked games), UOutpostBuilderEdMode::Enter, and UOutpostRuntimeSettings::PostEditChangeProperty (asset repointed).
  • IsDataValid(Context) (WITH_EDITOR) - errors on any registered plot-size tag with no PlotSizeTagHalfSizeCm entry (the four native tags excepted, since they always resolve through the built-in ladder), and on a native non-Small tag that resolves to the same dimensions as Small (a sign the built-in dimension ladder is missing its rung for that tag).

Runtime categories (shipped in packaged games):

  • DefaultPreviewMesh - TSoftObjectPtr<UStaticMesh>, Preview category. Fallback mesh for a plot's mesh ladder (rung 3, reached when EmptyPlotMesh is unset, or the assigned building's own BuildingMesh is unset/fails to load).
    • NOT read by the placement ghost, which has no equivalent rung of its own. A ghost that resolves nothing simply shows no mesh part (the wire box and its ground square alone).
    • Unset keeps the built-in cube for the plot.
  • EmptyPlotMesh - TSoftObjectPtr<UStaticMesh>, Preview category. What an UNASSIGNED plot looks like (EVERY unassigned plot, of every outpost, in the editor AND in packaged games), and what the placement ghost is made of while the palette's Empty tile is hot.
    • Unset is fine: the plot falls through to DefaultPreviewMesh, then the built-in cube.
    • It's load-bearing that "a plot is never invisible", since editor tooling traces a plot's MESH to hit it.
  • PlotSizeTagHalfSizeCm - TMap<FGameplayTag, float>, Placement category, DisplayName "Plot Size Tags" (meta = (Units = ...) is UHT-rejected on a TMap property, numeric/struct only, so the unit stays in the tooltip instead of a unit-aware spinner).
    • Every pad is a square, and the stored float is the HALF-size in cm: the distance from the pad's center to an edge (a 400x400cm Small pad is an entry of 200).
    • A tag absent from the map resolves via the native ladder and finally Small (UOutpostRuntimeSettings::GetPlotSizeFootprintRadiusCm/GetDefaultPlotSizeDimensionsCm).
    • This map is the ONE place a size class becomes a number, and it's the whole reason plot size is one feature rather than two: the tag names the class, this retunes what the class MEANS with no recompile and without touching a single building asset.
  • OutpostActorClass / OutpostPlotActorClass / OutpostVolumeActorClass / OverheadCameraActorClass - TSubclassOf<AOutpost> / TSubclassOf<AOutpostPlot> / TSubclassOf<AOutpostVolume> / TSubclassOf<AOverheadCamera>, Actors category, each meta = (AllowAbstract = "false"). The class every new instance of that actor type spawns as.
    • The constructor defaults all four to the plugin's own native StaticClass(), so an unauthored asset reproduces the fixed-class behavior exactly.
    • A project points one of these at its own C++ or Blueprint subclass to swap what gets spawned, project-wide, with no call-site changes.
    • Never read directly (Get().OutpostActorClass etc.). Every consumer goes through the matching UOutpostRuntimeSettings::Get*Class() resolver below, which is what makes the override reach every spawn site instead of just some of them.
    • The editor-only OutpostActorFolder (below) shares this same Actors category, even though it lives inside WITH_EDITORONLY_DATA and these four don't. Details-panel categories group across that compile boundary freely.

Editor categories (inside WITH_EDITORONLY_DATA, stripped from cooked builds):

Category Holds
Assets CreatedDefinitionDirectory, DefinitionAssetPrefix, MaxDefaultBuildingPaletteEntries
Actors OutpostActorFolder (alongside the four actor-class overrides above)
Placement OutpostExclusionDistance, DefaultOutpostVolumeSizeCm, OutpostVolumeBoundsPaddingCm, plus two knobs that feed placement VALIDITY rather than a look: PlotRingRadius and PlotGhostRadius (the new-plot spawn-search radius and a last-resort geometry-bounds fallback), alongside the runtime-shipped PlotSizeTagHalfSizeCm (above), which feeds the same footprint-radius arithmetic

These stay on the shared asset, not the per-user class, because a per-user divergence would make the same plot legal on one designer's machine and illegal on another's.

Everything else the style surface holds (Ghosts/Footprints/Selection/Hover/Beams/HUD/Overhead Camera/Input: colors, sizes, timing) lives on the per-user UOutpostBuilderUserSettings (editor module). See "Per-User Style Settings" and "Editor Settings on the Asset" below.

Runtime Settings Host - UOutpostRuntimeSettings

Header: OutpostBuilder/Source/OutpostBuilder/Settings/OutpostRuntimeSettings.h

A UDeveloperSettings (config = Game, defaultconfig, DisplayName "Outpost Builder"): the plugin's ONE Project Settings entry. It holds no tunables of its own, its single visible property is the SettingsAsset pointer.

It stays in the RUNTIME module for reachability. Packaged games must resolve the pointer (a runtime plot's mesh-ladder resolution needs EmptyPlotMesh/DefaultPreviewMesh, and a runtime plot must learn its own size's real dimensions), and DefaultGame.ini ships.

  • SettingsAsset - TSoftObjectPtr<UOutpostBuilderSettingsAsset>, config, EditAnywhere. THE pointer everything resolves through. Unset is supported (every read falls back to the asset class's CDO defaults), but a real project should author one. The asset is also what makes its soft-referenced meshes cook.
  • PinnedBuildingDefinitions - TArray<FName>, UPROPERTY(config) with no EditAnywhere, WITH_EDITORONLY_DATA. Package names of building definitions pinned to always show in the editing panel's palette.
    • Deliberately INVISIBLE in Project Settings and hosted here rather than on the asset: pins are workflow state the Pin button flips with a silent, instant SaveConfig. Asset-hosting them would turn every pin toggle into a dirty package and save prompt.
  • GetPlotSizeDimensionsCm(PlotSizeTag) / GetDefaultPlotSizeDimensionsCm(PlotSizeTag) - the settings asset's configured entry if present, else the built-in default; an unset tag resolves as the default (Small) size. Built-in defaults exist only for the four NATIVE tags, square pads on a 4m step: Small 400×400, Medium 800×800, Large 1200×1200, Heavy 1600×1600. A project-added tag with no configured entry falls back to Small's.
  • GetPlotSizeFootprintRadiusCm(PlotSizeTag) - a plot size's configured half-size in cm: the PlotSizeTagHalfSizeCm entry for the (resolved) tag, or the built-in default when it has none. This is the one place the size→radius arithmetic lives.
    • Every pad is a square, so this one number doubles as "distance from center to edge" and the radius OutpostBuilder::Draw::GetActorGeometryRadius uses for a plot's own selection/footprint ring, without either needing to re-derive it from the other.
    • A configured entry is returned as authored, so a negative half-size reaches callers as-is. Callers must NOT use a negative value as an "unresolved" sentinel.
  • GetOutpostClass() / GetPlotClass() / GetVolumeClass() / GetOverheadCameraClass() - the four actor-class resolvers every spawn site in the plugin routes through: the settings asset's configured OutpostActorClass/OutpostPlotActorClass/OutpostVolumeActorClass/OverheadCameraActorClass (above) when set, else that actor type's own native class. Never nullptr, even with a cleared field.
    • Callable from BOTH modules (the editor module already depends on the runtime one, so this creates no circular dependency), which is what lets editor placement AND the runtime-only StampOutpost/PlaceDefinitionAt path share one source of truth for which class each spawn instantiates.
    • All 11 spawn sites resolve through these four statics: ConfirmOutpostPlacement/ConfirmPlotPlacement/EnsureOverheadCameraForEditingOutpost/StartOverheadCameraPositioning (UOutpostBuilderEdMode), StampOutpost/PlaceDefinitionAt/RestoreOutpost's outpost spawn plus the shared plot- and camera-spawn helper they call (UOutpostStampLibrary), SpawnDefaultOutpostVolume (OutpostPrefabUtils), and the Content Browser drag-stamp's UActorFactoryOutpostPrefab::GetDefaultActorClass override.
  • PostEditChangeProperty (WITH_EDITOR) - a repointed SettingsAsset pre-warms the new asset (UOutpostBuilderSettingsAsset::PreWarm) so the never-loading per-frame resolution serves the new values immediately.

All the statics resolve through UOutpostBuilderSettingsAsset::Get(), which is loaded-or-CDO, never a load, so they are safe on per-frame Slate bindings and draw paths.

AOutpostPlot

Header: OutpostBuilder/Source/OutpostBuilder/Actors/OutpostPlot.h

  • AOutpostPlot() - root USceneComponent ("Root") plus ONE runtime UStaticMeshComponent, BuildingMeshComponent (not WITH_EDITORONLY_DATA), so a plot's building renders in packaged games too.
    • See runtime-loadout.html for the mesh-ladder selection model (AssignedBuildingId, else the settings asset's plugin-wide EmptyPlotMesh, else its DefaultPreviewMesh, else the built-in cube). That ladder is unconditional and the ONLY path in a GAME world, and the EDITOR-world fallback.
    • A second, WITH_EDITORONLY_DATA+Transient array, MirroredBuildingParts, holds the actor-template mirror an EDITOR-world plot wears instead when its assigned building's BuildingActorClass resolves at least one static-mesh part (see RebuildMirroredBuildingParts() below). BuildingMeshComponent carries no mesh while that array is populated.
  • GetOutpostDefinitionId() / SetOutpostDefinitionId(NewId) - Modify+Dirty.
  • GetPlotId() / SetPlotId(NewPlotId) - Modify+Dirty.
  • GetAssignedBuildingId() / SetAssignedBuilding(BuildingId) - Modify+Dirty, then triggers a re-realization of the rendered building and broadcasts UOutpostEventSubsystem::OnPlotAssigned for this world.
  • GetPlotSizeTag() / SetPlotSizeTag(NewSizeTag) - Modify+Dirty, skipped when unchanged. The ACTOR half of the write-through pair (see FOutpostPlotRecord::PlotSizeTag); a caller resizing a live plot must also call UOutpostDefinition::SetPlotSizeTag, in the SAME transaction, or the next stamp rebuilds the plot at its old size.
    • Deliberately does NOT refresh the mesh, unlike SetAssignedBuilding: size is not an input to mesh resolution, so there is nothing cached to re-derive.
    • What size DOES feed (the editor's footprint radius and the disabled treatment) is re-read every frame, never cached. It IS what the plot's selection ring and overlap test measure (OutpostBuilder::Draw::GetActorGeometryRadius).
  • GetPlotTags() / SetPlotTags(NewTags) - Modify+Dirty, skipped when unchanged. The ACTOR half of the write-through pair (see FOutpostPlotRecord::PlotTags); a caller retagging a live plot must also call UOutpostDefinition::SetPlotTags, in the SAME transaction.
    • The Details panel is the only interactive write surface: PostEditChangeChainProperty syncs the record via SyncRecordPlotTags, mirroring PlotSizeTag's own branch. No mesh refresh (tags are not a mesh-resolution input) and no migration (no legacy source).
  • RefreshBuildingPreview() - building realization. In an EDITOR world it first tries RebuildMirroredBuildingParts() (below) when the assigned building's BuildingActorClass is set. Only when that returns false (no class, an unloadable class, or a class with no static-mesh parts) does it fall through to the mesh-ladder priority order in runtime-loadout.html, reusing UOutpostBuildingDefinition's existing mesh resolution.
    • That ladder is unconditional (and the ONLY path) in a GAME world. It runs in both the editor and packaged games.
    • This is the one idempotent, synchronous realize path. PostRegisterAllComponents() (below, the override contracts.md cites) calls it in an editor world and kicks BeginAsyncBuildingRefresh() in a game world instead (which never mirrors: the async path is the mesh ladder only), so a streaming cell never takes a synchronous mesh load.
  • OutpostBuilder::ActorEditing::RebuildMirroredBuildingParts(Plot, BuildingDefinition) (WITH_EDITOR, OutpostActorEditingLibrary.h, called from RefreshBuildingPreview) - loads BuildingDefinition->BuildingActorClass synchronously (one-shot; the caller already guards the world type) and mirrors its template's static-mesh parts, via OutpostPreviewMeshUtils::CollectMeshParts() (the SAME collector the placement ghost uses, covered in edmode.html), into MirroredBuildingParts.
    • These are ordinary collidable, WITH_EDITORONLY_DATA+Transient UStaticMeshComponents, each carrying the template's own authored per-slot material overrides.
    • Returns false and leaves no parts when the class is unset, fails to load, or contributes no static-mesh parts. The caller then falls through to the mesh ladder.
    • Never a child actor, never a spawned instance: that's the hard law. Template mirroring is the compliant pattern. ClearMirroredBuildingParts(Plot) destroys every mirrored part and empties the array. Both run on every RefreshBuildingPreview() call.
  • No RefreshFactionVisuals() or CachedFactionColor - there is no faction-color mechanism in the plugin; a plot's building is never tinted. See faction-visuals.html.
  • OnConstruction(const FTransform&) (WITH_EDITOR) - re-derives the plot's building mesh (RefreshBuildingPreview()). Early-returns in a game world, where the async PostRegisterAllComponents path owns realization instead. An uncooked game world reruns construction scripts inside the time-sliced AddToWorld.
  • PostEditMove(bFinished) / PostEditChangeChainProperty(...) (WITH_EDITOR) - both drive the same write-back: this plot's transform, relative to the owner's unit-scale record basis, gets written into the definition record. Guarded by finding the owning outpost and by IsRecordOwnershipUnique().
  • PostEditUndo() (WITH_EDITOR) - calls RefreshBuildingPreview(), since the mesh isn't transactional and needs re-deriving after undo/redo.
  • PostRegisterAllComponents() - realizes the building mesh, on both spawn (game) and registration (editor). Deliberately not WITH_EDITOR-gated, which is what makes a plot's building render in packaged games. Re-entrancy-guarded (re-registration around undo/redo can fire it more than once for the same instance).
    • It branches on world type: a game world kicks the async load-then-swap (BeginAsyncBuildingRefresh()), an editor world realizes synchronously via RefreshBuildingPreview().
  • PostDuplicate(bDuplicateForPIE) / PostEditImport() (WITH_EDITOR) - both route through OutpostBuilder::ActorEditing::HandleImportIdentityReset, idempotent against the engine firing either one more than once per paste.
    • An already-resolved PlotId for this paste is left alone, else a still-uniquely-owned record is reclaimed (a cut base pasted back reconnects to its own record), else a fresh id is minted. A copy never silently overwrites the original's record.
  • IsRecordOwnershipUnique() - true when no other plot actor in the world shares this plot's (OutpostDefinitionId, PlotId) pair. Gates every record write-back and removal. A shared pair means a duplicate exists somewhere. Writing would corrupt the original's record in that case.

Runtime Function Library

Header: OutpostBuilder/Source/OutpostBuilder/Core/OutpostStampLibrary.h

UOutpostStampLibrary

  • StampOutpost(WorldContextObject, Definition, TargetTransform, OptionalAnchor = nullptr) - Blueprint-callable. Spawns an outpost, its plots, and its Overhead camera (when set) from Definition at TargetTransform. Pass OptionalAnchor to reuse an already-spawned AOutpost instead of spawning one, in which case its transform becomes the target and TargetTransform is ignored.
    • Opens no transactions itself, since editor callers own that.
    • This is the stamp half of fork-on-stamp: callers fork the definition first (see prefabs.html), which is why every stamped outpost ends up owning its own definition.
  • PlaceDefinitionAt(WorldContextObject, Definition, Transform) - Blueprint-callable. Interactive, non-forking placement of an EXISTING definition at an arbitrary transform: spawns an AOutpost at Transform, binds the SAME definition id (no fork), reattaches its plots and Overhead camera from records, and writes PlacedOutpostPath/PlacedOutpostTransform back onto Definition.
    • Three-way contrast: StampOutpost forks, RestoreOutpost re-attaches at the recorded transform and bails if already placed, PlaceDefinitionAt re-attaches the same definition at a caller-supplied transform regardless of any prior placement.
    • Returns nullptr (and logs a warning) on a null Definition/World or a failed spawn. This is the runtime half of the toolkit's "Edit (Place Actor)" action (see edmode.html).
  • RestoreOutpostFromBaked(WorldContextObject, Baked) - Blueprint-callable. Rebuilds one outpost from its BAKED registry entry, leaving the definition untouched.
    • This is the recovery path once records live on the actors: the registry holds what the outpost WAS, so a deleted one comes back from the bake rather than from the template, and it works for an outpost whose definition is shared, which the definition-keyed restore below cannot.
    • Refuses and returns nullptr when the instance is already live, since restoring over it would mint a second claimant to one handle. See Instance Identity.
  • RestoreOutpost(Definition, World) (WITH_EDITOR, not Blueprint-callable) - superseded by RestoreOutpostFromBaked, kept while content authored before the registry still carries its records on the definition.
    • The deliberate contrast with the drag-stamp path: it re-attaches the SAME definition asset to a freshly spawned AOutpost rather than forking a new one first, because this is reconstructing what already belonged to Definition, not creating a new placement.
    • Spawns at Definition->PlacedOutpostTransform, rebuilds every plot and the Overhead camera record (when set) against the new outpost's own record basis, and writes PlacedOutpostPath/PlacedOutpostTransform back onto Definition.
    • Returns nullptr (and logs a warning) when Definition or World is null, or when PlacedOutpostPath still resolves to a live AOutpost (nothing to restore).
    • No transaction opened here either. Its callers own that: the Content Browser's "Restore Placed Outpost" action and the mode's RestoreOutpostForDefinition (both below).

All three broadcast UOutpostEventSubsystem::OnOutpostStamped once, last, after every actor and record write for that call has landed.

Instance Identity and the Registry

The surfaces the per-instance identity work added. Instance Identity covers the model and why it exists; this is the API shape.

FOutpostInstanceId (OutpostInstanceId.h)

USTRUCT(BlueprintType) wrapping one FGuid Value (VisibleAnywhere, BlueprintReadOnly). Says WHICH placed outpost an actor belongs to, where the definition id says only what it was built from. Carried as a UPROPERTY on all four family actors, written out per header rather than pasted from a macro, because a UPROPERTY inside a user-defined macro is invisible to UHT and still compiles.

  • IsValid() - the wrapped guid is set.
  • Generate() - static, mints a fresh one.
  • operator== / operator!= / GetTypeHash / ToString() - usable as a TMap key.

FOutpostBakedInstance (OutpostLevelRegistry.h)

USTRUCT(BlueprintType), one placed outpost's baked default state: InstanceId, DefinitionId, DisplayName, Faction, AnchorTransform, Plots, OverheadCamera, TerritoryBounds, AnchorActorPath, ContentHash, bVerifiedThisBake. Plots and ContentHash are not BlueprintReadOnly (FOutpostPlotRecord is not a BlueprintType, and Blueprints have no uint32).

AnchorActorPath is an FString rather than an FSoftObjectPath deliberately: a soft path is a cook-graph edge, and under One File Per Actor it would make the registry a recursive cook manager of the level's external actor packages.

UOutpostLevelRegistry (OutpostLevelRegistry.h)

UPrimaryDataAsset, one per level, type name "OutpostLevelRegistry". Treat it as a generated artifact.

  • Instances / RecentlyRemoved / LevelPackageName - the entries, the lossy undo net (capped at MaxRecentlyRemoved, 32), and the level this describes.
  • bBakeWasComplete / IncompleteReasons - how far to trust it. A partitioned save sees only loaded cells and says so here.
  • FindInstance(InstanceId) - const, by handle.
  • UpsertInstance(Instance) - adds or updates, returns whether anything changed. Refuses when two different actors claim one handle, comparing AnchorActorPath, and early-outs on an unchanged ContentHash.
  • RetireInstance(InstanceId) - moves the entry to RecentlyRemoved.
  • BeginBakePass() - clears every bVerifiedThisBake so one pass can mark what it actually saw.
  • IsDataValid(Context) (WITH_EDITOR) - flags an unresolvable level path and any duplicate instance id.

UOutpostRegistrySubsystem (OutpostRegistrySubsystem.h)

UEngineSubsystem, so every registry is resident and answerable with no level loaded. Nothing here is a UFUNCTION: the data types are Blueprint-exposed, the accessors are C++ only.

  • MakeLevelKey(World) / MakeLevelKeyForActor(Actor) - static. THE level keys. In the runtime module so a simulation layer can build one, and because a PIE caller reaching for the package name directly gets a UEDPIE_-prefixed string that matches nothing baked.
  • EnsureLoaded() / IsReady() / InvalidateCache() - load on first use, refusing to latch while assets are still loading.
  • FindInstance(InstanceId) / FindLevelForInstance(InstanceId) - point lookups, no verification filter.
  • GetAllInstances(Out) / GetUnverifiedInstances(Out) - split on bVerifiedThisBake. Read the Current state note before relying on that split.
  • GetInstancesForLevel(LevelPackageName, Out) / GetInstancesContainingPoint(Point, Out) / GetIncompleteLevels(Out).
  • FindLiveOutpost(WorldContextObject, InstanceId) - the live actor, or null when its level is not loaded. The baked entry still answers.

Every returned FOutpostBakedInstance* points into a registry's own array and is valid only until the next bake or InvalidateCache. Read what you need, do not store it.

Console

  • Outpost.BakeRegistry - bakes the currently open level's outposts into its registry asset. Marks the asset dirty and does not save it - save to keep the result. On a partitioned map it bakes only the loaded cells and says so, pointing at the builder commandlet for a complete pass.
  • Outpost.DumpRegistry - lists every baked outpost with its handle, level, plot count and verification state, including entries the last bake did not see.
  • Outpost.CheckBounds - checks every outpost's bounds volume in the open level and prints the numbers. Flags a missing or duplicated volume, a volume whose brush was never built, a cached box that no longer matches the brush, and a baked box that no longer matches the live one. Lines marked ! need a decision from you. Refit drift and plots outside their bounds are printed without the mark: neither is a fault, because nothing resizes a volume after it is spawned and the plot rule only ever ran at placement time.
  • Outpost.CheckBounds X Y Z - answers a single world-space point against every containment rule the plugin ships: the volume's axis-aligned box, the actual brush, and the baked territory box. They can disagree, and the point of printing all three together is that you can see it when they do.

None of this needs a PIE session. The registry is a UEngineSubsystem, the brush is built editor-side, and each box is a const read off a spawned actor.

UEdMode Overrides

UOutpostBuilderEdMode is a UCLASS(Transient) deriving UBaseLegacyWidgetEdMode, which is a UEdMode that also supplies the legacy widget and viewport interfaces (ILegacyEdModeWidgetInterface/ILegacyEdModeViewportInterface).

There is no registration call anywhere: UAssetEditorSubsystem::RegisterEditorModes discovers the class from its CDO and reads GetModeInfo(), which is why the CONSTRUCTOR fills in Info (id, name, icon, visibility, and a MAX_int32 priority that sorts the mode last in the Modes toolbar).

  • EM_OutpostBuilderId - static FEditorModeID, value "EM_OutpostBuilder".
  • GetActive() - static; the running mode instance, or null when GEditor is absent or the mode isn't active (GLevelEditorModeTools().GetActiveScriptableMode). Never cache the result across ticks: a deactivated instance is parked in FEditorModeTools' recycle list and handed back on the next activation.
  • Enter() / Exit() - mode lifecycle. Enter() pre-warms the settings asset BEFORE Super::Enter(), since that base call is what builds the toolkit and the palette/details it constructs read resolved settings.
    • Exit() cancels any active placement and Overhead camera positioning session and exits the editing submode, all ahead of Super::Exit(). It deliberately does NOT close the toolkit itself (FEditorModeTools::DeactivateModeAtIndex already did, and Super::Exit() resets the pointer).

  • Render(View, Viewport, PDI) - draws the placement ghosts, the ownership beams, the RTS-style selection markers (a crisp neon-green rim under every selected AOutpost/AOutpostPlot), the Outpost Volume borders, and the hover highlight.

  • DrawHUD(ViewportClient, Viewport, View, Canvas) - screen-space text: every loaded outpost's label, the placement reason line (a refusal or the warn-only tag advisory), and the plot ghost's three live readouts.

  • The remove tool - holding the configured Remove-Mode Modifier (Ctrl by default; an Input-category knob) during PLOT placement flips the session into a remove-plot tool.
    • The ghost hides, a flat red plate + X marks the editing outpost's plot under the cursor (found by the SAME cursor trace that positions the ghost, never a second trace), and LMB destroys that plot and its record through the shared RemovePlotAndItsRecord rule, one "Remove Plot" (singular) transaction per removal.
    • A per-frame Tick-cached flag (bRemoveModifierHeld) drives every DISPLAY surface (banner "Removing Plot" + its red accent stripe/text, legend, hint bar, ghost visibility, the mouse cursor), while the destructive click re-reads the actual key state from the viewport at click time. The PIE gate is independent of the flag (D6/I4).
    • Releasing Ctrl resumes placing exactly where the session was. RMB tap / Esc still cancels the whole session from remove mode.
    • The modifier is a fixed gesture, NOT rebindable (a chord fires on a key event; a hold needs per-frame state, the same reason the Alt-orbit check polls).
    • The bracket keys explicitly still rotate the (hidden) ghost while armed (see InputKey above), and Ctrl+1-9 are the EDITOR's viewport bookmarks. That's why the legend suppresses both the rotate row and the "1-9: select building" row while remove mode is armed, even though rotation itself keeps working.
    • A plot whose mesh has no simple collision is invisible to the trace (ECC_Visibility hits simple collision). The Del key (CanDeleteSelection()/DeleteSelection(), below) remains the escape hatch.
    • The mouse cursor changes while armed (GetCursor, above: crosshair over a removable plot, a slashed circle otherwise). Every OTHER plot of the editing outpost draws a dim red candidate ring (UOutpostBuilderUserSettings::RemoveCandidateRingColor) so the whole removable set reads at a glance.
    • RemovePlotAndItsRecord deselects a selected target BEFORE destroying it (a just-placed plot stays selected by design, unlike the Del path, so without this the transform gizmo would linger at the dead actor's location).
    • The hovered target's marker uses the SAME PlacementPlateComponent/PlacementPlateInvalidColor knob the invalid-placement plate uses: one "red = removal/invalid" visual language.

Toolkit utilities

  • LocateOutpostForDefinition(DefinitionId) - resolves the definition's PlacedOutpostPath. A live actor in the current editor world gets selected, framed, and entered for editing. Anything else (an unset path, an unresolvable actor, or an actor whose world isn't the current editor world) surfaces a non-intrusive notification instead. This never auto-loads a map.

Toolkit notifications and firing discipline

There is no public delegate surface on the mode for these events. The mode calls the toolkit's own public methods directly (see FOutpostBuilderToolkit below and toolkit.html), through a private GetOutpostToolkit() getter. The firing rule each one keeps is the part worth remembering, since a notification that fires on the wrong edge is worse than one that doesn't fire at all:

  • HandleEditingOutpostChanged() - called from EnterOutpostEditMode/ExitOutpostEditMode, only on a genuine state change.
  • HandleCameraPositioningChanged() - called on StartOverheadCameraPositioning's success path, and on ConfirmOverheadCameraPositioning/CancelOverheadCameraPositioning, but only when a session was actually active. Both of those are also called unconditionally from cleanup paths, which must not spuriously notify. Lets the toolkit add and remove its viewport overlay.
  • HandlePlacementStateChanged() - called once on a genuine placement-state transition. StartOutpostPlacement/StartPlotPlacement each wrap their body in BeginPlacementTransition()/EndPlacementTransition(), which runs CancelPlacement() internally first with its own notification suppressed.
    • That way, switching from idle into placement, or from one placement kind straight into the other, notifies exactly once instead of a spurious end-then-start pair. A direct CancelPlacement() call (RMB, world cleanup, session teardown) notifies only when a placement was actually active.
  • HandlePaletteHotkey(int32) - called with index 0-8 when a SelectPaletteBuilding command executes (bare 1-9 by default, rebindable) while editing an outpost (not while positioning the camera). Indexes VisiblePaletteEntries, not BuildingPaletteEntries.
    • That way the keys follow whatever the palette actually shows, and the filter combos / faction gate remap them exactly the way pinning does (the refill re-renders the tile badges from the same indices, so a badge never lies about its key; see toolkit.html).
  • HandlePaletteEmptyHotkey() - the same for the SelectEmptyBuilding command (bare 0 by default): selects the palette's Empty tile, clearing the hot building so new plots are placed unassigned.
  • HandleEyedropperPick(BuildingId) - called when the PickBuildingFromPlot command executes (bare E by default). The MODE resolves the target plot (ResolveEyedropperTargetPlot(): the AOutpostPlot under the cursor, else the single selected plot, else null, scoped to the EDITING outpost's own plots, so a foreign plot resolves to null and returns the key unconsumed) and reads its AssignedBuildingId.
    • The toolkit end just calls SelectHotBuilding, so a pick and a tile click can't leave the palette in different states. An INVALID id is expected input, not a failure to screen: an unassigned plot IS the Empty tile.
    • CanPickBuildingFromPlot() gates on editing an outpost, not positioning the camera, the toolkit being hosted, the active viewport NOT tracking a drag, and a target actually resolving.
    • A false CanExecute returns the chord unconsumed, which is what leaves bare E doing its normal editor job everywhere this tool has nothing to pick.
  • HandlePlotsChanged() - called after a plot is placed, removed (DeleteSelection, or the Ctrl-remove tool's RemovePlotUnderCursor), assigned a building, or randomized (RandomizeSelectedPlots). Re-runs RefreshPlotList() so the editing panel's plot list never shows a stale row.

Editor Settings on the Asset

Header: OutpostBuilder/Source/OutpostBuilder/Settings/OutpostBuilderSettingsAsset.h (the WITH_EDITORONLY_DATA block)

These properties live inside UOutpostBuilderSettingsAsset's #if WITH_EDITORONLY_DATA block, so cooked builds strip them. They hold the asset-creation/placement config plus two knobs on a shared Placement category. The debug-draw/editor-UI-style knobs live on the per-user UOutpostBuilderUserSettings (see the next section).

There is no separate Project Settings page for any of this. Open the settings asset and edit it there (and Editor Preferences for the style knobs, covered below).

Editor categories (Assets / Placement / Actors):

  • CreatedDefinitionDirectory - FDirectoryPath, default /Game/Outposts, shown as Created Definition Folder with a browsable content-directory picker (meta = (ContentDir)) instead of a typed string. Where newly created UOutpostDefinition assets land.
    • Outpost definitions are auto-named with NO save dialog, and "+ New Building"'s modal dialog seeds itself here. Read via .Path at every call site.
    • A folder outside /Game resolves in-editor but not in packaged games (only /Game is scanned there).
  • DefinitionAssetPrefix - FString, default "OD_". Auto-created definitions are named <Prefix><SanitizedActorLabel>, de-duplicated via CreateUniqueAssetName.
  • OutpostExclusionDistance - float, meta = (Units = "Centimeters"), default 3000 (30 m). Minimum clearance between a NEW outpost and any AOutpostVolume's extents, enforced by the placement ghost AND drag-stamp's hard refusal.
  • DefaultOutpostVolumeSizeCm - float, meta = (Units = "Centimeters", DisplayName = "Default Outpost Volume Size"), default 3000. Per-axis MINIMUM size of a newly spawned outpost volume's box brush, the PROJECT-WIDE fallback.
    • SpawnDefaultOutpostVolume fits the brush to the outpost's actual base bounds plus OutpostVolumeBoundsPaddingCm per side, and only falls back to this floor when the fitted result would be smaller on that axis AND the outpost's own definition has no override (see VolumeSizeCm just below).
    • Affects newly spawned volumes only. It never re-fits an existing one.
  • UOutpostDefinition::VolumeSizeCm/bVolumeSizeOverridden (RUNTIME module: OutpostDefinition.h, Category "Outpost", not on the settings asset): a PER-OUTPOST override for the same floor DefaultOutpostVolumeSizeCm supplies project-wide.
    • bVolumeSizeOverridden (meta = (InlineEditConditionToggle)) distinguishes "never authored, fall back to the settings asset" (false, the default, which is what every already-placed definition predating this field carries) from "this outpost has its own value" (true). VolumeSizeCm (DisplayName = "Outpost Volume Size", ClampMin = "0.0") holds that value only while the bool is true.
    • RESOLVE LADDER, read by UOutpostDefinition::GetVolumeSizeCm(FallbackCm), the one call site being OutpostPrefabUtils::SpawnDefaultOutpostVolume: the definition's own VolumeSizeCm when bVolumeSizeOverridden, else the caller-supplied fallback (the settings asset's DefaultOutpostVolumeSizeCm).
    • SEEDED, not migrated: both UOutpostDefinitionFactory::FactoryCreateNew and UOutpostBuilderEdMode::GetOrCreateOutpostDefinitionForOutpost (the two "create a new definition" surfaces) set bVolumeSizeOverridden = true and copy the settings asset's CURRENT DefaultOutpostVolumeSizeCm in as a one-time baked snapshot for every NEWLY created definition.
    • That way a fresh definition starts as an editable, honest copy of the project default rather than silently tracking a LATER settings-asset edit.
    • IsDataValid adds one WARNING (never Invalid, matching every other check on this class) when bVolumeSizeOverridden is true with VolumeSizeCm <= 0 (every newly spawned volume on that outpost would floor to nothing).
  • OutpostVolumeBoundsPaddingCm - float, meta = (Units = "Centimeters", DisplayName = "Outpost Volume Bounds Padding"), default 500. Padding added to EACH SIDE of the computed base bounds when sizing a newly spawned outpost volume, contributing twice per axis (once per side), applied BEFORE the DefaultOutpostVolumeSizeCm floor. Kept alongside that floor deliberately: the two are one sizing recipe.
  • MaxDefaultBuildingPaletteEntries - int32, default 9 (lines up with the 1-9 palette hotkeys), Assets category. How many building definitions the editing panel's palette shows by default; beyond this many, a definition is hidden unless pinned. Pinned entries are shown IN ADDITION to this count, not counted against it. (The pin list itself is NOT on the asset. See UOutpostRuntimeSettings::PinnedBuildingDefinitions above.)
  • OutpostActorFolder - FString, default "Outposts", Actors category, shown as Outpost Outliner Folder. World Outliner base folder for actors the plugin spawns.
    • Every NEWLY spawned outpost/plot/Overhead camera/volume lands in <this>/<definition asset name> (e.g. Outposts/OD_MyBase). The subfolder is the definition's PrimaryAssetName: free to read, stable across restore/re-place, and fork-on-stamp gives each drag-stamped base its own folder.
    • A / nests the base deeper. EMPTY disables foldering entirely (new spawns land at the Outliner root, since the helpers skip SetFolderPath rather than writing NAME_None).
    • Spawn-time only: editing this never moves an already-placed actor, hand-moved actors are never yanked back, and restore/re-place (which respawns through a folding path, sweeping the whole base by the anchor's identity) is the deliberate opt-in migration for an unfoldered base.
    • Renaming a definition re-folds only actors still in the exact stale computed folder. Editor tooling only: Blueprint/game-code callers of UOutpostStampLibrary get no folders.
    • Recipe and sweep live in OutpostEditorUtils (ResolveOutpostActorFolder / ApplyOutpostActorFolder / ApplyOutpostFoldersForInstance).

Placement category, the knobs that stayed shared: these did NOT move to the per-user class, because each feeds placement VALIDITY rather than a look. A per-user divergence would make the same plot legal on one designer's machine and illegal on another's:

  • PlotSizeTagHalfSizeCm - see above (Runtime categories); on Placement because it feeds the same footprint-radius arithmetic as the two knobs below. DisplayName "Plot Size Tags", with no Units meta, since UHT rejects it on this TMap property.
  • PlotRingRadius - float, meta = (Units = "Centimeters", DisplayName = "New Plot Search Distance"), default 600. Ring search radius StartPlotPlacement/FindPlotSpawnLocation use to seed a new plot's spawn location. Sizes where a NEW plot may land.
  • PlotGhostRadius - float, meta = (Units = "Centimeters", DisplayName = "Fallback Footprint Half-Size"), default 150. Last-resort radius for an outpost-family actor with no usable geometry bounds. Despite the name it does not size the plot ghost (a plot's footprint is rooted on its size class instead).
    • The name is kept because it's a serialized property and renaming it would orphan authored data.

Everything else the style surface holds (the knobs across Ghosts/Footprints/Selection/Hover/Beams/HUD/Overhead Camera/Input) lives on the per-user UOutpostBuilderUserSettings, documented next.

Editor Module and Content Browser Actions

Header: OutpostBuilder/Source/OutpostBuilderEditor/OutpostBuilderEditorModule.h

FOutpostBuilderEditorModule::StartupModule() registers the editor mode, subscribes to FCoreUObjectDelegates::OnObjectPropertyChanged (live-refreshes loaded outposts/plots when a faction or building definition gets edited), and defers Content Browser context-menu registration until UToolMenus is ready. ShutdownModule() unwinds all three.

Two Content Browser asset-context-menu actions get registered on UOutpostDefinition assets:

  • Locate Placed Outpost - always shown for a selected UOutpostDefinition. Activates the Outpost Builder mode if it isn't already active, then calls LocateOutpostForDefinition on the active mode instance.
  • Restore Placed Outpost - same activation step, but greyed out while the definition's PlacedOutpostPath still resolves to a live AOutpost.
    • Enabled, it opens a "Restore Outpost" transaction, calls UOutpostStampLibrary::RestoreOutpost, folds the restored base into the configured Outliner folder while the transaction is still open (the fold Modify()s actors and can create a UActorFolder in a World Partition map, so it must not escape the undo scope), then selects, frames, and enters edit mode on the restored outpost.

The module's OnDefinitionAssetRenamed handler (asset-registry OnAssetRenamed) rebinds every loaded outpost/plot/camera/volume from the old name-based id to the new one, and re-folds alongside the rebind: the Outliner subfolder is the definition's PrimaryAssetName, so a rename orphans <base>/<old name>. Only actors still sitting in that exact stale computed folder are moved to <base>/<new name>, while anything the designer dragged elsewhere stays put.

Non-transactional like the rebind itself, for the same reason (the rename isn't Ctrl+Z-able, so an undoable follow-up could be reverted independently).

Note: the runtime module (FOutpostBuilderModule, OutpostBuilder/Source/OutpostBuilder/Core/OutpostBuilderModule.h) has its own StartupModule/ShutdownModule. It registers the primary-asset scan paths for THREE types with UAssetManager, the outpost and building definitions plus the settings asset (faction is not scanned, since it's an enum, not an asset).

It sets all three types' cook rule to AlwaysCook: definitions are reached only through FPrimaryAssetId, a name pair the cooker can't follow as a package-dependency edge, and the settings asset only through an ini-hosted soft path, which no cooked package references either.

It then pre-warms the configured settings asset (UOutpostBuilderSettingsAsset::PreWarm()) so the per-frame, never-loading resolution serves authored values from the first frame of a packaged game. It's deliberately in the runtime module rather than the editor one, which lets a packaged game resolve the same ids the editor tooling writes. Check out architecture.html for why that split exists.

Hotkeys and Mouse

Every KEY binding below is an FUICommandInfo (OutpostBuilderCommands.h/.cpp), rebindable under Editor Preferences > Keyboard Shortcuts > Outpost Builder. The key names listed are the shipped defaults, and the in-viewport legend, placement bar, and palette tile badges read the ACTIVE chords so they follow a rebind.

Mouse gestures (LMB place, RMB tap-to-cancel, the double-click into and out of editing) are not commands and are fixed.

Outside any session (no placement, no camera positioning):

  • LMB double-click on an outpost - enter editing on it, or leave editing when it's the outpost you're already editing. One gesture, both doors.
    • Plain LMB only and NO modifier held: Ctrl and Shift stay the editor's additive-selection gestures and Alt stays its orbit gesture, so all three fall through untouched. A single click still just selects.
    • The build-mode banner carries a Dbl-click legend row stating whichever face applies, which is the gesture's only written record (it has no chord to rebind and no button to read). See edmode.html's "The Viewport Way In and Out".

While placing an outpost or plot:

  • LMB - place. Refused (but still consumed) while a plot ghost is invalid.
  • RMB tap / Esc - cancel placement (Esc is the CancelPlacement command; RMB is a gesture, which means a drag still orbits).
  • 1-9 - the nine SelectPaletteBuilding commands: select a building palette slot, while editing an outpost and not positioning the camera. A tenth building is click-only.
  • 0 - SelectEmptyBuilding: select the palette's leading Empty tile, clearing the hot building so new plots are placed unassigned. Same gate as its nine siblings. Bare number keys by default; exact-chord matching means any Ctrl, Alt, or Shift held falls through instead, keeping editor bookmark chords working.

While placing a PLOT specifically, the same nine digits (plus 0) also badge the in-viewport building command grid's tiles (SOutpostBuildingCommandGrid, toolkit.html).

That's a grid of compact palette tiles (columns configurable, rows derived from content, each with a small truncated name under its thumbnail) anchored to a corner of the viewport, so the hot building can be switched without looking away from the placement ghost.

The badges are read off the SAME SelectPaletteBuilding/SelectEmptyBuilding chords the panel palette's own tiles show (never a second, positional key scheme). A rebind shows on both surfaces identically. Digits were kept over the RTS command-card convention's usual QWERT/ASDFG precisely because those collide with the flycam's own WASD/QE.

While editing an outpost (the editing viewport bar's four keybinds, where each chord's CanExecute is the literal SAME method its bar button's enabled state already reads, so a key can never do more than the button would):

  • N - AddPlot: starts placing a new plot (mirrors the bar's New Plot button / the Plots section's "+ New Plot").
  • O - PositionOverheadCamera: pilots the viewport onto this outpost's Overhead camera.
  • B - EditOutpostVolume: creates (if missing) and selects this outpost's Outpost Volume, then starts the Edit Outpost Volume excursion. See "Edit Outpost Volume Excursion" below.

  • J - RandomizePlots: assigns a random eligible building to each selected plot.

  • E - PickBuildingFromPlot, the eyedropper: loads the building assigned to the plot under the cursor (or the single selected plot) into the Selected Building. A plot with nothing assigned selects the palette's Empty tile rather than doing nothing, and a short toast names whichever was picked.

    • A DEDICATED key, never a modifier chord, because the Ctrl-remove tool already owns a user-configurable Ctrl/Alt/Shift chord that a designer's own setting could re-point onto whatever we picked here, making one gesture mean two things.
    • E is also the key The Sims uses for this exact verb, so it arrives pre-learned.

Bare E is NOT free, unlike the four defaults above, and that's an accepted trade rather than an oversight: E is the editor's Rotate widget-mode key and the flycam's up key. Both are protected by the command's CanExecute rather than by choosing a different key.

It refuses (and so falls through unconsumed) unless a pick target actually resolves, and always while the active viewport is tracking a drag, flying included, so E keeps flying the viewport and keeps reaching the Rotate widget except in the one state where a plot is genuinely under the cursor or selected.

The guard is IsTracking() and deliberately not IsFlightCameraActive(): that one is true whenever a navigation key is DOWN under Flight Camera Control Type = "WASD always", and E is itself one of those keys, so the guard would have refused its own keystroke. Rebind it in Keyboard Shortcuts if you want the plain E behavior back in that state.

The four BAR keybinds were each checked against the engine's own level-viewport chords before picking them (see OutpostBuilderCommands.h's own per-member doc for the specific collision each one dodges).

Checked chords: the WASDQE flycam keys plus its R/F/C/Z (local-up/down, FOV) rungs, the W/E/R gizmo-mode keys, the P/X/V/G viewport toggles (Navigation showflag, TRS-snap, vertex-snap, Game View), the Alt-modified showflag chords, and the L/U raw-poll orbit-force keys.

N/O/B/J are the confirmed-clear picks. The eyedropper's E is the one deliberate exception, covered above.

Each bar button's tooltip and face both show the active chord (FUICommandInfo::GetInputText()), so a Keyboard-Shortcuts rebind is always visible without needing this list.

While positioning the Overhead camera (the viewport overlay's three buttons, each showing its active chord on its face):

  • Enter - ConfirmOverheadCamera: saves the current framing to the definition and restores your viewport (the overlay's Done, its first button).
  • Home - RevertOverheadCamera: returns the camera to the last saved framing for the current target (the selected plot, or the outpost), or the computed default when none is saved yet.
  • Esc - cancels positioning and restores your viewport: the same CancelPlacement command placement uses, one Esc for both session kinds.

Both new chords are gated to the positioning session (CanExecute is IsPositioningOverheadCamera), so Enter and Home fall through unconsumed everywhere else.

Edit Outpost Volume Excursion

Clicking Edit Outpost Volume (the bar button, or its B chord) does its existing create-if-missing-then-select work, then, if a volume actually resolved, starts an excursion: the editor temporarily leaves Outpost Builder mode and enters the engine's own Geometry ("Brush Editing") mode (FGeometryEditingModes::EM_Geometry, Engine/Plugins/Editor/GeometryMode).

That's so the designer can reshape the volume's brush immediately with the stock vertex/edge/poly tools, no separate "enter brush editing" step required.

Activating Geometry mode deactivates Outpost Builder mode as a side effect (neither mode overrides IsCompatibleWith, so FEditorModeTools::ActivateMode treats them as mutually exclusive, exactly like any other legacy-mode switch). THAT tears down FOutpostBuilderToolkit and every viewport overlay it hosts, so the excursion cannot be toolkit-owned.

It is a small object (FOutpostVolumeExcursion, OutpostBuilderVolumeExcursion.h/.cpp) owned by the EDITOR MODULE instead (FOutpostBuilderEditorModule::ActiveVolumeExcursion/BeginEditVolumeExcursion), which outlives the mode switch:

  • Stores the editing outpost's definition id (a name-based FPrimaryAssetId, with nothing actor/definition-pointer-shaped to dangle across the switch).
  • Activates EM_Geometry via the SAME GLevelEditorModeTools().ActivateMode(...) entry point the Modes toolbar itself uses. There is no other supported way in. The volume was already selected by EditVolumeForEditingOutpost() before this runs, so the engine's own FEdModeGeometry::Enter() (which reads the CURRENT actor selection for ABrushes) picks it up with no extra wiring.
  • Mounts a compact "Editing Outpost Volume / Done (Esc)" viewport overlay, reusing SOutpostViewportOverlay, the same fully-generic bottom-center shell the toolkit's own overlays use (it holds no toolkit/mode reference by design), added via ILevelEditor::AddViewportOverlayWidget (ILevelEditor IS an IToolkitHost, the identical interface the toolkit's overlays use, just reached through FLevelEditorModule instead of a toolkit's cached host).
  • Registers itself as a Slate IInputProcessor so Esc returns even when the viewport doesn't hold Slate focus.

Return (Done button or Esc): unsubscribes its own watcher delegates first, removes the overlay/input processor, deactivates EM_Geometry, re-activates EM_OutpostBuilderId, then calls the freshly-active UOutpostBuilderEdMode::LocateOutpostForDefinition on the stored id, the SAME select+frame+EnterOutpostEditMode path the Content Browser's "Locate Placed Outpost" action already uses. That lands the designer back in Outpost Builder mode, editing the same outpost.

Abnormal teardown: the designer may instead manually pick a third mode from the Modes toolbar, or close/switch the map. Either is caught (FEditorModeTools::OnEditorModeIDChanged / FWorldDelegates::OnWorldCleanup, the latter scoped to the EDITOR world only, mirroring UOutpostBuilderEdMode::HandleWorldCleanup's own guard) and torn down the same way (overlay/input-processor/delegates removed).

It deliberately does NOT re-activate Outpost Builder mode or re-enter editing, since the designer's own action (or the map going away) should win, not be silently overridden.

Engine finding worth noting: FGeometryEditingModes::EM_Geometry lives in the GeometryMode engine plugin (Engine/Plugins/Editor/GeometryMode, EnabledByDefault: true). There is no EM_Geometry-equivalent constant in FBuiltinEditorModes itself (that plugin was the only place it's still defined in UE 5.8).

Activation never refuses for lack of a selection: FEdModeGeometry::Enter() just calls GetFromSource(), which produces an empty (but valid) geometry-object set if nothing selected. The excursion never needs a fallback path for a "mode refused to activate" case because that case doesn't occur here.

  • Ctrl + S (the SaveOutpostAssets command) - while the mode is active, saves every dirty outpost/building definition package, then deliberately passes through so the editor's own level save runs too. (Alt + LMB is purely the editor's orbit gesture.)

Test Factions Script - Now a Read-Only Migration Helper

scripts/create_test_factions.py is a read-only migration helper. Factions are the fixed EOutpostFaction enum, so there is nothing to author beyond picking a value per outpost (see faction-visuals.html); the script creates and updates nothing.

Running it prints that explanation and, read-only, lists any asset paths still present under /Game/Outposts/Factions/, as a reminder to delete them manually (they're orphaned once the class they were saved against no longer exists). It never references unreal.OutpostFactionDefinition, since that class no longer exists.

The editor has to be closed first. A running editor already holds the project's asset registry and package locks. A second process opening the same project will conflict with it. The shape of the command, with your own paths substituted in:

"<engine-root>\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" ^
    "<your-project>\YourProject.uproject" ^
    -run=pythonscript -script="<plugin-root>\scripts\create_test_factions.py" ^
    -EnablePlugins=PythonScriptPlugin

Note: -EnablePlugins=PythonScriptPlugin enables the Python Editor Script Plugin's commandlet for this one run, without editing the .uproject file. That flag matters, since the plugin ships with EnabledByDefault: false, and the host project's .uproject doesn't list it either. Without it, -run=pythonscript won't resolve to anything, since there's no such commandlet registered.

Columns are configurable; rows derive from content.
    • Also not built on SOutpostViewportOverlay, for the same corner-anchor-vs-bottom-center-shell reason SOutpostBuildModeBanner isn't. Mounted/unmounted by HandlePlacementStateChanged (IsPlacementActive() && IsPlacingPlot()), alongside PlacementOverlayWidget.
    • Two UOutpostBuilderUserSettings knobs (BuildingGridCols/BuildingGridAnchorCorner, category UI|BuildingGrid) size and anchor it. See "Per-User Style Settings" above. Deep dive: toolkit.html's "The In-Viewport Building Command Grid".

The browser widget itself (list, inline details view, "+ New Building", Find References in World) lives in SOutpostBuildingsBrowser.h/.cpp below.

    • Owns FBuildingBrowserEntry/FBuildingReferenceEntry, the browser list, its inline details view, "+ New Building" (via the toolkit's OnCreateBuildingRequested delegate), and Find References in World (plot-record scan, loaded and unloaded maps alike).

SOutpostTabBar<TEnum>'s only mount is the Overview panel's Outposts/Buildings bar (EOutpostBrowseTab).
