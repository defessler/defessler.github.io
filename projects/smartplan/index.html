Route each model to the work it's good at.

Agent Skills for Claude Code and GitHub Copilot CLI. Strong models plan and check. Cheap models write the code. Nothing they write merges until a verifier has re-run its check.

The skills name roles, not vendors. Each role goes to the best model your harness serves for it, whoever makes it.

Built for C++ game development first, across Unreal, a custom engine or plain C++. The routing works in any language.

Whatever the harness, the skill fills the same roles. A cheap model writes the code. What you get

Seven skills that work in Claude Code and Copilot CLI. You only ever call /smartplan. The rest trigger on what you ask for. smartplan's own features (fan-out, model tiers, the cost dial, briefs, verify) are part skills of their own, so you can switch off any one you don't want. Each one has a short example of what it gives back, and Getting Started walks through a whole session. The rulebook lists every rule and figure in the family as one plain line each, with a filter box, so you can check what a skill will do before it does it.

smartexec

The rules a cheap model works under. It does only what its brief says and proves it with pasted test output. Otherwise it stops and reports BLOCKED.

smartplan hands it to each part of a plan. You don't call it.

See an example 
DONE: add SaveState to InventoryComponent
Files changed: Source/Game/InventoryComponent.cpp,
  Source/Game/InventoryComponent.h
Verify-first: matched
Acceptance:
$ ctest -R Inventory --output-on-failure
100% tests passed, 0 tests failed out of 6
Deviations: none

When the brief doesn't fit the code, it stops instead of guessing.

BLOCKED: add SaveState to QuestLog
Tried: added the field, ran the acceptance
Obstacle: QuestLog.h includes SaveTypes.h, which
  isn't in FILES and has no FQuestEntry
Unblock: add SaveTypes.h to FILES, or name the type

How it works

Every task starts with one line saying how it will run. The first row that matches wins.

The work Route
Bigger than one context window Fan out
Four or more independent parts, separate files, and finishing sooner beats finishing cheaper Fan out
Inline already failed twice on the same error Fan out
Risky merge (C++ undefined behavior, concurrency, templates, security) Inline, plus an independent check
Everything else Inline

A fan-out runs in three steps. You approve the plan before any work starts.

  1. Plan. A strong model splits the work into parts that touch separate files, each with a written brief and a check that can fail.
  2. Build. A cheap model builds each part from its brief and pastes the check's output as proof.
  3. Verify. A fresh model at least as strong as the builder re-runs the check and reads the diff. Nothing merges on the builder's word.

Fanning out costs 1.5 to 2.9 times an inline pass at equal quality, at every size measured so far. The skill only does it when the time saved is worth that. It says so in the routing line when it does.

Does it work? Across seven test scenarios on Haiku, Sonnet and Opus, 62 of 63 runs passed with the skill and 4 of 21 without. The benchmarks page has the method and the caveats.

Install

On Claude Code, add the marketplace and install the plugin.

/plugin marketplace add defessler/smartplan
/plugin install sp@smartplan

On Copilot CLI, or for a zip you can unpack anywhere, see Quickstart and Downloads. Then run the install check to prove it's wired up.
