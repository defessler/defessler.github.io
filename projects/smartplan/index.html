Portable Agent Skills that route each model to the work it's good at. Strong models plan and judge. Cheap models execute behind a verifier gate. It runs in Claude Code and GitHub Copilot CLI.

Does it work?

Seven scenarios, run with and without the skill on Haiku 4.5, Sonnet 5, and Opus 5, each graded by three independent judges. The with-skill arm ran every case three times per model. The baseline ran each once, which is why the counts are 63 and 21.

It holds on the cheap seat too. The newest case passed 3/3 on Haiku, Sonnet, and Opus alike.

Caveats. The no-skill arm was told not to use the skill rather than prevented from it. The run is a hand-built stand-in for claude plugin eval while that's in early access. One case passes without the skill too and stays in the suite for that reason. Another failed its first pass at 6/9 and reached 9/9 only after the rule it tests was rewritten.

Method and full results: T39 and T40.

The rule

Plan with the strong model. Implement with the cheaper model. Escalate on demonstrated failure, never on a hunch. And never reach above your current seat without asking.

A strong model's edge is mostly in planning and decomposition, not in writing any one leaf of code. So buy quality once at the plan, then go cheap and wide. Three things make that safe: a per-leaf contract, a disciplined executor, and an independent verifier never weaker than what it checks.

How it routes

The first matching row wins.

The work Route
Bigger than one context window Fan out
≥4 independent units, disjoint files, and finishing sooner beats finishing cheaper Fan out
Inline already failed twice on the same error Fan out
Risky merge (C++ UB, concurrency, templates, security) Inline, plus an independent check
Everything else Inline

Fan-out costs 1.5–2.9× an inline pass at equal quality, at every leaf count and size measured. So it's a deliberate purchase of wall-clock time. The skill says when it's making one.

Independent verification still gates risky merges at any size. Cheap-tier output never merges unchecked.

Primary use case: C++ game development

Engine-agnostic across Unreal, a custom engine, or vanilla C++.

smartreview reviews a changelist against a swappable per-project standards doc and ranks what it finds: game-breaking bugs first, then best practices, then conventions. Its shipped default is C++ gamedev. General C++ rules apply everywhere, with Unreal and custom-engine idioms as selectable profiles.

The brief and verify references add a C++ correctness layer (ownership and lifetime, undefined behavior, hot-path performance, threading, header hygiene, determinism and serialization) that keeps cheap tiers safe on gamedev diffs. The tiering policy itself is language-agnostic and covers non-gamedev work the same way.

What ships

Path Read by What
.claude/skills/ Claude Code, Copilot CLI smartplan (entry point and flow policy), smartexec (executor payload), and four companions: smartreview, smartwiki, smartvoice, smartdiagram.
.claude/agents/ Claude Code Implementer, cheap implementer, scout, and verifier, all tool-locked. The scout is read-only. The verifier gets Bash to re-run acceptance but no file-editing tools.
.github/agents/ Copilot CLI The same seats as pinned profiles.
evals/ claude plugin eval Eight graded cases, four testing what the skill refuses to do. The eighth, seat-ceiling, is unrun.
scripts/smartcheck-mechanical.sh both Zero-model verifier for mechanical leaves: acceptance criteria, git scope, allow list.
docs/benchmarks/ humans One timestamped record per live test, with real costs and verdicts.

smartroute, smartbrief, and smartcheck are seat names, not directories. Their content lives in .claude/skills/smartplan/references/.

Both harnesses read the one skill tree natively. Marketplace installs serve it too, with no packaged copy or sync step. Skills self-trigger from their descriptions, with no instructions file needed on Copilot.

Install

Claude Code: install the plugin.

/plugin marketplace add defessler/smartplan
/plugin install sp@smartplan

Or open the repo, which auto-loads .claude/skills/. Invoke with /smartplan.

Copilot CLI: in this repo, it auto-loads .claude/skills/ and .github/agents/. Elsewhere, copy the skill folders into ~/.copilot/skills/ and the agents into ~/.copilot/agents/. Manage them with /skills list and /subagents.

Windows, interactive: scripts\install.cmd walks you through picking a target and skills. Re-run it to toggle them later.

Windows, every session always current:

powershell -ExecutionPolicy Bypass -File scripts\install-global.ps1

This junctions the core pair and both agent directories into the checkout. One git pull then updates every session on the machine, with no frozen plugin cache or /plugin update. Re-run it any time to repair a setup, since it's idempotent.

Companions install per project with scripts\install-project.ps1 -Project <root>, which keeps their descriptions out of every session's standing context.

Note: Copilot's sandbox can't read through a junction that points outside the project root. In a project set up this way, run Copilot with --add-dir <this-checkout>. Claude Code follows the junctions without it.
