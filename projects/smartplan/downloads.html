What the bundles are, and are not

Claude Code and Copilot are installable trees. Unzip, follow the Quickstart for your harness, and the skills load.

M365 Copilot has no package format. Agent Builder takes pasted instruction text. That zip is documentation, built around three instruction blocks sized to the 8,000-character field. references/m365-copilot.md in the source tree says which half of this family ships there and which half structurally can't.

Which one do I want?

Take the one for your harness. What to know about each:

  • Claude Code is the reference implementation and the only surface where you set the model on each call.
  • Copilot CLI puts everything under .github/, one folder to commit in a shared repo.
  • M365 Copilot: read the install guide before pasting anything. Its "Three things that will bite you" section will save you an afternoon.

Freshness

The version, size, file count, and build date under each link come from the archives themselves at build time. Version and build date match across all four because the bundles ship together from one tree.

Filenames stay unversioned so links keep working. To tell what a zip is later, read the BUNDLE-INFO.txt at its root. It carries the same stamps plus the commit it was built from.

Since bundles rebuild on every push, the build date is roughly when the source last moved. Before you trust a model roster, check the data date in the page header instead. It records the last primary-source sweep. A bundle built today can still carry research from a fortnight ago.
