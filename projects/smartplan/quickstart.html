smartplan routes each model to the work it's good at. A strong model plans and judges while cheaper models implement behind an independent verifier. It escalates only on failure.

1. Install (pick your harness)

Windows: scripts\install.cmd or scripts\install.ps1 replaces the manual steps below. It asks where to install and which skills to turn on.

Claude Code. Open this repo and run /smartplan. The skills load from .claude/skills/. Or, in any project, run /plugin marketplace add defessler/smartplan, then /plugin install sp@smartplan, and use /sp:smartplan. Don't do both in one repo. Plugin copies stay frozen at the version you installed until you run /plugin update sp@smartplan.

Copilot CLI. Open this project. The skills load from .claude/skills/ and seven pinned agents from .github/agents/: @smartplan-planner, @smartplan-implementer (plus -cheap and -reserve), @smartplan-verifier (plus -cheap at max-savings), and @smartplan-scout. For personal use, copy the skill folders into ~/.copilot/skills/ and the agents into ~/.copilot/agents/. Don't leave the session model on Auto for tiered work. Auto overrides every subagent's pin and re-routes mid-task. Inline sessions can keep Auto and its 10% discount (paid plans only).

ZCode. Run bash scripts/zcode-export.sh and point ZCode's marketplace at dist/zcode/. Or copy skills/ into ~/.zcode/skills/ and agents/ into ~/.zcode/agents/. Put the generated AGENTS.md at ~/.zcode/AGENTS.md or your workspace root. ZCode never reads CLAUDE.md at runtime. More in references/zcode.md.

Microsoft 365 Copilot. There's no bundle. Paste text into Agent Builder:

  1. In M365 Copilot, choose New agent, then Skip to configure.
  2. Paste the Name, Description, and Instructions from a file in docs/m365-agents/.
  3. Set the response mode to Think deeper.
  4. Open the agent from the rail. @mention may ignore the response mode.

Three agents ship: UE5 Engineer, Studio Doc Writer, and UE5 Build & Crash Doctor. The install guide has the field limits. Most of this family does not port to M365 (see references/m365-copilot.md).

2. Fill-once configuration

Only smartreview needs filling before first use.

  • smartplan {{MODE}} (quality/cost dial): optional. Pick max-quality, high-quality, balanced, budget, or max-savings per run (--mode budget or plain words), per leaf (a plan's unit of work) with a MODE: line in its brief, or here as the default. A mode sets which model class plans (the "seat"), the implementer's minimum tier (the "floor"), verify depth, effort, report detail, and parallelism. No mode changes the human gate, verify-before-merge, or honest reporting. The full matrix is in smartplan/references/modes.md.

Defaults follow billing: max-quality on Claude Code, max-savings on Copilot CLI, which meters AI credits per token.

  • smartreview (code review): FILL BEFORE FIRST USE. In .claude/skills/smartreview/references/cpp-review-standards.md § Project Profile, set Engine (vanilla, custom, or unreal) and the C++ tokens ({{COMPANY}}, {{PREFIX}}, and the rest). In .claude/skills/smartreview/SKILL.md § Project Profile, set indentation, max line length, and local-variable case. Unset tokens leave their rows N/A. The bug hunt needs only Engine. Not C++? Point {{STANDARDS}} at your own standards doc.
  • smartvoice (house voice): works out of the box. It uses voice-profiles/<username>.md when one matches your OS username, else defaultvoice.md. To personalize, copy either to voice-profiles/<your-username>.md (your whoami name in lowercase, without the domain). Delete defaultvoice.md to skip the voice pass for everyone else.

python .claude/skills/smartvoice/scripts/install_voice.py applies the chat rules to every reply on Claude Code and Copilot CLI, subagents included. --uninstall removes them.

  • smartwiki (change writeups): ships ready for Git and Perforce. For another VCS, fill the four verbs in its VCS Adapter.
  • Model roster: edit by hand when models move. Reclassify a model in .claude/skills/smartplan/references/model-classes.md and every seat rule follows.

3. First run

In your project, type:

/smartplan <task>

For a first test, pick work that's too big for one context or needs an independent check. A small task just runs inline, which is correct but shows you less.

smartplan routes by regime. A task that fits one strong model's context runs inline, skipping plan, fan-out, and verify, which cost more than they save at that scale (T14, T19, T20, T21). On a real UE5 task the as-shipped skill measured 1.05x bare cost at equal quality, in Copilot credits (T28).

Fan-out (parallel leaves) pays only for work too big for one context, failure-prone work that keeps needing rework inline (T9), wall-clock-bound batches, or merges that need independent verification. Width alone doesn't pay: a wide, easy, one-context task cost 180% of inline (T20).

When the full flow runs, you'll see:

  1. A plan of small independent leaves, each with a model class. An ambiguous ask gets a clarifying question first.
  2. A gate. Nothing edits until you approve.
  3. A dispatch-board line showing each leaf's model, like ▶ 3 running: L1 stubs→haiku · L2 parser→sonnet · L3 scout→haiku | seat: opus (plan)

Between updates, watch /tasks on Copilot or the agent panel on Claude Code.

  1. Verification: every cheap leaf gets an independent check.
  2. An Integrate pass that reconciles the seams before you accept.

Two files may appear in your project root: run-state.md, which lets a crashed run resume, and contracts.md, which freezes the interfaces parallel leaves share. Commit or ignore them.

4. Verify it actually works

bash scripts/selftest.sh

That checks the static install in about two seconds. Then run the four behavioral probes in docs/selftest.md, graded on visible artifacts (files, board lines, gate behavior) rather than the model's claims.

Note: on Claude Code, whether each leaf bills as its intended model is contested upstream (issue #43869). Only the Console usage page shows the per-model bill. If guaranteed tiering matters more than fan-out, use /model opusplan, which isn't affected.

5. Day-to-day

  • The plan seats by class even when you name a model. "Use Opus for the renames" gets Haiku, flagged at the gate. Say "seat it anyway" to override.
  • Under budget or rate-cap pressure, mechanical work drops a tier. Planning waits for the reset instead.
  • Repeated deterministic work moves into a script, which costs no model calls.

Going deeper

The skill body (.claude/skills/smartplan/SKILL.md) is the policy. references/routing.md maps task classes to tiers. model-classes.md is the roster.

check.md is the verifier protocol. claude-code.md, copilot.md, zcode.md, and m365-copilot.md cover each harness. caching.md covers prompt caching. The changelog (docs/changelogs/smartplan.md) records why each rule exists.
