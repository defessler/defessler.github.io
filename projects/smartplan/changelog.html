2026-11-02 · smartdiff reviews only the agent's own edits, on Copilot CLI and Claude Code (v4.153.0)

Agent-only mode. trail.py exports the edits the agent made and nothing else, read from the session record rather than the working tree, so a teammate's change or a hand edit can't leak into the review. It scopes to the last message, the last N messages or the whole session. It reads Copilot CLI sessions (apply_patch, edit and create) and Claude Code transcripts (Edit, Write and subagent edits), and finds the running session by itself. A change it can't prove from recorded evidence is left out and named, and the run exits 2. It ships the before and after files, a plain diff, the prompts and a transcript beside the page. Checked live on both harnesses: a real Copilot CLI edit session, and this repo's own Claude Code session, where every reconstructed file matched the live copy.

The page gains an expandable diff. a or a click on a hunk header shows the omitted lines between hunks. b or a chevron hides the file list, with f kept as an alias. Free functions, static calls, format strings and Unreal export macros get their own colors. diffview.py --git-context <repo> reads whole files from git so a normal session diff can expand too.

Oracle stage (k) now also runs a 31-case trail self-test.

2026-11-03 · Every smartplan feature is its own skill, and any one can be switched off (v4.164.0)

The author asked for each smartplan feature to live in a separate skill, with smartplan picking the ones a task needs, and for any part to be switchable by disabling its skill.

Eight part skills. The references moved out of smartplan/ with their history intact: smartflow (flow.md, artifacts.md), smartroute (routing.md, model-classes.md), smartcost (modes.md), smartbrief (brief.md), smartcheck (check.md), smartcheck-cpp (cpp-gamedev-check.md) and smartcache (caching.md, Claude Code only). smartexec joins them as a part. Each one's SKILL.md says to read its reference whole and states what smartplan does without it.

The listing is the switch. Parts are user-invocable: false, which keeps them off the slash menu but in the model's skill listing. smartplan treats a part as on only when that listing names it. A part switched off by the harness toggle, skillOverrides or the installer's SKILL.md.off rename is skipped. smartplan follows its Off column in the new Parts table, says so once after the routing call, and never reads the part's files by path to get around the switch. smartexec lost its disable-model-invocation line so it can be listed too. Turning smartflow off means no fan-out at all.

What stayed in smartplan. The harness references (copilot.md, claude-code.md, m365-copilot.md, local-models.md) and evidence.md are facts about a harness, not features, so they stay.

A live check. Probe 5 in docs/selftest.md switches smartflow off and reruns Probe 2's prompt. A headless Haiku 5.5 run with skillOverrides setting smartflow off listed the other parts, said smartflow was missing, routed inline and read none of its files.

The plumbing followed. check.sh gate (c) resolves a reference in any part, gate (p) reads the new hard-gate line, and gate (k) rises from 2,816B to 4,096B for fourteen descriptions (3,745B used). selftest checks 13 skills. Both exports carry the parts, and the Copilot bundle drops smartcache with a new assert that it can't leak. The three installers know the parts. install.ps1 prints what you lose when you switch one off. install-global.ps1 links smartcache for Claude Code only. Both verifier seats load smartcheck.

2026-11-03 · The verifier seat runs code reviews through smartreview (v4.165.0)

The author asked for the verifier to load smartreview. A review run in the session that wrote the code shares that code's blind spots, so reviews now go to the seat that already sits apart from the author.

One seat, two jobs. smartplan-verifier on Claude Code and Copilot CLI now has a review mode. Asked to review a change, a changelist or a fileset rather than verify a leaf, it loads smartreview and follows its Protocol and Report instead of check.md's verdict templates. It resolves the skill the same way it resolves check.md. It has no edit tools, so every fix is proposed. With no smartreview installed it reports BLOCKED rather than review from memory. No new seat, no new description in the standing load and no new Copilot profile.

Not on Luna. smartplan-verifier-cheap refuses a review outright, since a review is judgment from top to bottom and that seat is Mechanical. It names @smartplan-verifier as the Unblock, and unlike its other refusals this one never gives way.

smartreview/SKILL.md gains a short "Review away from the author" paragraph that points at the seat.

A live check. Probe 6 in docs/selftest.md asks the verifier seat for a review. A headless Claude Code run as smartplan-verifier on Opus 5.5 reviewed the vanilla ProjectilePool fixture. It came back in smartreview's Report shape with a Standards: line, BREAKING, PRACTICE and CONVENTION, and 23 proposed fixes, none applied, with the tree left clean. That run tested the seat's instructions, not a dispatch from another session.
