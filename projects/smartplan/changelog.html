2026-11-03 · Every smartplan feature is its own skill, and any one can be switched off (v4.164.0)

The author asked for each smartplan feature to live in a separate skill, with smartplan picking the ones a task needs, and for any part to be switchable by disabling its skill.

Eight part skills. The references moved out of smartplan/ with their history intact: smartflow (flow.md, artifacts.md), smartroute (routing.md, model-classes.md), smartcost (modes.md), smartbrief (brief.md), smartcheck (check.md), smartcheck-cpp (cpp-gamedev-check.md) and smartcache (caching.md, Claude Code only). smartexec joins them as a part. Each one's SKILL.md says to read its reference whole and states what smartplan does without it.

The listing is the switch. Parts are user-invocable: false, which keeps them off the slash menu but in the model's skill listing. smartplan treats a part as on only when that listing names it. A part switched off by the harness toggle, skillOverrides or the installer's SKILL.md.off rename is skipped. smartplan follows its Off column in the new Parts table, says so once after the routing call, and never reads the part's files by path to get around the switch. smartexec lost its disable-model-invocation line so it can be listed too. Turning smartflow off means no fan-out at all.

What stayed in smartplan. The harness references (copilot.md, claude-code.md, m365-copilot.md, local-models.md) and evidence.md are facts about a harness, not features, so they stay.

A live check. Probe 5 in docs/selftest.md switches smartflow off and reruns Probe 2's prompt. A headless Haiku 5.5 run with skillOverrides setting smartflow off listed the other parts, said smartflow was missing, routed inline and read none of its files.

The plumbing followed. check.sh gate (c) resolves a reference in any part, gate (p) reads the new hard-gate line, and gate (k) rises from 2,816B to 4,096B for fourteen descriptions (3,745B used). selftest checks 13 skills. Both exports carry the parts, and the Copilot bundle drops smartcache with a new assert that it can't leak. The three installers know the parts. install.ps1 prints what you lose when you switch one off. install-global.ps1 links smartcache for Claude Code only. Both verifier seats load smartcheck.

2026-11-03 · The verifier seat runs code reviews through smartreview (v4.165.0)

The author asked for the verifier to load smartreview. A review run in the session that wrote the code shares that code's blind spots, so reviews now go to the seat that already sits apart from the author.

One seat, two jobs. smartplan-verifier on Claude Code and Copilot CLI now has a review mode. Asked to review a change, a changelist or a fileset rather than verify a leaf, it loads smartreview and follows its Protocol and Report instead of check.md's verdict templates. It resolves the skill the same way it resolves check.md. It has no edit tools, so every fix is proposed. With no smartreview installed it reports BLOCKED rather than review from memory. No new seat, no new description in the standing load and no new Copilot profile.

Not on Luna. smartplan-verifier-cheap refuses a review outright, since a review is judgment from top to bottom and that seat is Mechanical. It names @smartplan-verifier as the Unblock, and unlike its other refusals this one never gives way.

smartreview/SKILL.md gains a short "Review away from the author" paragraph that points at the seat.

A live check. Probe 6 in docs/selftest.md asks the verifier seat for a review. A headless Claude Code run as smartplan-verifier on Opus 5.5 reviewed the vanilla ProjectilePool fixture. It came back in smartreview's Report shape with a Standards: line, BREAKING, PRACTICE and CONVENTION, and 23 proposed fixes, none applied, with the tree left clean. That run tested the seat's instructions, not a dispatch from another session.

2026-11-11 · smartdiff reads a shelved changelist, names every file, and shows added values (v4.169.0)

Three fixes from one field report: a Copilot session that rendered a shelved Perforce changelist and had to work around the skill to do it.

A shelved changelist works. bp_prepare.py --p4 -c <CL> only asked p4 opened, and a shelf has nothing opened, so it prepared zero Blueprints. It now reads the shelf with p4 describe -S. The old side is the revision each file was shelved against. The new side is the shelved file, <depotFile>@=<CL>, which isn't in the workspace, so bp_export.py stages it the way it already staged the old revision. --shelved asks for this outright. A -c changelist with nothing opened gets it unasked. SKILL.md's step 1 gains the matching capture, p4 describe -S -du5 <CL>.

No more "(unnamed)" files. p4 describe -du names a file only in its ==== //depot/path#rev (type) ==== line, with no --- and +++ lines after it. diffview.py read that header in p4 diff's shape alone, so a text file from a shelf, a .ini in the report, came out unnamed. Both shapes are read now, and a binary type marks the file binary.

Added and removed items show their values. An added node lists the pin values it was given, an added variable its default, an added component or other subobject its properties (eight, then a count), and a pin added to an existing node its value. Removed ones show what they carried. Before this only a changed value was printed.

SKILL.md says not to text-diff the T3D exports. The session did, and got megabytes of serialized path noise. --blueprints is the reader. The file's gate (i) cap goes from 5.75KB to 6.0KB for these lines.

Tested against a stand-in, not a server. This box has no Perforce. A new self-test, smartdiff-prepare-selftest.py in oracle stage (k), plants a fake p4 and checks which revisions bp_prepare.py asks for. The staged load of a shelved revision in the editor isn't exercised here. The turret demo is re-rendered for gate (aa). The videos aren't, as in v4.168.0.

2026-11-17 · smartdiff names events as the editor does, shows one final diff per file, and puts review findings on their lines (v4.173.0)

Three asks from the author: the wrong event names on deleted nodes, a diff that is the final result rather than one per prompt, and smartreview's findings shown as comments on the lines they name.

Events carry the editor's name. T3D saves an overridden event by its function, so a removed wire read Event ReceiveBeginPlay.then where the editor says Event BeginPlay. node_title now drops the Receive or K2_ prefix, spaces End Play and component events the way the editor does, and titles component-bound, actor-bound, input key, input action and input axis events by what they listen to. Those used to fall through to a bare class name like ComponentBoundEvent, so two removed overlap events couldn't be told apart. A removed wire also names its nodes from the old revision now. A custom event renamed in the same change used to show its new name on a wire that only the old one had.

One comparison per file in agent-only mode. trail.py joined a file's edits only while each began exactly where the last ended. A hand edit or a formatter in between split the file into one diff per prompt. Each file is now one comparison from before the first agent edit in the range to after the last. A change between two agent edits sits inside it, so the run names the file and exits 2 rather than splitting it. SKILL.md says to render one page for the range.

Review findings sit on their lines. diffview.py --review and trail.py --review take smartreview's report as written, or JSON findings, and put each one under the line it names, on its own side in the split view. A finding on a line the diff doesn't show sits above its file, and one on no file in the diff sits above the file list. The header counts them, a file with comments always opens, and n and p step through them. smartreview's SKILL.md points at the flag.

smartdiff-selftest.py gains 21 checks: seven event titles, no event left under its function name on the planted page, the removed wire's old name, and twelve on review comments (rows in both views, both side blocks, the counts, the keys, a skipped Ambiguous line, and JSON findings on a removed line and on a Blueprint). Two trail tests now expect one comparison and a warning where they expected a split. Not tried on a real UE export here. The event titles follow the engine's DisplayName metadata as of UE 5.8, at time of writing, so a project event with its own DisplayName still shows its function name.

2026-11-17 · One reviewer for every engine: detection and project overlays replace the Unreal seat (v4.175.0)

The author asked whether the new Unreal reviewer should be a mechanism instead of a special seat, then pointed out that EngineAssociation often isn't set. Both answers landed.

Detection. smartreview's C++ standards doc now resolves the Engine itself: stated by the project, else detected from project files, else vanilla. A new stdlib script, smartreview/scripts/ue_engine.py, finds the .uproject, .uplugin or *.Build.cs and works out the engine version even when EngineAssociation is empty or a build id. It tries an engine tree above the project, the binaries' BuildId, the editor log, the engine that saved the assets, and the one engine installed, and it lists every probe's answer with any conflicts. Oracle stage (l) plants each case. smartcheck-cpp and smartbrief resolve the Engine Profile the same way when a brief leaves it out.

Mechanism. A standards doc can add steps the driver runs, and the C++ doc's Unreal procedure (version, Build.cs and config, header-checked deprecations, Blueprints through smartdiff) moved there from the seat. A project's own rules go in an overlay, REVIEW-STANDARDS.md with an Extends: line, rather than a fork or a seat.

The seat is gone. smartreview-unreal left both harnesses, and the Copilot profile count is back to seven. On the Unreal fixture, in a project with an empty EngineAssociation and a brief that never said Unreal, the plain verifier caught all 7 gradeable seeds, the same as the seat, for 157,433 tokens.

2026-11-19 · smartdiff reads more than Blueprints, and a move no longer looks like a new wire (v4.176.0)

Two asks from the author: turn a design note on generic graph-asset reading into a solution for smartdiff, and give Blueprints whose nodes or wires only moved a treatment that doesn't look like new connections.

Readers. bp_export.py now picks a reader by the asset's type or what it holds: blueprint, material for Materials and Material Functions, and edgraph for any other asset that saves editor graphs, like a Sound Cue. Each side's record says which reader ran and whether it worked. diffview.py trusts that record instead of looking for "Blueprint" in the class name. A revision that didn't load or didn't export now marks the file "Not compared" with the reason. It used to show every node as added, or no changes at all.

Moves. Wires compare as real connections, with reroute chains collapsed, and a cut-and-pasted node pairs with the one it replaced. Only a changed endpoint is a new wire. In the drawing a moved node gets a dotted grey outline and shows its old place on hover, a new route for an old connection draws dotted, and green and red are kept for real changes.

Checked end to end on UE 5.8 with a Material, a Sound Cue and a Blueprint through the real export, and by screenshot. An Opus verifier found a crash on a deleted reroute-only graph in its first round, now fixed. The smartdiff self-test gains 34 checks. smartdiff's SKILL.md cap went from 6.5KB to 6.75KB, recorded in the M4 table.

2026-11-21 · smartdiff's trail mode shows the Unreal assets an agent changed through Aethyr (v4.177.0)

The author planned this with an Aethyr-MCP change on 2026-11-20. An agent's asset edits through Aethyr reached the session record only as JSON replies, so trail mode, which exports just the agent's own work, showed none of them.

Assets in trail mode. trail.py reads saved_packages from each mcp__* tool result in a Claude Code transcript. Each entry names the SHA-1 and journal blob of the file before and after the save. Both sides are copied into <output>/bp, each checked against its hash first, and the range rule matches the one for files: the first save's before-image against the last save's after-image. --export-assets runs the headless export and puts the Blueprint diff on the page. A package the call deleted stages its old side only and lists as removed. A missing or mismatched blob is named under the partial results, never guessed at.

Safer staging. A saved_packages entry comes from a tool result, so its package name has to match a long package name, its extension has to be an asset extension, and each staged file has to resolve inside the export folder.

bp_prepare.py's export command is now export_command(), shared by both paths. The new smartdiff-trail-selftest.py covers the reader, the range rule, the hash check, staging, deletes and the refused names. Aethyr's own live check fed real blobs from a headless editor through the same functions, and the page showed the Blueprint diff. Still open: one run from a real session record, which waits on a gate token. Copilot CLI sessions aren't read for assets yet, so the feature stays out of the Copilot export.

Also in this release: the public README, the downloads page and QUICKSTART said five Claude Code seats and eight Copilot seats after the v4.175.0 seat removal. They now say four and seven.
