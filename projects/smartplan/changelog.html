2026-11-03 · Every smartplan feature is its own skill, and any one can be switched off (v4.164.0)

The author asked for each smartplan feature to live in a separate skill, with smartplan picking the ones a task needs, and for any part to be switchable by disabling its skill.

Eight part skills. The references moved out of smartplan/ with their history intact: smartflow (flow.md, artifacts.md), smartroute (routing.md, model-classes.md), smartcost (modes.md), smartbrief (brief.md), smartcheck (check.md), smartcheck-cpp (cpp-gamedev-check.md) and smartcache (caching.md, Claude Code only). smartexec joins them as a part. Each one's SKILL.md says to read its reference whole and states what smartplan does without it.

The listing is the switch. Parts are user-invocable: false, which keeps them off the slash menu but in the model's skill listing. smartplan treats a part as on only when that listing names it. A part switched off by the harness toggle, skillOverrides or the installer's SKILL.md.off rename is skipped. smartplan follows its Off column in the new Parts table, says so once after the routing call, and never reads the part's files by path to get around the switch. smartexec lost its disable-model-invocation line so it can be listed too. Turning smartflow off means no fan-out at all.

What stayed in smartplan. The harness references (copilot.md, claude-code.md, m365-copilot.md, local-models.md) and evidence.md are facts about a harness, not features, so they stay.

A live check. Probe 5 in docs/selftest.md switches smartflow off and reruns Probe 2's prompt. A headless Haiku 5.5 run with skillOverrides setting smartflow off listed the other parts, said smartflow was missing, routed inline and read none of its files.

The plumbing followed. check.sh gate (c) resolves a reference in any part, gate (p) reads the new hard-gate line, and gate (k) rises from 2,816B to 4,096B for fourteen descriptions (3,745B used). selftest checks 13 skills. Both exports carry the parts, and the Copilot bundle drops smartcache with a new assert that it can't leak. The three installers know the parts. install.ps1 prints what you lose when you switch one off. install-global.ps1 links smartcache for Claude Code only. Both verifier seats load smartcheck.

2026-11-03 · The verifier seat runs code reviews through smartreview (v4.165.0)

2026-11-11 · smartdiff reads a shelved changelist, names every file, and shows added values (v4.169.0)

Three fixes from one field report: a Copilot session that rendered a shelved Perforce changelist and had to work around the skill to do it.

A shelved changelist works. bp_prepare.py --p4 -c <CL> only asked p4 opened, and a shelf has nothing opened, so it prepared zero Blueprints. It now reads the shelf with p4 describe -S. The old side is the revision each file was shelved against. The new side is the shelved file, <depotFile>@=<CL>, which isn't in the workspace, so bp_export.py stages it the way it already staged the old revision. --shelved asks for this outright. A -c changelist with nothing opened gets it unasked. SKILL.md's step 1 gains the matching capture, p4 describe -S -du5 <CL>.

No more "(unnamed)" files. p4 describe -du names a file only in its ==== //depot/path#rev (type) ==== line, with no --- and +++ lines after it. diffview.py read that header in p4 diff's shape alone, so a text file from a shelf, a .ini in the report, came out unnamed. Both shapes are read now, and a binary type marks the file binary.

Added and removed items show their values. An added node lists the pin values it was given, an added variable its default, an added component or other subobject its properties (eight, then a count), and a pin added to an existing node its value. Removed ones show what they carried. Before this only a changed value was printed.

SKILL.md says not to text-diff the T3D exports. The session did, and got megabytes of serialized path noise. --blueprints is the reader. The file's gate (i) cap goes from 5.75KB to 6.0KB for these lines.

Tested against a stand-in, not a server. This box has no Perforce. A new self-test, smartdiff-prepare-selftest.py in oracle stage (k), plants a fake p4 and checks which revisions bp_prepare.py asks for. The staged load of a shelved revision in the editor isn't exercised here. The turret demo is re-rendered for gate (aa). The videos aren't, as in v4.168.0.
