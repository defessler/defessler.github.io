The goal, in one paragraph

Ship a portable policy, not an engine, that makes AI coding work cost what it should. The strong model plans and judges, where it compounds most. Cheaper models handle bounded, well-specified implementation that an automated check can grade. An independent verifier checks the result before it counts as done. Escalation to a stronger model happens only on demonstrated failure. A human gates every plan. Every claim traces to evidence. Success means equal-or-better delivered quality than a strong model used inline, at materially lower cost, on both supported harnesses (Claude Code, Copilot CLI), without overselling what's verified. The primary domain is C++ game development. The policy itself is language-agnostic.

Two dials, not one

Cheaper models handle implementation only within a scope. Anthropic's published default runs the other way: start with the most intelligent model and use effort level to dial in cost, since "Cost-per-task is often lower for more intelligent models, especially at lower effort levels, even if the price-per-token is higher" (Claude models explained). Going down the ladder is the second move. The same page warns that "Starting with a smaller model can also make it harder to distinguish between model failures and setup failures." The guard is running the same brief, oracle, and setup at more than one tier, where a setup fault shows up in every arm. It's only as strong as the arm count.

Tier answers "it didn't know enough". Effort answers "it didn't try hard enough." smartplan's routing.md sets effort next to the tier at plan time and raises it first when a run didn't try hard enough. The Claude Code implementer pins medium, since T44 measured it at high's scores for 38 to 59% less. The verifier pins high. Cheap seats pin low where the model has the dial.

Effort isn't yet as strong a lever as the vendor framing suggests. On Sonnet 5 via Copilot, max effort cost 1.92× for no measured quality gain (one task, k=2). Switching effort mid-session breaks the prompt cache on most models and costs ~2.4× on the next turn. Fable 5.1 (Claude Code v2.1.260+) and Opus 5.5 keep the cache on an API key or a subscription. Haiku 4.5 has no effort dial. On Copilot CLI, effort is session-wide unless a seat pins it with the reasoningEffort frontmatter field (documented, untested here), as the Cheap implementer and scout do.

The cost ceiling, shipped and awaiting its measurement

Since 2026-09-21 a third constraint ships: no initial seat pick prices above the incumbent, meaning the session seat or the seat handing the leaf down (routing.md § The cost ceiling). A pick climbs above the seat only through the ask-first seat ceiling, fail-twice escalation, the planner seat, or the verifier floor. scripts/seat-map.py checks the ceiling, with a warn-only hook note whenever $SMARTPLAN_SEAT is exported (off by default). t41-cost-ceiling-validation-prereg.md pre-registers the open measurement: paired arms that validate a cheaper pick under the ceiling at equal quality.

Shorthand used below

  • leaf - One small independent unit of work. A wave fans out into leaves, each with its own model and check.
  • fan-out - Splitting a task across parallel leaves instead of one pass.
  • seat - The role a model class fills: planner, implementer, verifier.
  • regime - A task's shape (size, whether it fits one context, how failure-prone), which decides routing.
  • oracle - A hidden automated check grading whether the code works, not how it looks.
  • k=N / n=N - How many times a test was repeated.
  • cr - AI credits, the unit Copilot meters.
  • warm / cold - Whether an earlier call already primed the shared context.
  • bounce - A run that failed and needed rework before it passed.
  • break-even - Where the tiered flow's premium on easy work is repaid by the failures it catches.

The goals, measured

# Goal Status
1 Cheaper per correct change Met only for execution and repair from a precise spec. Not met for tasks that fit one strong model's context.
2 Quality never sacrificed silently Met for scriptable mechanical work and convention-standard judgment. Novel ambiguity is open.
3 Verification that actually catches things Met and economical.
4 Portable across harnesses Met, asymmetrically.
5 Honesty as a feature Met, with one caught lapse.
6 The primary domain works Partial, advancing.

1. Cheaper per correct change

Success looks like the tiered flow beating inline strong-model usage on cost per correct change.

  • Where it wins. In T9, a pre-registered A/B at k=3, tiered won 3/3 runs at 39-55% of inline cost, with inline failing outright on 1 of the 3.
  • Where it loses. Forced fan-out on one-context work lost every time at equal oracle quality. T14 (one leaf) ran at 148% of inline in raw tokens. On a pre-registered price-weighted metric, T19 (5 leaves, k=2, 11/11 quality) ran at 234%/289% of inline Opus, T20 (12 Haiku leaves, k=1) at 180%, and T21 (5 big Sonnet leaves, k=1) at 163%. One strong context is more token-efficient than N cold cheaper ones at every leaf count, size, and tier tested. Credit-billed forced fan-out loses too, at 4.0-4.2× (tiny) to 2.3× (complex) on Copilot credits (T22/T23/T24, mechanism references rather than product costs).
  • As shipped. smartplan routes one-context work inline and pays a load tax that shrinks as the task grows: 1.52× (T25), 1.20× (T25b), 1.05× on a real UE5 task (T28), and ~1.0× in T30, where both with-skill arms ran under the no-skill baseline (0.88×/0.86×, 6/6 parity, n=2 vs n=1). T28's Claude Code A/B left its cost ratio unresolved (confounded, k=1).
  • How to read it. "Cheaper per correct change across a workload with a failure tail." Break-even is ≈1 failure-prone task in 20 at the old +4.62 cr tax (T25) and ≈1 in 40 at +2.06 cr (T25b), against a ~90 cr T9-class blind repair. That's derived, not measured. T9's repairs ran 75-167 cr.

2. Quality never sacrificed silently

Success looks like cheap tiers landing the same quality behind verification.

  • In T8, max-savings mode matched balanced mode on a 50-case hidden oracle at 54% of the cost. Its wide-wave probe bounced 1 of 11 dispatches (~9%), well under routing.md's 20-30% bounce-rate threshold.
  • T9 showed identical first-shot quality across arms. T28 showed 12/12 rubric parity across all five arms on real Epic code.
  • Met for scriptable mechanical work (T8) and for convention-standard judgment (T13: 23/23 hidden edges, zero delta, 32% cost). Novel-ambiguity judgment is still open.

3. Verification that actually catches things

Success looks like independent checks catching what executors and self-review miss, affordably.

  • Verification caught 4/4 seeded defects (T1/T2) and named a falsified DONE claim (T11).
  • The C++ UB (undefined behavior) layer caught a real latent bug in code that compiles clean (T12).
  • Verify first cost 55% of wave cost (T2). Script and batch modes cut that by 68%, and a failed check was shown not to spread to the rest (T10/T11).
  • Known limit: 2/2 unhinted model verifiers missed a shared blind-spot defect that the functional oracle caught (T9). Scripts and checks with different blind spots aren't optional.

4. Portable across harnesses

Success looks like the same seats and working levers on Claude Code and Copilot CLI.

  • Both harnesses were live-validated end-to-end, with tool-locked agent seats for each (.github/agents/, .claude/agents/). Copilot's levers are native and observable. Copilot CLI reads the project .claude/skills tree natively. T28 ran the same real UE5 task on both harnesses with exact routing compliance.
  • Claude Code routing is validated. Whether a routed tier bills as routed is contested upstream (#43869) and can't be confirmed from inside the harness.
  • On Copilot, read plan-gating as an expectation to confirm per account, not a fact. In T30, claude-opus-5 and claude-opus-4.8 served without a plan gate on an account that had refused 4.8 two weeks earlier.
  • Copilot's sandbox can't read a junction that points outside the project root (T28). install-project.ps1 installs need --add-dir.

5. Honesty as a feature

Success looks like no claim outliving its evidence, and failures reported as found.

  • The VERIFIED.md claim ledger keeps dated sources and is CI-gated. Deviations get pre-registered and declared, including T9's own instrument bugs. Null results get published, like T4's escalation that never fired. Unmeasured claims are labeled.
  • The discipline held even when it made the program's own tests look worse. It isn't automatic. CI gates cover VERIFIED.md rows, not narrative prose, where a stale claim that Opus is plan-gated on Copilot Pro survived eleven days after T30 falsified it.

6. The primary domain works

Success looks like C++ gamedev leaves flowing through with the correctness layer biting.

  • T12, the first live C++ leaf, produced a blocking UB finding with a concrete fix on code that passes desk-checks.
  • T28, a real Lyra task on UE 5.8, gave the first compile-gated arms in the primary domain, all 5/5 compile-clean. Both harnesses' reviews found the same finding classes with zero invented values.
  • On real Epic code, smartreview's Unreal profile discriminated correctly in T15 (15/8/20 PASS/FAIL/N-A), handled ambiguity honestly, and found a checklist gap in Lyra's component lifecycle. Vanilla was probed in T12.
  • T39's one ranking case passed 9/9 with the skill across three tiers, and without it on all three too (k=1), an honest null.
  • Still open: run acceptance, the custom-engine profile, and the never-measured recall of smartreview's BREAKING category, which tests/fixtures/cpp/unreal/ could measure.

The fan-out loss is published guidance, not a local bruise

Anthropic reserves multi-agent for "when context pollution degrades performance, when tasks can run in parallel, and when specialization improves tool selection or task focus", and says "Outside these situations, the coordination costs typically exceed the benefits" (Building multi-agent systems: When and how to use them, 2026-01-23). Those three map onto what survived our measurement: work beyond one context (context pollution), wall-clock-bound batches (parallel), and the independent verify floor (specialization). The regimes the tests killed met none of the three.

The token overhead matches too. "Multi-agent implementations typically use 3-10x more tokens than single-agent approaches" (same post). Our forced fan-out measured 4.07x (T21), 5.3x (T19), and 7.46x (T20) in tokens, inside that band. The price-weighted figures above run lower because cheaper per-token tiers buy part of that back. The architecture isn't the surprise.

Task shape is. Building a multi-agent research system (2025-06-13) names it: "most coding tasks involve fewer truly parallelizable tasks than research, and LLM agents are not yet great at coordinating and delegating to other agents in real time." Its second clause is why plan-then-dispatch with no live inter-agent chatter is the right conservative shape, not a missing feature.

The losses stand. What ships is a gate that refuses to fan out unless one of those three situations holds, plus a verify floor that makes fan-out safe when it does.

Overall: how close?

The machinery is demonstrated. The economic claim is bounded. Every mechanism in the flow (briefing, tiered dispatch, independent verification, retry, live tier escalation, batching, script checks, the mode dial) has run for real. T9's cost win came from inline failing. T33 replayed T9's question on the current stack and measured tiering at 2.78x AGAINST inline at identical quality, k=3, once inline stopped failing. So the regime that wins is rework-avoidance under demonstrated failure, not spec-plus-oracle execution as such. SKILL.md's inline default rests on these numbers. What remains:

  • Untested regimes - work beyond one context, wall-clock-bound batches, and the failure-prone regime as shipped. T26 tested that last one and came back null: none of its three organic traps fired on current models.
  • Real C++ scale - an engine-profiled (Unreal or custom) leaf set with run acceptance at scale.
  • Claude Code billing confirmation - it's structural (#43869). Documented mitigations: opusplan, Console spot-checks, and the Copilot path.
  • Sample sizes - n=1-6 per cell. The large ratios (roughly 1.5× to 4.2× across T9-T24) sit well outside documented run-to-run noise. The near-parity results (T28 1.05×, T30 0.88×) don't. They count as parity, not wins. These are case studies with variance bars, not benchmarks.

What this family is not built for

Every skill in this family assumes a real filesystem, a git checkout, and shell access. Skills on the API surface "run in a sandboxed container with no network access and no runtime package installation" (Agent Skills overview). So this family targets filesystem agents (Claude Code, Copilot CLI, and CLI-class clients), which is why Goal 4 names only those two harnesses.

smartexec carries user-invocable: false and disable-model-invocation: true to stay out of the session skill listing. Neither is in the six-field Agent Skills spec at agentskills.io/specification (unversioned, both pages read 2026-08-05). So it fails outright where that spec is enforced: claude.ai uploads, the Skills API, package_skill.py, and Cowork and cloud sessions. If your work is sensitive, Agent Skills "is not covered by ZDR arrangements", per the same overview.
