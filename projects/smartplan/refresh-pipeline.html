What "refresh everything" means here, and in what order. Five surfaces go stale on different clocks.

Surface Where it lives Goes stale because
Research research/, VERIFIED.md, model-classes.md vendors move weekly
Docs and site docs/, built into _site/ they quote the research
Skills .claude/skills/ harness behaviour changes under them
Agent seats .claude/agents/, .github/agents/ tool locks and tier names drift
M365 agents docs/m365-agents/ they encode UE and Copilot facts

The one rule

bash scripts/refresh.sh does everything a machine can do and nothing else. Then it prints the work it can't do.

It never restamps research/FRESHNESS. A restamp without a sweep buys seven clean days for rows nobody read.

Order

Research first, since docs quote it. Any other order republishes stale numbers under a new date.

1. Research sweep, if anything is stale

refresh.sh prints which per-area stamps are past seven days. Sweep those areas at primary sources only: vendor documentation and official boards, never an aggregator.

What works is a fan-out with a refute-minded verifier on every claimed change, since an agent's research finding is a lead, not a citation. Two failure modes we've hit:

  • A verifier reading a thinner source than the claim will "correct" a true statement into a false one. Give the refuter the same or better sources.
  • NEW findings on an unfamiliar surface are the highest-risk kind. With no repo baseline to contradict them, only a verifier catches a confident invention. Route NEW to a refuter, not just CHANGED.

Report unchanged findings too. Then restamp only the areas you actually swept. The rest go amber, which keeps the gap visible.

2. Apply findings

Registry first (model-classes.md), then VERIFIED.md rows, then the docs pages that quote them. Gate (m) fails when a subject on its curated list is priced two ways across the docs pages (it prints its coverage on every run). Land a price correction everywhere in one change.

Every claim row needs four cells, a known verdict, a non-blank source, and a unique ``. Anchored claims need a bidirectional link into the skills tree.

3. Skills and agent seats

Only if a harness changed. Watch the byte budgets, which are tight by design. A raise edits both places the budget lives, with its dated rationale in docs/v4-rule-inventory.md.

4. M365 agents

These encode Unreal facts and Copilot platform facts, which drift independently. refresh.sh checks only the character budgets. Read both sets of facts:

  • Unreal: engine version, API renames, anything in the build or crash sections that a version bump invalidates.
  • Copilot: the 8,000-character instructions cap, the per-type knowledge-source caps in 00-SETUP.md (SharePoint 100, OneDrive 50, one list, 4 URLs, 5 Teams chats, 20 uploads), the response-mode list, and whether the @mention response-mode bug is still open.

5. Re-run and push

bash scripts/refresh.sh --full

Then bump the version in all three gated places if anything shipped, write the changelog entry, commit, and push.

What refresh.sh checks, in order

  1. Working tree and remote. Warns if the remote looks like the public publish target, since a public push makes a redaction slip permanent.
  2. Research freshness, per area, against the seven-day line.
  3. Due RECHECK markers, dated claims asking to be re-read today. They fire with no code change.
  4. Repo consistency gates (check.sh).
  5. Full acceptance gate (run-oracles.sh), only with --full.
  6. All three harness exports, before the site build, since build-site.py packages whatever dist/ holds into the download zips. In CI only the Pages deploy runs them, where a break shows up as a failed deploy, not a red check.
  7. Site build, including the dead-relative-link count.
  8. M365 agent field budgets, against the 8,000 and 1,000-character caps.

A trap worth knowing

A new docs page that isn't in build_manifest() builds into nothing and nobody notices. Add it to the hand-maintained manifest in scripts/build-site.py. Stage 7's dead-link count won't catch a miss, since an unbuilt page is absent, not broken.

Cadence

Weekly is the floor for research, not a target. In one fortnight a flagship shipped, six models were scheduled for deprecation, a promo price was cancelled, and two roster claims became wrong. On 2026-08-12 one model's price had moved 5× in the six days since the previous sweep.

Everything else refreshes when research does, or when a harness changes under you.
