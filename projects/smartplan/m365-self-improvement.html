1. The direct answer

No. No Microsoft 365 Copilot agent modifies its own definition on any documented surface, Agent Builder and Copilot Studio included.

Something adjacent exists. Copilot Studio's Memory component is a per-user store that the runtime writes to across sessions. It doesn't touch the agent's Instructions, Skills, Knowledge, or Tools.

Your three agents are frozen. UE5 Engineer, Studio Doc Writer, and Build & Crash Doctor are identical on every turn for everyone. The v1.8 declarative agent manifest never mentions memory or persistence. Only a person who edits and republishes can improve them.

3. The loop that actually works

The agent drafts each update. A human commits it.

Setup, once, about an hour

a. One list per agent. In the agents' SharePoint site, create UE5 Engineer Lessons, Doc Writer Corrections, and Crash Signatures. Columns: Signature, Symptom, Root cause, Fix, First seen, Times seen, Status (Candidate / Stable / Graduated / Retired), Evidence. Attach each list to its agent by its URL.

b. Reserve a managed block at the bottom of each agent's Instructions.

## Lessons (managed block, regenerated weekly, do not hand-edit)

Without a rule for removing old entries, the block grows until a republish fails.

c. Put the drafting contract above the block, about 400 characters:

When asked to draft a ledger entry, output exactly one row:
Signature | Symptom | Root cause | Fix | Confidence 1-3 | Evidence
Evidence must quote the user's actual correction from this
conversation. If you cannot cite one, say so and stop.

The last line stops the agent inventing a lesson to be helpful.

d. Add two starter prompts (a built-in Agent Builder field) to each agent: - "What did you get wrong here? Draft a ledger entry." - "Review the lessons list and propose this week's managed block."

In the moment, roughly 30 seconds

When you correct an agent, click the first starter prompt and paste its row into the list as Status = Candidate. This step decides whether any of this happens.

Friday, roughly 15 minutes, one named owner

  1. Promote anything seen twice or more to Stable, the threshold smartplan/SKILL.md uses to stop self-repair.
  2. Run the probe set (five fixed questions per agent, kept in the list) and record the answers.
  3. Click the second starter prompt to get a replacement managed block, under budget, naming what it removed.
  4. Read that diff, paste the block into Instructions, and republish.
  5. Re-run the probe set. If anything regressed, restore the previous block from a Block History list.

Can it really answer "what did I get wrong this week"?

Only through the list. The agent can't see last week's conversations, only the rows they left.

What makes it cheap enough to actually happen

  • Instructions are one string. A commit is a plain replace.
  • Skipping a week loses nothing. Candidate rows already improve answers, since the list is a knowledge source.
  • An edit to an already-indexed document is indexed immediately. A new document in a site two or more people can reach is indexed daily. Rewrite one ledger in place.

Note: new Agent Builder uploads take "up to several minutes." List-row freshness is undocumented. Copilot caches answers within a session, even across tool calls. Test in a fresh chat. For immediate effect, republish Instructions.

4. Why human-gated is arguably right here

The smartplan family gates its own changes on a human. Three of its reasons transfer to a shared studio agent.

n=1 is not a lesson. One bad afternoon isn't a pattern, which is why the threshold is two.

The damage is shared. A wrong lesson becomes everyone's default answer, including at 2am for someone who wasn't in that conversation.

The changelog is most of the value. Without a record of what changed and when, you can't trace a regression to its cause.

The gate you'd design and the gate Microsoft ships aren't the same gate. A good gate is a diff, a reviewer, a changelog, and a rollback. Agent Builder has no write path at all. You rebuild the ledger, changelog, and rollback by hand in SharePoint.

The one surface that does write autonomously is gated worse. Copilot Studio Memory is per-user, and the maker can't see it. It has no Purview audit log entries, retention policies, or labels. Admins can't restrict what goes in.

Rebuilding the three agents in Copilot Studio on the GitHub Copilot harness gets you Memory. It also brings Copilot Credits billed from the start of building, preview terms, per-user isolation, a 28-day inactivity wipe, and no Memory in Teams channels. For studio-wide learning, that's a bad trade.
