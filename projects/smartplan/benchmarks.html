Metrics tracked

# Metric What it measures
M1 Protocol compliance Dispatches whose output matched the required template/discipline exactly
M2 Seeded-defect catch rate Planted defects caught by verifiers
M3 Independent findings Real problems verifiers found that nobody seeded
M4 BLOCKED / retry / escalation correctness The fail-twice machinery behaving as written when exercised
M5 Executor cost by tier Credits (Copilot, metered) or tokens (Claude Code, harness-reported) per dispatch
M6 Verify cost + verify:exec ratio The independent check's cost relative to the work it checks
M7 Verify share of wave Verification's share of a complete wave's real bill
M8 Wall time Per-dispatch latency
M9 Size vs budget Tracked files against docs/v4-rule-inventory.md § Byte budgets
M10 Mechanical gates check.sh + selftest.sh pass state
M11 Roster coverage Pinned agent seats (roles like planner, executor, or verifier) shipped per harness
M12 Flow-step live coverage Which of Plan/Gate/Dispatch/Verify/Integrate/Escalate have real (non-toy) exercises
M13 Cost-per-merged-change The north star, measurable only on real waves. No data until T5

Incident-window discipline. Record run timestamps in UTC. Before blaming a model for a mid-run death or a quality dip, check the vendor's incident history for the run's window. A run that died inside an incident is an infrastructure failure. Recording it as a model result corrupts the ledger permanently.

status.claude.com logged at least six incidents naming Opus 5 in its first fortnight, including two on 2026-08-05 that overlap for a combined 7h29m, 07:05 to 14:34 UTC. Every T32 to T36 result file landed 01:26 to 02:53 UTC on 08-06, hours clear of that window. A T-record isn't finished until it records this check.

Record frontmatter (required on every T-record)

check.sh gate (l) requires each 2026-*-T*.md record to open with a frontmatter block, which lets tooling read its spend as data instead of parsing prose:

---
test: T25b
date: 2026-07-13
spend_cr: 66.60          # total AI credits to run the test (Copilot)
---

Use exactly one spend declaration: spend_cr: (Copilot credits), spend_tok: (Claude Code tokens, the raw total across arms), or ledger: exclude plus a ledger_note: "reason" when the test has no single ledger-comparable total (multi-arm price-weighted W, ratio-only A/Bs, probe ranges, preliminary estimates). The spend report lists excluded records with their reason.
