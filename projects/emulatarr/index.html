Emulatarr

A desktop wizard that stands up a self-hosted retro game library on your NAS, over SSH.

emulatarr:~$ emulatarr --what-it-does

        

          
Six screens, start to finish:

          

            WelcomeConnectDetectConfigureRunDone
          

          
    
            
  • Connects over SSH - password or key, with the privilege escalation worked out for you. Sudo passwords are masked at fixed width before they reach the screen or the log, so the length does not leak either.
    • 
            
  • Looks before it leaps - one batched probe reports your platform, architecture, container runtime, free space, and whether the web port is already taken, before anything is written.
    • 
            
  • Writes the config - a form becomes a .env, deterministically. Values are quoted against an allow-list, because the NAS side sources that file.
    • 
            
  • Deploys the stack - RomM, MariaDB, and Valkey via Docker Compose, plus the folder layout with the right PUID/PGID and Synology ACLs.
    • 
            
  • Streams the whole install - real output, a step rail that tracks it, and a health check at the end that tells you how many services came up.
    • 
            
  • Remembers your NAS - profiles are encrypted at rest, and export as a passphrase-wrapped file if you want to move one to another machine.
    • 
            
  • Updates itself - checks GitHub Releases, verifies the download by size and sha256, and swaps itself in place on restart. Saved profiles survive.
    • 
          

          
// idempotent throughout. The network drops, people click Run twice, and neither should hurt.

        


        
emulatarr:~$ emulatarr --the-stack

        

          
   your PC                        your NAS
  +-----------+   ssh+sftp   +----------------------+
  |  wizard   |  --------->  |  RomM + MariaDB +   |
  +-----------+              |  Valkey  (compose)   |
                             +----------+-----------+
                                        |
                             smb / nfs / browser
                                        |
                  Steam Deck · phone · PC · Batocera

          
The NAS is a library server, not an emulator box. RomM catalogs and scrapes your collection and serves the files. Light systems play in the browser through EmulatorJS, which runs client-side. Heavier ones play on a real device that mounts the library over SMB or NFS.

emulatarr:~$ emulatarr --requirements

        

          
    
            
  • wizard - Windows 10 or 11 (x64). It is a portable folder, so deleting the folder uninstalls it.
    • 
            
  • nas - an x86-64 NAS running Docker or Podman, reachable over SSH. Built and tested against a Synology DS1522+ with Container Manager.
    • 
            
  • storage - size the volume around the disc systems you actually want. Cartridges are tens of GB. PS2 alone is around 15 TB.
    • 
            
  • games - bring your own. Nothing here ships or links to game files.
    • 
          

        


        
emulatarr:~$ emulatarr --by-hand

        

          
The wizard uploads exactly one folder, nas/scripts/, and runs setup.sh inside it. Copying that folder across yourself and running the script is a supported route, not a fallback. If you would rather see every command, start with
          QUICKSTART.md.

emulatarr:~$ emulatarr --legal

        

          

            Bring your own games. RomM ships no game files, and neither does this. The
            recommended route is dumping discs and cartridges you physically own, which is the defensible
            one. Downloading games you do not own is generally infringement in the US even when you own the
            original cartridge. Not legal advice.
