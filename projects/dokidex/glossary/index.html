:: THE VOCABULARY

Glossary

Every term this site uses, defined correctly and briefly. The one page to check when a word anywhere else on the site stops you.

This site uses precise words for precise reasons. Precise words are exactly the ones popular usage blurs. If a term anywhere else on the site stopped you, it’s defined here: correctly, not approximately, with a note on what it’s not wherever that’s the part people get wrong.

A

ACP (Agent Client Protocol)

An open JSON-RPC 2.0 protocol, co-maintained by Zed and JetBrains, that lets an IDE talk to a coding agent as a subprocess speaking a standard message format instead of a vendor-specific plugin API: “Zed’s LSP for coding agents.” Rider, Zed and neovim can each launch a conforming agent as a subprocess. DokiDex spoke ACP through its own agent until 2026-09-02. The CLIs it ships now integrate with editors through their own mechanisms instead.

Acceptance rate

In speculative decoding, the share of drafted tokens the target model keeps. It decides how much speed a draft buys and nothing else, because a rejected token is simply regenerated. Our Qwen3.8-27B seat measured 0.50 to 0.54 with its MTP head in August 2026, so about half of every draft survived. Full treatment.

Active parameters

The subset of a model’s total parameters that actually run the multiply-add math for a given token: the number that determines speed, not memory footprint. Not the same axis as total parameters, which determines whether the model fits in VRAM at all. A Mixture-of-Experts model can have active parameters a tenth the size of its total. Full treatment.

Agent

A system that interleaves model generation with real tool calls in a loop (reading files, running commands, calling APIs) rather than only producing text. It’s not a separate reasoning module bolted onto a chat model. The same next-token mechanism drives it, wired into a loop by code outside the model. Full treatment.

Agent loop

The repeating cycle a coding agent implements: assemble context, let the model reason and pick a tool, execute that tool, stream the result back, and repeat until the model stops calling tools. The permission gate that decides whether a mutating tool call may run sits inside this loop. Full treatment.

AGENTS.md

An open orientation-file spec (project-level build commands, conventions, and rules re-read every session) originated by OpenAI/Codex, Cursor, and Google’s Jules team, later donated to the Linux Foundation. Claude Code reads it, and so does every agent this stack drives.

AIME

The American Invitational Mathematics Examination, repurposed as an olympiad-level math benchmark. Recent years are fully saturated by frontier models, which is why evaluators rotate to the newest available contest rather than an old one: freshness resists contamination, not the benchmark’s brand name. Full treatment.

ALiBi

Attention with Linear Biases: a positional-encoding alternative that penalizes attention scores by a fixed, distance-based amount rather than rotating or adding to the embeddings, letting a model trained on short sequences extrapolate to longer ones at inference. Full treatment.

Alignment (research)

The effort to keep increasingly capable AI systems pursuing goals compatible with human interests, especially once a system exceeds the competence of the humans checking its work. Genuinely unresolved as a research problem: not “basically solved by RLHF” and not “provably impossible,” despite both claims circulating. Full treatment.

ARC-AGI

A benchmark family (versions 1 through 3) testing abstract puzzle generalization rather than memorized knowledge. ARC-AGI-1 is now considered saturated by its own creators. ARC-AGI-2 is a harder static-puzzle successor. ARC-AGI-3 replaces static puzzles with interactive game environments scored over time. “ARC-AGI” without a version number names three different tests. Full treatment.

Arena.ai / LMArena

A leaderboard built from anonymized human pairwise preference votes, aggregated into an Elo-style rating (lmarena.ai now redirects to arena.ai). It measures blind stylistic preference under real usage, not correctness: a longer, more confidently-formatted wrong answer can still win votes. Full treatment.

Attention (self-attention)

The mechanism letting every token’s representation be updated by every preceding token in the sequence, and by itself, weighted by a learned relevance score computed from Query, Key, and Value vectors. A causal mask blocks any token from attending to ones that come after it, which is what makes next-token training possible in the first place, and what makes the KV cache (below) valid, since an earlier token’s cached Key/Value can never be invalidated by a token that comes later. It’s a real, load-bearing part of the computation. But a controlled study found attention weights are frequently uncorrelated with what actually drove a prediction. So they’re not a reliable explanation of “why” a model answered the way it did. Full treatment.

Autoregressive

Describes a model that generates output by repeatedly predicting one token at a time from everything generated so far, feeding each new token back in as input for the next step. There’s no separate module planning the whole answer in advance: any appearance of long-range planning is an emergent property of training. Full treatment.

AWQ

Activation-aware Weight Quantization: a scheme that finds the small fraction of weight channels most important to output quality (by looking at activation magnitude, not weight magnitude) and protects them, instead of rounding every weight the same way. Full treatment.

A<n>B notation

The active-parameter suffix in a Mixture-of-Experts model name: 235B-A22B means 235 billion total (stored) parameters and roughly 22 billion active (computed) per token. VRAM sizing uses the first number. Speed estimates use the second. Full treatment.

B

B (size suffix)

The B in 20B, 27B or 35B is billions of parameters. For a dense model it’s a fair guide to both quality and speed. For a Mixture-of-Experts model it’s the total, which sets memory but not speed (see A<n>B notation). A rough memory rule at 4-bit: a little over half a gigabyte per billion, so a 27B model is about 16 to 17 GB before the KV cache. Full treatment.

Backpropagation

The algorithm that computes, for every weight in a network, the direction it should move to reduce the gap between the model’s output and the desired output (the loss). It computes the direction. Gradient descent takes the step. The two are often mentioned together but aren’t the same operation. Full treatment.

Bake-off

DokiDex’s own term for a dated, scored comparison we run between candidate models on the same hardware. A candidate only gets promoted to a default serving tier once it clears both a golden suite score and a native tool-call check. Full treatment.

Base model

A model after pretraining only, with no instruction-tuning stage applied. Given an instruction, a base model is just as likely to continue it with more instructions as to follow it: instruction-following has to be trained in afterward. It isn’t a pretraining property. Full treatment.

Benchmark

A score produced by running a model against a fixed set of test questions under a fixed scoring rule. That score isn’t a fact about the model alone. It’s a fact about a model, a prompt template, a tool-access setting, a reasoning-effort tier, and an attempt-counting rule, all together. Full treatment.

BFCL (Berkeley Function-Calling Leaderboard)

A benchmark scoring the accuracy of function/tool-call generation against ground truth, checked by comparing abstract syntax trees rather than exact text. Its official leaderboard is JavaScript-rendered. Scraped copies have been caught showing years-stale data under a fresh “last updated” timestamp. Full treatment.

BF16 / FP16

16-bit floating-point formats, roughly 2 bytes per weight: the “full precision” baseline before 8-bit and 4-bit quantization became standard. BF16 trades some mantissa precision for a wider exponent range than FP16, making it more resistant to overflow during training. Full treatment.

Bits per weight (bpw)

The average number of bits a quantization format spends storing each parameter: the figure that multiplies directly into a model’s VRAM footprint. It’s a property of the quantization scheme, not of the model itself, and stays nearly constant across model sizes for a given format. Full treatment.

Box

DokiDex’s word for a second GPU machine that serves its card to the rest of the LAN, behind a key and with billed rows stripped. Another machine’s router or eval run can then send work to it by id. In October 2026 that’s how a laptop-class RTX 3080 hands big jobs to an RTX 5090 across the room.

BPE (byte-pair encoding)

The algorithm behind most modern tokenizers: starting from individual bytes or characters, it repeatedly merges the most frequent adjacent pair until it reaches a target vocabulary size. It operates on raw bytes, not human-legible characters, which is why a token boundary can land mid-character in non-Latin scripts. Full treatment.

C

Chain-of-thought (CoT)

Prompting or training a model to generate intermediate reasoning steps before its final answer, which measurably helps on arithmetic, symbolic, and multi-step tasks. It’s not necessarily a faithful transcript of the model’s real internal computation: controlled studies have found models sometimes use a hint without ever mentioning it in their visible reasoning trace. Full treatment.

Chat template

The exact string format (role markers, special tokens, whitespace) a specific model’s training pipeline used to represent a conversation. Using a different, “reasonable-looking” format instead of a model’s actual template is a common, silent way to degrade a self-hosted model’s output: it still produces fluent text, just measurably worse. Full treatment.

Checkpoint

In an agent, a saved snapshot that lets you undo: Claude Code’s /rewind restores file content and conversation from a prior turn. This is a different sense from a training checkpoint (an intermediate saved state of a model’s weights during training). Context determines which one applies.

Chinchilla / Chinchilla-optimal

The finding that, for a fixed training-compute budget, model size and training-token count should scale together rather than favoring size alone. A properly token-matched smaller model outperformed a far larger, undertrained one at equal compute. Most current models are deliberately trained well past this ratio anyway, because it optimizes training cost only, not the cost of serving the model afterward. Full treatment.

CLAUDE.md

An orientation file used by Claude Code for project-level instructions re-read every session. In this repo it is a single line, @AGENTS.md, so both files stay in step.

Compaction

Summarizing older conversation history to free context-window space, rather than truncating it outright. What a compaction summary keeps (architectural decisions, open questions) matters more than how aggressively it compresses. Naive truncation reliably reintroduces bugs an agent already fixed once. Full treatment.

Context cap

A blunter alternative to compaction: if a turn’s prompt exceeds a configured token limit, the next turn drops the single oldest whole conversation turn outright, with no attempt to preserve its meaning. Full treatment.

Context editing

An Anthropic feature that strips stale tool calls and results out of a long conversation as the context limit approaches, paired with a memory tool that persists facts to an external store across sessions. Not the same mechanism as compaction, which summarizes rather than strips. Full treatment.

Context rot

The empirically observed, non-uniform degradation of model performance as context length grows, well before the model’s stated limit, and worse for semantically-similar (not just lexically exact) information than the classic needle-in-a-haystack test suggests. Not the same claim as “the context window is too small”: it happens inside windows that technically fit the content. Full treatment.

Context window

The maximum number of tokens (input and output combined, in most APIs) a model can attend to in a single request. It is not memory: nothing persists between separate API calls unless an application explicitly re-sends or stores the text itself. Full treatment.

Contamination

The risk that a benchmark’s test questions appeared, verbatim or near-verbatim, in a model’s training data, inflating scores on anything built from public sources like GitHub issues or old contest archives. It’s the primary reason several older benchmarks are considered “dead” today. Full treatment.

Cross-family review

Having a model from a different vendor family check another model’s work. Models trained the same way tend to share blind spots, so a Qwen reviewing Qwen misses what a Qwen wrote wrong more often than a Gemini or a gpt-oss would. It still ranks below an executable check: a compiler or a test suite doesn’t share anyone’s blind spots.

D

Decode

The second phase of answering: writing the reply one token at a time, each step reading the whole KV cache. Speed here is limited by memory bandwidth, and it’s the number most people quote as “tokens per second”. On a deep agent session it’s most of the wall clock. Our seat measured decode at 96.9% and prefill at 3.1% past 100k tokens of context, in August 2026. Compare Prefill.

Dense model

A model that runs every parameter on every token, as opposed to a Mixture-of-Experts model, which routes each token through only a subset of its parameters. Classic GPT, Llama, and Mistral-7B-style architectures are dense. Full treatment.

Distillation

Training a smaller “student” model to reproduce a larger “teacher” model’s full output probability distribution, not just its single best answer. What transfers is the graded shape of the teacher’s near-misses, not an explanation of why the teacher answered that way. In practice, though, a shipped Distill suffix usually marks something narrower: supervised fine-tuning on teacher-generated output text, not logit-level distribution matching. DeepSeek-R1-Distill-Qwen-7B, the site’s own worked example, was SFT’d on ~800K R1-generated reasoning traces, sequence-level imitation rather than distribution matching.

Community uploads stretch the word further. A name like Qwen3.6-35B-A3B-Claude-Opus-Reasoning-Distilled usually means a LoRA fine-tune on a few thousand answers collected from a closed model, and some model cards admit the reasoning traces were rebuilt by another model rather than copied. Treat the teacher’s name as a claim about the training data, not about the result. Full treatment.

DokiGen Studio

DokiDex’s former generative front end, where image, video and audio generation lived. Removed on 2026-09-02 with the rest of the non-coding stack. The term survives here because it appears throughout the project history and the older measurement records.

DPO (Direct Preference Optimization)

A post-training method that reformulates preference-pair data as a classification-style loss, solving the same objective RLHF solves in one supervised-style stage instead of training a separate reward model and running an RL sampling loop. It removes the separately trained reward model, not the underlying concept of a reward. That concept just becomes implicit in the policy itself. Full treatment.

Draft model

The small, fast model in speculative decoding that proposes several tokens ahead for a larger target model to verify in one parallel pass. A weak draft model only costs speed, never correctness: a bad guess is simply rejected and regenerated by the target model. Full treatment.

E

Effort

A per-request dial (Low/Medium/High/XHigh/Max, in DokiDex’s UI) controlling how much reasoning depth and tool-call budget a model gets, never which model runs. The same underlying model can score meaningfully differently on a benchmark depending only on this setting.

Embedding

A vector (a list of numbers, hundreds to thousands of entries long) assigned to a piece of text such that distance and direction in that space reflect learned relationships between meanings. It doesn’t encode a dictionary definition. A modern transformer’s embeddings also shift with surrounding context rather than sitting at one fixed coordinate per word. Full treatment.

Embed (marker)

A model-name marker meaning the model outputs a fixed-size similarity vector rather than text: a retrieval component, not a generator. DokiDex’s embedding server (:8090) is this kind of model. Full treatment.

EXL2 / EXL3

Quantization formats from the ExLlamaV2/V3 project. EXL2 is a mixed-bitrate format shipped as plain safetensors. EXL3 is a newer lattice-codebook format spanning very low bit-widths, closer in spirit to I-quants than to GPTQ’s linear scaling. Full treatment.

Expert offload

Keeping a Mixture-of-Experts model’s expert weights in system RAM while attention and the shared layers stay on the GPU (--n-cpu-moe N in llama.cpp, which offloads the experts of the first N layers). Since only a few experts run per token, the CPU side stays tolerable. It’s how a 35B MoE runs on a 10 GB card: our RTX 3080 seat holds 8.1 GB of VRAM this way and decodes at about 28 tokens a second, as of October 2026. It doesn’t help a dense model, where every weight runs every token.

F

Feed-forward layer

The sublayer inside a transformer block that transforms each token’s representation on its own, with no mixing across token positions. Attention does the cross-token mixing. The feed-forward layer does the per-token transformation. Most of a dense transformer’s raw parameter count sits here, which is exactly the sublayer Mixture-of-Experts replaces with parallel experts. Full treatment.

Fine-tuning

Further training an already-pretrained model on a smaller, curated dataset to change its behavior, format, or style. It reliably teaches behavior. It’s comparatively unreliable at injecting new, precise facts. For that, retrieval (RAG) is the more dependable lever. Full treatment.

FIM (fill-in-the-middle)

Training a model on <prefix><suffix> → <middle> examples alongside ordinary next-token prediction, so it can complete code from both directions at once: the shape IDE autocomplete actually needs. A chat-only model can fake this via prompting, with materially worse completion quality. Full treatment.

FlashAttention

An exact (not approximate) algorithm for computing self-attention that reorders the computation to minimize data movement between a GPU’s slow main memory and its fast on-chip memory, rather than changing what gets computed. It targets the same underlying bottleneck as GQA and MLA: memory bandwidth, not raw arithmetic. Full treatment.

Flash (tier word)

Google’s name for its lower-latency, lower-cost tier below “Pro”, still a genuinely distinct model, not a rate-limited version of the flagship. The word carries no meaning outside Google’s own lineup. Full treatment.

FP8

An 8-bit floating-point format, roughly 1 byte per weight, that some frontier models now use for their entire pretraining run rather than only for post-training quantization. Full treatment.

G

GGUF

llama.cpp’s model container format: the file type most local, quantized models ship in, spanning legacy, K-quant, and I-quant families at bit-widths from roughly 1 to 8 bits per weight. Full treatment.

Golden suite

DokiDex’s own fixed set of hand-checked tasks that gates a candidate model’s promotion to a default serving tier. We don’t promote a model on a high score alone. It also has to pass the native tool-call gate cleanly. Full treatment.

GPQA Diamond

A PhD-vetted, multiple-choice benchmark across biology, physics, and chemistry, built specifically to resist a skilled non-expert solving it with a web search. Near-saturated at the frontier as of mid-2026, with leading models scoring above the human expert baseline. Full treatment.

GPTQ

A one-shot, Hessian-informed, layer-wise quantization method that minimizes output error: the long-standing GPU-side INT4 quantization standard, predating AWQ. Full treatment.

GPU mode

DokiDex’s own term for which profile currently owns the single GPU: agent (the seat plus the CPU-only embedder) or coexist (the same, plus a reduced-context FIM autocomplete sidecar). A third mode, media, held the image and video models and was mutually exclusive with both. It was removed on 2026-09-02 along with the stack it served.

Gradient descent

The optimization step that nudges each weight a small amount in the direction backpropagation computes will reduce the loss, then repeats on the next batch of examples, millions of times. It computes the step. Backpropagation computes the direction. Full treatment.

GQA (Grouped-Query Attention)

A KV-cache-shrinking scheme where several query heads share one key/value head, rather than every head keeping its own (the middle ground between full multi-head attention and Multi-Query Attention, which takes the sharing to its extreme). It shrinks the KV cache’s memory footprint, not the attention computation’s arithmetic cost. Full treatment.

H

Hallucination

Confident generation of false or unsupported content. Current theoretical work argues it’s a predictable consequence of how models are evaluated: most benchmarks score a confident wrong answer the same as an honest “I don’t know” (both zero credit), which structurally rewards guessing over calibrated uncertainty. It is not simply a bug that more training data or a bigger model straightforwardly fixes. Full treatment.

Head / multi-head attention

Running several independent attention computations in parallel within one layer, each with its own learned Query/Key/Value projections, then combining their outputs. Some heads show identifiable specialization on inspection. But this is an emergent, not a designed, property. Full treatment.

HLE (Humanity’s Last Exam)

An expert-written benchmark across math, humanities, and science, built as a successor once MMLU-class tests saturated. Reported scores for the same models vary enormously across sources depending on dataset snapshot date and whether tool use was permitted: never trust an HLE number without its source, date, and tool-use condition. Full treatment.

HMMT

The Harvard-MIT Math Tournament: the benchmark evaluators rotate to once a given year’s AIME saturates, because a brand-new contest has had no time to leak into training data. Full treatment.

HumanEval

An early Python coding benchmark, now considered retired: near-saturated, contaminated by years of public exposure, and narrow in construct (short, interview-style, purely algorithmic problems that say nothing about repo-scale work). Current frontier model cards typically no longer report a score on it. Full treatment.

Hybrid model

A model that mixes ordinary attention layers with linear-time recurrent layers, so most layers carry a small fixed-size state instead of a KV cache that grows with every token. Qwen3.8 is built this way. It makes long windows cheaper. The catch is that the engine has to support the layer type properly. Qwen3.8 on llama.cpp builds older than about b10450 produced corrupted output at full speed, with no error at all.

I

Inference

Running a model’s already-fixed weights on a specific input to produce an output: the constant, comparatively cheap counterpart to training. Nothing about a normal inference call changes the model’s weights. Full treatment.

Inference-optimal / overtrained scaling

Deliberately training a model on far more tokens than the Chinchilla-optimal ratio would prescribe, trading extra one-time training compute for a smaller, cheaper-to-serve model: rational once you account for a model being queried far more times than it’s trained. Full treatment.

Instruct

A model-name suffix (also -It, Chat) meaning the model went through supervised fine-tuning (usually plus RLHF or DPO) for instruction-following, as opposed to a raw Base checkpoint. Full treatment.

INT4 / INT8

Fixed-point integer quantization formats: the substrate underneath GPTQ, AWQ, and bitsandbytes-style quantization. INT4 is roughly 0.5 bytes per weight before block-scale overhead. Full treatment.

Interpretability (mechanistic)

Research trying to reverse-engineer what a trained network’s internal components actually compute. Most individual neurons respond to a tangled mix of unrelated concepts rather than one clean idea, which is why techniques like sparse autoencoders exist, and why even the field’s best current tools give only a partial, not a complete, account of a model’s behavior. Full treatment.

I-quant

A GGUF quantization family (IQ1_S through IQ4_XS) using non-uniform, codebook-based encoding rather than simple per-block scaling: built for aggressive 1-to-3-bit compression, where it holds quality better than K-quants at the cost of more dequantization compute. Full treatment.

J

Jamba

AI21’s hybrid architecture (literally “Joint Attention and Mamba”) interleaving standard attention blocks with linear-time Mamba (State Space Model) blocks plus Mixture-of-Experts, trading some quality for much cheaper long-context inference. Full treatment.

K

K-quant

A GGUF quantization family (Q2_K through Q6_K) using 256-value super-blocks with per-sub-block scaling. The _S/_M/_L suffix marks which tensors get selectively bumped to higher precision within that bit family, not an independent size class. Full treatment.

Knowledge cutoff

The date after which a model has no reliable knowledge of events: a separate figure from the training-data cutoff (the date training data was gathered up to), which is typically later. A model’s release date is a third, different figure again. None of the three should be assumed equal. Full treatment.

KV cache

Stored Key and Value vectors from every previous token, at every layer, kept so that generating each new token only requires computing a fresh Query rather than recomputing everything before it, turning what would be quadratic work into linear, incremental work per step. It is not the model’s memory of a conversation: it’s discarded the moment the request ends. It grows continuously with every token generated. Full treatment.

KV cache quantization

Storing the KV cache in fewer bits (--cache-type-k q4_0 and --cache-type-v q4_0 in llama.cpp), the same idea as weight quantization applied to the context. It buys room, not speed. Our seat fit a 256k window in less memory than a 104k window had needed at f16. Per cached token, attention was no faster: f16 measured 37.0 ns, q8_0 57.8 and q4_0 53.3, in August 2026.

L

LiveCodeBench

A competitive-programming benchmark continuously scraped from LeetCode, AtCoder, and Codeforces, with each problem tagged by release date so evaluators can score only on problems published after a model’s training cutoff: a contamination control built into the dataset itself. Full treatment.

llama.cpp

The general-purpose local inference engine behind the GGUF ecosystem: runs on NVIDIA, Apple Metal, AMD, Intel, or CPU alone, and is the default choice for a single desktop GPU because it covers every quant format natively. Full treatment.

llama-swap

A small Go binary that exposes one OpenAI-compatible endpoint and swaps the underlying llama-server process to match whichever model a request asks for: the mechanism that lets one GPU serve many different model tiers without holding them all in memory at once. DokiDex’s entire serving stack runs behind one. Full treatment.

LoRA (Low-Rank Adaptation)

A fine-tuning method that freezes a model’s pretrained weights entirely and trains a much smaller pair of low-rank matrices added on top of specific weight layers. Because the learned update can be mathematically merged back into the base weights, a LoRA fine-tune adds zero inference latency once training is done. Full treatment.

Long context (advertised vs. effective)

The gap between a model’s advertised maximum context length and the length at which it actually retains reliable recall. Independent research consistently finds effective length sits well below the advertised figure: a live, measured phenomenon, not a rare edge case. Full treatment.

M

Mamba / State Space Model (SSM)

An architecture family using a linear-time recurrent scan instead of (or alongside) attention, trading some quality for much cheaper long-context inference (critically, no KV cache that grows with sequence length). Hybrid designs like Jamba interleave Mamba blocks with a minority of attention layers. Full treatment.

MatFormer

Google’s technique for training one large model that contains several smaller, independently-usable submodels nested inside it, yielding multiple deployable sizes from one training run with no separate distillation pass. The resulting “effective” parameter count (E<n>B) isn’t the same axis as an ordinary <n>B size figure. Full treatment.

MCP (Model Context Protocol)

An open protocol, originated by Anthropic, that lets a model connect to external tools and data sources through a standard client/server interface rather than a bespoke integration per tool. DokiDex serves two of its own over stdio: a persistent project memory and code_search, semantic retrieval over the repo. Both are wired in harness/crush.json.

mini / nano (tier words)

OpenAI’s historical naming for progressively smaller, cheaper siblings within a generation, exact size undisclosed. As of July 2026 OpenAI’s frontier lineup has moved to codenames (Sol/Terra/Luna) instead, so treat mini/nano as legacy wording still used elsewhere, not a stable, portable size signal. Full treatment.

MLA (Multi-head Latent Attention)

A KV-cache-shrinking scheme that compresses Keys and Values into one small, shared low-rank latent vector per token instead of caching them per head: reported to exceed GQA’s quality at an even smaller cache footprint, not merely a lesser trade-off. Used by the DeepSeek-V3/R1 family. Full treatment.

MMLU / MMLU-Pro

MMLU is a broad-knowledge, multiple-choice benchmark spanning 57 subjects, now considered saturated with frontier models exceeding 90%. MMLU-Pro is its harder successor (more options per question, trivial questions removed, skewed toward reasoning-heavy items) and still shows meaningful score spread across models. Full treatment.

MMMU

A multimodal, college-level benchmark spanning charts, diagrams, and chemical structures, requiring genuine joint image-and-text reasoning rather than OCR-plus-guessing. “MMMU-Pro” is a distinct, harder variant, not directly comparable to plain MMMU scores. Full treatment.

mmproj (vision projector)

The small extra GGUF file that lets a text model read images, by turning an image into tokens the model understands. llama.cpp loads it with --mmproj. Without it, a request carrying an image fails outright, even if the model was trained for vision. Qwen3.8-27B’s is about 600 MB at Q8_0.

MoE (Mixture of Experts)

An architecture where a layer’s single feed-forward block is replaced by many smaller parallel “expert” blocks plus a learned router that activates only a small subset per token. It saves compute, not memory: every expert must still sit resident in VRAM, because routing is decided per token and a real request sweeps across most or all experts over time. It’s not a document-level or topic-level classifier. Routing is a per-token, per-layer decision, and there’s no evidence experts map onto human categories like “the math expert.” Full treatment.

MQA (Multi-Query Attention)

The most aggressive KV-cache-sharing scheme: every query head shares a single key/value head, maximizing cache savings at the largest quality risk. GQA is the commonly-used middle ground between MQA and full multi-head attention. Full treatment.

MTP (Multi-token prediction)

Training a model to predict several future tokens from one hidden state instead of just the next one, densifying the training signal and enabling speculative decoding. Models that keep the extra head ship it as a built-in draft model, and some uploads now put MTP in the name (Qwen3.6-35B-A3B-MTP). llama.cpp runs it with --spec-type draft-mtp. Like any draft, it changes speed and never the output. It’s worth it on a GPU with fast memory: our Qwen3.8-27B seat went from 44.1 to 54.7 tokens a second on an RTX 5090. With the experts offloaded to system RAM on an RTX 3080, it fell to 2.4, so it’s off there. Full treatment.

N

Next-token prediction

The core generative mechanism of an autoregressive language model: compute a probability distribution over the entire vocabulary for what comes next, sample one token, append it, and repeat. There’s no separate module planning a whole sentence in advance. Full treatment.

NF4

“4-bit NormalFloat”: a quantization format that places its representable values for equal probability mass under a Gaussian weight-distribution assumption, built specifically for QLoRA fine-tuning (though usable for plain inference too). Full treatment.

NoLiMa

A long-context benchmark that deliberately chooses “needle” facts sharing almost no literal wording with the test question, forcing genuine semantic inference instead of simple string matching: a harder, more honest test than classic needle-in-a-haystack. Full treatment.

NVFP4 / MXFP4

Two 4-bit floating-point quantization formats. MXFP4 is an open OCP-spec format using a shared block-32 scale. NVFP4 is NVIDIA-specific, with a finer block-16 scale reported to edge out MXFP4 in accuracy at the same bitrate. Full treatment.

O

Open data

Release of a model’s actual training corpus (or a detailed description of its provenance), not just the trained weights. Almost no model marketed as “open source” clears this bar: releasing weights alone says nothing about what the model was trained on. Full treatment.

Open source (AI)

Under the Open Source Initiative’s stricter definition, a model qualifies only if the training data’s provenance, the full training/inference code, and the weights are all released with no permission needed to use, study, modify, or share. Almost every model casually called “open source” is, more precisely, only open-weight. Full treatment.

Open weight

A model whose trained parameters are downloadable and runnable with no further permission required. That’s a real and valuable promise, but a much smaller one than “open source” implies for regular software, since it says nothing about training data or training code. License terms still vary hugely even among open-weight models, from permissive (Apache-2.0, MIT) to research-only or revenue-capped. Full treatment.

Orientation file

A project-level instructions file (AGENTS.md or CLAUDE.md) that a coding agent re-reads every session (build commands, conventions, security rules). An agent checks for them in a fixed precedence order and uses whichever it finds first.

OSS (in a model name)

Short for open source, used loosely. gpt-oss-20b and gpt-oss-120b are OpenAI’s open-weight models, Apache 2.0 licensed and runnable locally, unlike the models behind ChatGPT. By the stricter definition above they’re open weight rather than open source. Both are Mixture-of-Experts: the 20B runs about 3.6B parameters per token, which is why it’s the fastest model on our RTX 3080.

P

Parameters

The learned numeric values (see Weights) that a trained model uses to turn an input into an output. The count in a model’s name (7B, 235B) refers to these. For a dense model, that count is also how many run per token. For a Mixture-of-Experts model it’s not: the number in a name is almost always total parameters, the figure that determines VRAM footprint, a different axis from active parameters (see A<n>B notation), the much smaller subset that actually computes for a given token and determines speed. Full treatment.

PEFT (Parameter-Efficient Fine-Tuning)

An umbrella term for fine-tuning methods (LoRA foremost among them) that train only a small added set of parameters while leaving the pretrained weights frozen, instead of updating every weight in the model. Full treatment.

Permission mode

The gate deciding whether a mutating tool call (a file write, an edit, a shell command) is allowed to run without asking first. We name four: ask (default, every mutation stops and asks), auto (mutations auto-approve), plan (read-only, mutating tools are filtered out of the model’s toolset entirely), and bypass (everything auto-approves, no exceptions, reachable only by a deliberate act, never a stray keypress). Full treatment.

Perplexity

A measure of how well a model predicts a held-out piece of text (lower is better). It is a blunt instrument for judging quantization quality specifically: a quant can look fine on a perplexity chart and still measurably regress on coding, tool-use, or multi-step reasoning tasks. Full treatment.

Plan mode / Act mode

The now near-universal agent pattern of proposing changes read-only in one phase, then executing them only after an explicit switch to a granted phase, implemented across Claude Code and Codex. The implementations worth trusting filter the model’s tool schema down to read-only calls rather than just asking it nicely not to write. Full treatment.

PPO (Proximal Policy Optimization)

The original RLHF algorithm: optimize a policy against a separately trained reward model, using a clipped objective that permits several safe update steps per batch. It inherits the generic risk of any proxy-optimization setup: a policy can find outputs that score well on the reward model without being genuinely better. Full treatment.

Pretraining

The first, most expensive training stage: next-token prediction over a massive raw text/code corpus, building broad world knowledge and language ability from scratch. It sets the great majority of a model’s factual knowledge: later stages (SFT, RLHF) reshape behavior and style far more than they add facts. Full treatment.

Preview / -exp suffix

A model-name marker signaling an unstable, possibly short-lived release with looser rate limits and faster deprecation than a GA (generally available) release under the same base name. Don’t hardcode a -preview or -exp model ID in production. Full treatment.

Prefill

The first phase of answering: reading the whole prompt in one parallel pass to fill the KV cache. It’s compute-bound and much faster per token than decode, often thousands of tokens a second. It’s the wait before the first word appears, and it’s what prefix caching saves. Compare Decode.

Prefix caching (prompt caching)

Reusing an already-computed KV cache for a shared prefix (a repeated system prompt, tool schema, or earlier conversation turns) across multiple requests, so unchanged text isn’t reprocessed from scratch every time. It’s exact-match: a single changed token anywhere in the prefix invalidates everything cached after that point. This is the mechanism agent economics depend on, since an agent resends a large, mostly-static prefix on nearly every turn. Full treatment.

PTQ / QAT

Post-Training Quantization compresses an already-trained model afterward, as a cheap, one-shot conversion. Nearly everything discussed on this site is PTQ. Quantization-Aware Training bakes simulated quantization noise into training itself, generally yielding higher quality at a given bit-width, at the cost of needing training compute rather than a quick conversion. Full treatment.

Q

Quantization

Storing model weights (and sometimes activations or the KV cache) using fewer bits per number than the original training precision, shrinking memory footprint and often raising throughput, at some cost to precision. Quality doesn’t degrade uniformly across all weights. Practical schemes protect the small fraction of weights that matter most. Full treatment.

Quantization suffix (Q4_K_M, Q5_K_S, etc.)

Three related but distinct GGUF naming grammars, not one shared template. K-quants: Q<bits>_K plus an optional _S/_M/_L suffix marking how many of the most error-sensitive tensors get selectively upgraded within that same bit family (Q4_K_M, Q5_K_S, or suffix-less Q6_K), not an independent size class. Legacy quants: Q<bits>_0 (Q8_0, Q5_0), plain per-block round-to-nearest with no K-quant super-blocks and no _S/_M/_L slot at all. I-quants: IQ is a prefix, not a letter code slotted after the number (IQ4_XS, IQ2_XXS, never Q4_IQ_XS), naming a non-uniform, codebook-based family with its own size codes (XXS/XS/S/M). Q4_K_M is a commonly cited reasonable floor for real reasoning or coding work. Full treatment.

R

RAG (Retrieval-Augmented Generation)

Pairing a model with a search step: at query time, relevant passages are found via embedding similarity and inserted directly into the prompt. The model’s answer is conditioned on that retrieved text. It does not give a model memory (retrieved text lives in the same context window as everything else and vanishes when the request ends), and it does not eliminate hallucination, since the model can still misread a passage, or the retriever can hand back the wrong one. Full treatment.

ReAct

The canonical agent-loop pattern: alternate a Thought (reasoning about what to do), an Action (a tool call), and an Observation (the real result fed back in), repeating until done. It’s still the same underlying next-token model: the “reasoning” step isn’t a separate planning module. Full treatment.

Reasoning / Reasoner (tier word)

A model-name marker for extended chain-of-thought: sometimes a genuinely separate checkpoint (Qwen’s -Thinking variants), sometimes just a toggle on one model (Anthropic’s Claude Opus 5 turns extended thinking on or off via a request parameter, same model ID either way). xAI takes the opposite, least-ambiguous approach: reasoning and non-reasoning ship as separate model IDs, not a toggle on one. Check which one a specific vendor means before assuming. Full treatment.

Residual connection

A design where a sublayer’s output is added to its input rather than replacing it, giving information from earlier in the network a direct path forward even when a given sublayer contributes little for a particular token. Both sublayers in a transformer block are wrapped in one. Full treatment.

RLAIF

Reinforcement Learning from AI Feedback: the same mechanism as RLHF, except the reward model is trained on AI-generated preference judgments instead of human ones, reported to reach comparable quality at lower labeling cost. Full treatment.

RLHF (Reinforcement Learning from Human Feedback)

Training a reward model on human preference rankings of model outputs, then further training the policy to optimize against that reward model. Its headline demonstrated effect is a preference effect (a much smaller RLHF’d model was preferred by human raters over a far larger non-RLHF’d base model), not a knowledge effect. RLHF reshapes style and helpfulness, not what a model factually knows. Full treatment.

RLVR (RL with Verifiable Rewards)

Reinforcement learning where the reward comes from an automatically checkable outcome (a passing test, a correct final number) rather than a human or AI preference judgment: the technique behind most current “reasoning” post-training. Whether it teaches genuinely new reasoning ability or mostly resamples what the base model could already do is a live, contested research question. Full treatment.

RoPE (Rotary Position Embedding)

The positional-encoding scheme used by most current models: it rotates the Query and Key vectors by an angle proportional to their position before the attention comparison happens. What gets used in that comparison is relative distance between two tokens, not an absolute address read off like a page number. Full treatment.

S

Scaling laws

Empirically fit power-law relationships between a model’s loss and the resources spent training it (parameters, tokens, compute), letting researchers predict the payoff of a larger run before spending the money. Chinchilla was the most consequential correction to the original versions of these laws. Full treatment.

Seat

DokiDex’s word for the one local model that answers the coding client by default. In the catalog it’s the row whose nature word is Thinking, and only one row holds that at a time. A seat earns the job on the golden suite. Other rows stay runnable by name as candidates. Full treatment.

SFT (Supervised Fine-Tuning)

Further training a pretrained model on curated (prompt, ideal-response) demonstration pairs: the first stage that teaches instruction-following behavior and response format. It doesn’t reliably add new facts the pretraining data didn’t already contain. Full treatment.

Sliding-window attention

Capping each token’s attention to a nearby window of positions, interleaved with occasional full-context layers, to cut KV-cache cost: one of the techniques that makes a huge advertised context window computationally viable in the first place. Full treatment.

Speculative decoding

Using a small, fast “draft” model to propose several tokens ahead, then having the large “target” model verify all of them in one parallel forward pass, accepting the longest correct prefix. Because verification is exact, the final output distribution is identical to running the target model alone: it changes speed, never quality, by construction. Full treatment.

Subagent

A child agent instance that runs a delegated, self-contained piece of work in its own isolated context window, returning only a summary to the parent rather than its full transcript. doki code’s task tool implements this pattern. A subagent can’t itself spawn further subagents. Full treatment.

SWE-bench (Verified / Pro)

A coding benchmark: given a real GitHub issue at a real commit, the model must produce a patch, scored by the repository’s own test suite. Verified is a hand-filtered subset near-saturated at the frontier. SWE-bench Pro is a harder, partly-private successor where the specific data split (public, held-out, or private/commercial) changes the reported score substantially. Never compare two SWE-bench Pro numbers without checking the split. Full treatment.

System prompt

A block of instructions (persona, rules, available tools, formatting constraints) placed ahead of the user’s messages, which the model is trained to weight more durably than an ordinary turn. It’s a strong steering signal, not a hard sandbox boundary. It’s still just text the model attends to, and can sometimes be made to leak or deviate from under adversarial prompting. Full treatment.

T

tau-bench / tau2-bench

Benchmarks where an agent must complete a task (airline, retail, telecom) by calling tools correctly while conversing with a simulated user under written policy constraints. Their signature metric, pass^k, measures success across k repeated attempts at the same task specifically to expose reliability problems a single pass/fail run hides. Full treatment.

Temperature

A number that rescales a model’s output probability distribution before a token is sampled: low temperature sharpens toward the most likely token, high temperature flattens toward more uniform selection. It has no mechanism for checking truth: at temperature 0 the model deterministically outputs its single most-likely token. That token can be confidently wrong. Lowering it buys consistency, not correctness, though that’s not the same as saying error rates are identical at every setting, which they aren’t. Full treatment.

Terminal-Bench

A benchmark where an agent operates a real sandboxed terminal (sysadmin, security, ML, data-science tasks) scored as binary pass/fail against defined checks. Scores for similar-tier models span a wide range depending on the agent harness wrapped around the model, which is why a Terminal-Bench number without a named harness is an incomplete citation. Full treatment.

Test-time compute

Spending more computation at answer time (longer reasoning traces, or sampling several candidates and picking the best) rather than only at training time. It inverts the usual falling-cost story: per-token prices keep dropping. But reasoning models spend far more tokens per query. So cost per task can rise even as cost per token falls. Full treatment.

Thinking (suffix / tier word)

At Qwen, a genuinely separate model checkpoint (-Thinking-2507 versus -Instruct-2507) trained to always emit extended reasoning. Elsewhere, it’s frequently just a toggle on one model rather than a distinct checkpoint. Check which one a specific vendor means before assuming. Full treatment.

Tier name

A tier’s name is its id, self-describing by construction (real model, per-request context in brackets, then what it is and what it costs you in parens, for example Qwen3-Coder-30B-A3B [128k] (Coding, Light)). A (Candidate, ...) name means a tier is still being judged. Any other nature word means it already cleared the bar for the role it holds. The autocomplete (fim) and embedding (embed) services are named for what they do rather than for a model, since they aren’t llama-swap rows.

The serving config used to carry a second, unrelated kind of alias that reused the word: real routing names llama-swap resolved, like the subagent seats and the four doki-* tiers the local-CLI skills selected by. The 2026-08-25 rename retired both kinds together. A model’s name is now the only name it has, and it’s something a request can actually ask for, not a label layered on top of one. Full treatment.

Time horizon (METR)

METR’s measure of the task duration, timed against human experts, at which a model succeeds half the time: a way of tracking sustained-task coherence rather than single-question accuracy. Its own confidence intervals run wide. Whether its reported doubling rate is a durable trend or an artifact of a narrow, fast-saturating task suite is explicitly unresolved. Full treatment.

Token / Tokenizer

A tokenizer splits input text into tokens (sub-word chunks, not words) before a model ever processes it. A token can be a whole common word, a fragment of a rarer one, or a single character. This is the real reason letter-counting questions (“how many R’s in strawberry”) trip models up: the word typically arrives as one or two chunks, never as individual letters. Full treatment.

Tokens per second

The speed figure for a local model. Always ask which phase it measures. Prefill and decode differ by 10x or more, and a prefill number quoted as “speed” flatters a model badly. The depth matters too, since decode slows as the KV cache grows. A number without its phase and context depth isn’t comparable to anything.

Tool use (function calling)

A model has no way to directly run code. It only generates text. Tool use works by describing available functions to the model up front. Mid-response, instead of prose, the model emits a structured request: a name plus arguments. The calling application is what actually executes the function and returns the result. The model only ever proposes a call, never runs one itself. Full treatment.

Top-p (nucleus) sampling

A sampling technique layered on top of temperature: it first truncates the candidate token set to the smallest group whose combined probability exceeds a threshold (commonly 0.9 to 0.95), then samples only from that narrowed set, preventing temperature alone from occasionally surfacing a very unlikely, nonsensical token from the distribution’s long tail. Full treatment.

Transformer block

The repeating unit of a modern LLM: a self-attention sublayer that lets token positions exchange information, followed by a feed-forward sublayer that transforms each token’s representation on its own, each wrapped in a residual connection. Stack this two-step block dozens of times and you have a modern LLM. Full treatment.

U

Uncensored / Abliterated

A post-hoc weight-editing technique (not a training stage) that finds the direction in a model’s activations mediating refusal and projects it out, with no retraining involved. Community-produced, with no safety guardrails, intended for research or red-teaming, not production. The edit can cost some capability, so a score measured on the stock weights doesn’t carry over. Re-run the evals on the edited file before trusting it. Full treatment.

Ultra (tier word)

Google’s historical marker for “largest, most restricted” in the Gemini 1.0 generation, largely retired by the 2.5/3.x generations. Not a portable signal: the word means nothing consistent outside that one now-superseded lineup. Full treatment.

UD quant (Unsloth Dynamic)

Unsloth’s GGUF builds marked UD-, such as UD-Q4_K_XL. Instead of one rule for every tensor, they pick each layer’s precision from measurements of how much that layer suffers when squeezed. The result usually beats a plain K-quant of the same size. Both of our seats run one.

V

Vals Index

An independent evaluator’s own composite benchmark score, built from evaluations it runs itself rather than relying on vendor self-reports: one of the few “third-party, not self-reported” composite scores in the field. Full treatment.

Vision-language model (VL marker)

A model-name marker meaning an image (sometimes video) encoder and multimodal training have been added on top of a text model: often a genuinely distinct branch, not a strict superset of the text-only sibling it’s paired with. Full treatment.

VRAM

The GPU’s own onboard memory, where a model’s weights and its KV cache must both fit for local inference. For a Mixture-of-Experts model, VRAM sizing is driven by total parameters, not active parameters: every expert has to be resident even though only a handful compute per token. Full treatment.

W

WDDM spill

On Windows, a GPU driven under WDDM doesn’t refuse a model too big for its VRAM. It quietly spills the overflow into system RAM and runs many times slower, or crashes later. A load that “worked” can still be oversubscribed, which is why we check free VRAM before trusting any speed number. Linux drivers usually fail loudly instead.

Weights

The large set of fixed numbers a trained model uses to turn an input into an output through repeated arithmetic, learned from data, not written by a programmer. There is no separate, searchable archive of training text sitting alongside them. The weights are the entire model. Full treatment.

Y

YaRN

A technique that reinterpolates an existing RoPE model’s rotation frequencies to extend its usable context length beyond what it was originally trained on, reported to need far fewer extra tokens and training steps than prior extension methods. Extending the technical context limit this way doesn’t by itself guarantee the model uses that extended length reliably. Full treatment.
