Evals & the Parity Ledger

Golden tasks, bake-offs, in-binary selftests, and a generated parity scorecard. How anything here earns the word "done."

Every stack this size accumulates claims. This chapter is about the machinery that keeps DokiDex’s claims attached to measurements. It’s the part that would be QA and CI in a game team, and is treated with the same seriousness: automated gates, golden tests, and a standing rule that a number nobody can regenerate is a rumor.

The golden-task suite

evals/ holds a 26-task golden suite of real coding tasks with objective pass criteria, run headlessly against a harness + model combination (run-eval.ps1 / run-suite.ps1). Eight of the tasks (t16 through t23) are Unreal-specific C++: delegate wiring, UCLASS/UPROPERTY boilerplate, and Build.cs module dependencies. These are the workloads a gameplay programmer would actually hand to an agent, included precisely because generic Python-flavored evals over-predict how well a model handles engine-flavored C++. Three more (t24 through t26), added around 2026-08-30, test image and game-loop generation rather than a text diff.

Discipline around the suite, learned the hard way:

  • results.jsonl is append-only. Aggregate latest-per-task at report time. Never edit history. Trend analysis (trend.ps1) and per-run scorecards (docs/scorecards/) read from it.
  • Separate plumbing failures from model failures. A harness that crashed mid-task says nothing about the model. Conflating the two poisoned early numbers, which is why they’re now tallied apart.
  • Small deltas are noise. Promotion requires a candidate to beat the incumbent, not tie it.

The record shows the discipline working, and the rejections are the best evidence: the claw competitor CLI bake-off’d at 45% with flaky tool calls and was rejected (its research write-up survives as a what-not-to-do reference). Nemotron-Cascade-2 scored 45% and was rejected. A REAP-pruned challenger had broken tool calls and was rejected. The Q5 quant never beat Q4 and was parked with the numbers. High reasoning effort on the big planner measured worse for coding, so the default stayed medium. Meanwhile -np 2 parallel slots and the 8B vision tier earned adoption through the same gate. Nothing in the roster is there on vibes.

Selftests: the binary tests itself

The stack’s GPU-free suites are the everyday floor: every tests/*.test.ps1 and *.test.py, discovered by glob rather than by a hand-kept list, so a suite added later cannot silently go unrun. That glob exists because a hand-kept list had already drifted: seven committed suites were running nowhere. Most of them extract the real function out of the shipping script by AST and run it, rather than reimplementing its logic in the test, because a second implementation in a test proves only that two copies agree.

The instrument worth singling out is the corpus check. doki-bench and doki-depth-eval both build their prompt corpus from a frozen set of source files, and both used to fall back silently to a smaller set if that directory was missing. When the directory in question was deleted, every future run would still have printed numbers, on a corpus a third the size, with a different hash, and no message anywhere. tests/bench-corpus.test.ps1 now pins the five corpus hashes the recorded runs were measured against, and proves the tools refuse rather than substitute. That is the shape this handbook keeps recommending: not “does the check pass” but “what would make it fail, and does that answer name the thing I just changed”.

This chapter also documented a generated parity ledger, docs/PARITY.md, which scored how completely DokiDex’s own agent recreated the Claude Code CLI across 124 checklist items. The agent and the ledger were both removed on 2026-09-02. Measuring your own clone against an upstream stops being a useful instrument once you ship the upstream.
