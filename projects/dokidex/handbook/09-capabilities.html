ARSENAL

Capabilities

The full inventory. Everything the stack does today, by surface, with the honest caveats attached.

The complete inventory as of this writing, organized by surface. Where a capability has a caveat, the caveat is part of the entry, because an arsenal you can’t trust the labels on is worse than a smaller one. (Feature-level detail lives in the generated ledgers and per-surface docs. This is the commander’s view.)

The coding agents (terminal)

  • Two real, unmodified clients, not a clone. Anthropic’s Claude Code CLI and GitHub’s Copilot CLI both run against the local server, launched by scripts/claude-local.ps1 and scripts/copilot-local.ps1 (or the doki claude / doki copilot verbs and the doki-claude / doki-copilot PATH shims). llama-server implements the Anthropic Messages API and the OpenAI chat-completions API natively, so neither client needs a translation proxy.
  • A seating ladder instead of a hardcoded model list. Claude Code’s /model picker offers the tiers the server actually reports resident rather than a table baked into the launcher, which in practice is the seat plus whatever cheaper model is loaded beside it. Background calls (session titles, one-shot helpers) route to that cheaper model automatically. -SonnetModel / -FableModel point a tier at a different llama-swap key when you want a real menu instead, at the cost of a weight swap on every switch, and -OneSeat puts every tier back on one model with none.
  • Config isolation, in both directions. A local run never touches your real %USERPROFILE%\.claude (or Copilot’s own config directory). The whole per-user surface redirects to an isolated home for the run, one that shares CLAUDE.md, skills, and agents with the global one but never sessions, history, or credentials. An ambient ANTHROPIC_API_KEY and a parent session’s identity are cleared before the client starts, so a local run can’t inherit a cloud credential or another session’s id by accident.
  • A telemetry session per run, tapped from llama-swap so nothing client-side has to cooperate. Skip it with -NoTelemetry for one run or DOKI_TELEMETRY=0 for good.
  • Four tier skills (/doki-cheap, /doki-work, /doki-think, /doki-max, in harness/claude-skills/), one per seat, so a task can ask for a specific tier without changing the session’s default model.

The serving layer

  • One endpoint (:8080) over hot-swapped llama.cpp processes, covering the named model roster, the Claude Code seat and the small utility row that used to sit beside it, and the eval-only candidates (chapter 3’s table). Alongside it: FIM autocomplete (:8012) and embeddings/code-RAG (:8090).
  • Four everyday models (gpt-oss-120b [128k] (Reasoning, Heavy), Qwen3.8-27B [256k] (Candidate, Standard), Qwen3-Coder-30B-A3B [128k] (Coding, Light), Qwen2.5-3B-Instruct [32k] (Utility, Free)), no alias in front of any of them, with four matching skills in harness/claude-skills/.
  • Prompt-cache discipline: 92 to 99% prefill reuse on agent turns, -np 2 parallel slots on the lite tier, and KV-quant plus flash-attention fitting 128k context in budget.
  • SHA-256-pinned model acquisition, per-model installer opt-in, template-generated llama-swap config that survives repo moves.

The control plane & distribution

  • doki.ps1 carries fifteen verbs in one ValidateSet: up, down, status, restart, logs, verify, start, stop, test, doctor, index, claude, copilot, version, help. That covers per-profile lifecycle, health-gated detached service starts, status json as the single machine-readable truth, doctor diagnostics, verify full-stack live smoke, and test as the no-GPU unit layer.
  • Four PATH commands ship alongside it: doki-claude, doki-copilot, and doki-manager on the local weights, plus zai-claude as the one cloud path (Claude Code on z.ai’s GLM models, billed, opt-in), backed by scripts/*.ps1 and the shims in scripts/shims/.
  • Distribution: a cloned checkout and setup.ps1, idempotent, with per-model selection driven by serving/model-manifest.json and a relocatable data root. The NSIS installer and its auto-update feed went with the Electron shell on 2026-09-02.
  • Test surface: PowerShell and Python suites for the installer, the memory store and the code RAG, plus the golden-task eval harness. (Exact counts drift with the tree. Run the suites for the live number rather than trusting any doc, including this one.)

The evidence layer

  • 26-task golden eval suite (8 UE C++ tasks), append-only results ledger, trend analysis, per-run scorecards, and the master decision log. That’s chapter 7’s machinery, listed here because the evidence discipline is itself a capability. It’s what lets this stack adopt or reject a model in an afternoon with a defensible answer. A generated parity scorecard used to be part of this list too, probing DokiDex’s own agent against Claude Code. It went with the agent on 2026-09-02.

What it deliberately does not do

Honest edges, stated as scope rather than apology: no cloud model fallback (the point is local, and adding one kills the privacy story quietly) · no Linux/macOS (native-Windows performance choices are load-bearing) · no multi-user tenancy (one owner, one box) · no image, video, music or speech generation, and no desktop app: all of it worked and shipped, and all of it was removed on 2026-09-02 to put the whole card behind agentic coding (archive.md names the commit) · subagents don’t parallelize inference on one card, they serialize through one seat.
