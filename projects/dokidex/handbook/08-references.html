References & Study Path

The papers, docs, and videos under this handbook, ordered as a study path, each with a reason to spend the time.

Everything in the preceding chapters stands on public work. This is the curated version, not a bibliography dump, just the specific items worth their runtime, ordered as a study path for a senior engineer who wants the theory under the practice. Time estimates are honest.

Start here: the mechanics of the primitive (a weekend)

  • Andrej Karpathy, “Deep Dive into LLMs like ChatGPT” (YouTube, ~3.5 h). The single best end-to-end treatment, covering pretraining, tokenization, fine-tuning, RLHF, hallucination and tool use, at exactly the depth a systems engineer wants. If you watch one thing, watch this.
  • 3Blue1Brown, “But what is a GPT?” + “Attention in transformers, visually explained” (YouTube, ~45 min total). The attention mechanism as animated linear algebra. Pairs with Karpathy the way a good diagram pairs with a good lecture.
  • Andrej Karpathy, “Let’s build GPT: from scratch, in code” (YouTube, ~2 h). Optional but transformative, a transformer implemented line by line. You’re reading this handbook, which means you learn by writing code. This is the one that makes it stop being magic.
  • Jay Alammar, “The Illustrated Transformer” (blog). The canonical visual walkthrough. It’s 30 minutes. The diagrams stay in your head.

The paper trail (an evening each)

  • “Attention Is All You Need”, Vaswani et al., 2017 (arXiv 1706.03762). The architecture everything in this stack runs on. Read after the videos, not before, because it’s terse.
  • “ReAct: Synergizing Reasoning and Acting in Language Models”, Yao et al., 2022 (arXiv 2210.03629). The agent loop, formalized: interleaved reasoning and tool use beats either alone. Short and readable.
  • “Switch Transformers”, Fedus et al., 2021 (arXiv 2101.03961). The Mixture-of-Experts scaling result behind chapter 3’s “parameter count is the library, not the working set.”
  • “Fast Inference from Transformers via Speculative Decoding”, Leviathan et al., 2022 (arXiv 2211.17192). Why a draft model can 2× decoding without changing outputs, which is context for the self-drafting candidate rows in the roster.

The practice: agents and harnesses (reference, not cover-to-cover)

  • Anthropic, “Building Effective Agents” (anthropic.com/research/building-effective-agents). The best vendor-neutral-in-spirit writeup of agent patterns: workflows against agents, and when a loop beats a pipeline. DokiDex’s architecture agrees with most of it and the disagreements are deliberate.
  • Anthropic, “Claude Code: Best Practices for Agentic Coding” (anthropic.com/engineering/claude-code-best-practices). The client this stack now drives directly, in its authors’ own words: instructions files, permission discipline, context habits.
  • Model Context Protocol, modelcontextprotocol.io. The spec behind the memory and code_search servers. The concepts page is a 20-minute read.
  • Agent Client Protocol, agentclientprotocol.com. Zed’s “LSP for agents,” the spec an IDE uses to drive an agent as a subprocess. This stack spoke it until 2026-09-02. The wire-format ground truth lives in research/acp-protocol-notes-2026-07.md.
  • Aider, “Repository map” (aider.chat/docs/repomap.html). The PageRank-over-symbols approach to giving an agent repo awareness inside a token budget, and the reference design for this stack’s next arc (chapter 10).

The machinery: local serving

  • llama.cpp, github.com/ggml-org/llama.cpp. The engine. The server README and the quantization discussions are the practical documentation of chapter 3’s flags.
  • llama-swap, github.com/mostlygeek/llama-swap. The hot-swapping proxy, small enough to read in an afternoon.
  • GGUF format spec, in the ggml repo (docs/gguf.md). The cooked-asset format, if you want the byte layout.

In-repo: the primary sources

The deepest material isn’t external. research/ holds the working corpus this stack was built from. These are the strongest entries for understanding how Claude-Code-class tools work:

  • research/cli-improvement-research-2026-07.md is a two-workflow study whose Part I alone ran 25 agents, and which includes a mechanism-level deconstruction of the real Claude Code binary. The single richest document in the repo.
  • research/coding-clis-2026-07.md is the build-vs-adopt landscape review of every serious open coding CLI (pi, aider, Crush, OpenCode…), and the reasoning behind which ones this stack drives.
  • research/ue-gamedev-models-2026-07.md covers model specialization for UE5 C++ work specifically: which local models know the engine, where they fail, and the eval evidence.
  • docs/decisions.md is the master decision log. Every adoption and rejection, with the gate results. When you wonder “why is X like this,” the answer is usually here, dated.
