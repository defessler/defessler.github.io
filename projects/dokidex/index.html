What DokiDex is

DokiDex is a local model server for agentic coding, with three surfaces over it:

  • The real CLIs, on your own GPU: Anthropic’s Claude Code and GitHub’s Copilot CLI, both unmodified, driving the local server with no translation proxy in between. llama-server speaks the Anthropic Messages API natively. See Run the CLIs locally.
  • The harness configs: crush and opencode wired to the same server, generated from the same model roster so a row can never drift out of a client menu.
  • The measurement kit: a golden coding-task suite, a context-depth eval, a benchmark runner that refuses to run on a busy card, and a telemetry tap that sits in front of every client.

DokiDex used to ship its own terminal agent too, doki code, a C++17 Claude Code clone tracked against a generated parity ledger. It was removed on 2026-09-02 to put everything behind the real clients instead. It worked, and it is in git history.

Everything runs on your machine. There are no API keys, no per-token bill, and no request leaves the box at inference time.

  • 256kContext window on the seated model, measured for depth not just fit
  • 32 GBVRAM the whole stack is designed around (one RTX 5090)
  • $0Marginal cost per token, forever
  • 0Bytes of your code sent to a third party at runtime

Note: the context figure is the window the seat actually runs, and it is gated on retrieval rather than on fitting. doki-depth-eval buries facts at percentage depths through a real-source haystack and scores exact recall, with a control needle that reports a broken harness rather than a model score. A window that fits but cannot be read from is not a feature.

Why local, honestly

Local inference isn’t strictly better than a frontier API. This site won’t pretend it is. What it is:

  • Private by construction. Not “we don’t train on your data.” The request never leaves. There is exactly one opt-in exception. A GitHub Copilot row you have to name by id to reach is the only thing here that talks to anyone else.
  • Free at the margin. The GPU is a sunk cost. The ten-thousandth token costs the same as the first, which changes what you’re willing to spend tokens on.
  • Always available. No rate limits, no outages, no deprecation notice retiring the model you built a workflow around.
  • Yours to modify. Swap the model, requantize it, prune experts out of it, fine-tune it.

And what it isn’t: the strongest model you can get. A 30B model on a consumer card doesn’t match a frontier reasoning model on the hardest tasks. The gap is real. The open vs closed page puts numbers on it instead of hand-waving.

Learn AI here too

Half this site isn’t about DokiDex at all. Building a local stack means confronting every layer of how these systems work: what a parameter is, why Q4_K_M is a reasonable default, what “30B-A3B” tells you about memory, why a benchmark score is usually overstated. We wrote it down as we learned it. It turned into a course:

  • Level 1 Foundations Tokens, context, inference, sampling, and why models hallucinate.
  • Level 2 How models work Transformers, attention, the KV cache, training stages, tools, RAG.
  • Level 3 Advanced MoE routing, quantization theory, RL post-training, test-time compute.
  • Reference Decoding model names What MoE, 23B, A3B, Flash, mini, Instruct, and Q4_K_M actually mean.
  • Just tell me What's actually good Straight picks by task, with the evidence, and where the honest answer is still "nobody knows".
  • Look up Quick reference Every table on the site, in one place, for when you just need the number.
