Video Tutorial

Step 1: Tag An Actor

Every video uses the same demo level: one room placed three times, as Wing_A, Wing_B, and Wing_C, each with an orange door, and a blue switch in front of them.

An actor can only be pointed at once it carries a Tether component. The doors in the demo already have one from their class. This video adds one to the ground, which is a plain engine StaticMeshActor, to show that any placed actor can take it.

  1. Select it: click the actor in the Outliner, so the Details panel shows it.
  2. Add the component: click "Add" at the top of the Details panel, type "Tether", and pick it.
  3. Leave it as it is: the component has nothing to fill in. The ID it relies on is one the engine already gives placed actors.

Adding the component to a class or a Blueprint tags every actor you place from it. Adding it to one placed actor tags only that one.

Step 2: Pick One Door

A Tether Ref property shows up in the Details panel as a single row with a dropdown. The dropdown lists everything tagged in the level, laid out like the Outliner, with each room opening like a folder. Three copies of one room give you three doors to choose from.

  1. Select the switch: its "Target Door" row reads "None" to start with.
  2. Open the dropdown: each copy of the room lists its own door.
  3. Pick the door: the row now reads the door's name, then, in dimmer text, the room it's in.

The ✕ button next to the row clears it back to "None". Only the door you picked is the target. The other two copies are untouched.

Note:

The AllowedClasses metadata on the switch's C++ property is what limits this dropdown to doors. It only works on C++ properties, since a Blueprint variable can't carry that metadata. The "Extra Doors" list has no filter. It offers every tagged actor, the ground from step 1 included.

Step 3: Rename, Move, And Duplicate

The ref points at the door's placement, not at its name or its spot in the level. This video changes all of those and checks the switch after each one.

  1. Lock the Details panel: the lock icon at its top right keeps the switch on screen while you select other things.
  2. Rename the room: select Wing_A, press F2, and type "North Wing". The row picks up the new name by itself.
  3. Move the room: the row doesn't change, since position was never part of the link.
  4. Duplicate the room: Ctrl+D makes a copy with a door of its own. The dropdown now lists both. The ref stays on the original.

Moving actors between Outliner folders is safe too. A handful of editor actions do change an actor's ID, and the last section of this page covers them.

Step 4: Read The Ref In Blueprint

A ref on its own just remembers a door. To do something with the door in game, turn the ref into the actor with the "Get Actor From Tether Ref" node.

  1. Add a variable: under "My Blueprint", add one and set its type to "Tether Ref".
  2. Add the node: right-click the "Event Graph" and search for "Get Actor From Tether Ref".
  3. Wire it up: feed it the ref, pick the class you expect in "Actor Class", and use the return value.

The node returns the actor, or None when it can't, for example when the ref is empty, its target isn't loaded, or the target isn't the class you asked for. Its owner pin is hidden and set to self, since a ref is resolved from the actor that holds it. In C++ the same call reads: 

if (ADoor* Door = UTetherLibrary::ResolveTetherRef<ADoor>(this, TargetDoor))
{
    // Open it, highlight it, and so on.
}

Tether Refs also work in arrays, sets, and maps, in C++ and in Blueprint.

Step 5: Build The Switch Into The Room

So far the switch sits in the main level and points at one copy. When the switch is part of the room itself, you want every copy of the room to open its own door. Tether handles that by storing the ref relative to the room.

  1. Open the room's level: every copy in the demo comes from this one asset.
  2. Place a switch inside the room and pick the room's door, the same way as in step 2.
  3. Save the room: back in the main level, each copy of the room has its own switch.

Both actors live in the same level. The ref is stored relative to that level. Each copy's switch resolves to the door in its own copy, including copies you load at runtime. Picking a door from outside the room makes a ref to that one placement.

Troubleshooting

Fixing Broken Refs

A ref usually stops resolving for one of three reasons: its target is gone, its target lost its Tether component, or its target got a new ID. In all three the row in the Details panel changes. The plugin's checks report it too.

To run the checks by hand, right-click the level in the Content Browser and choose "Asset Actions" -> "Validate Assets", or type "Validate" into the menu's search box. Results land in the Message Log. Each one names the actor that holds the ref. Click the name to jump to it. The same checks run when you save, if your project validates on save.

A Deleted Target

  • The row - It keeps the door's saved name and room, and adds "not loaded".
  • The report - In a map without World Partition, like the demo, a warning that the ref "matches no actor in the loaded levels". In a World Partition map it's an error, since the editor can check unloaded actors too.
  • The fix - Undo the delete with Ctrl+Z, or open the dropdown and pick a door again.

"Not loaded" doesn't always mean deleted. In a big World Partition world the door's part of the map may just be streamed out. The ref starts resolving again as soon as it streams back in.

A Removed Tether Component

  • The row - The entry can't resolve any more.
  • The report - An error that the actor "has no UTetherComponent, so it never resolves".
  • The fix - Add the component back. The ID belongs to the actor. Every ref to it works again.

Removing the component from one placed actor only affects that actor. Its siblings from the same class still work.

An Actor With A New ID

  • The row - It shows "not loaded", even though a door is still standing there.
  • The report - The same "matches no actor" message as a deleted target. In a World Partition map it's an error that names these three actions and asks you to re-pick the target.
  • The fix - Open the dropdown and pick the door again. It's listed on its own now, outside any room.

Three editor actions copy actors under the hood, which gives the copies new IDs: "Move to Level", "Create Level Instance" from a selection, and "Break" on a level instance. Refs to those actors need picking again. Moving things between Outliner folders doesn't count.
