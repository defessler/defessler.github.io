wlm:~$ wlm --tutorial basics

The Main Window

Profiles live in the left sidebar. The selected profile's windows fill the right pane, one row per window: the app, its title at save time, and where it goes back to.

The Coding profile: six windows across two monitors and two virtual desktops.

  • ⌨ chip - The profile has a global hotkey.
  • ● / ○ dot - Bound / not bound to a monitor setup (see auto-activation).
  • Footer hints - The whole app drives from the keyboard: j/k to move, Enter to load, / to filter, ? for the full map.

wlm:~$ wlm --tutorial profiles

Saving & Loading Layouts

Arrange your windows the way you like, hit "+ new profile", name it, done. WLM captures every visible window's position, size, state (normal, minimised, or maximised), monitor, and virtual desktop.

  • Load - Puts every captured window back, even after apps restarted, titles changed, or Windows shoved everything onto one screen. The matcher re-finds windows by process, class, title, owner, and position.
  • Update - Re-captures the current arrangement into the selected profile. Your hotkey, binding, history, per-window colours and "recognise by" rules, and Docking Bays all survive.
  • Load details - A per-window report of the last load: what matched, what moved, what was missing.
  • A Load is one pass. It's finished when it returns. Nothing keeps moving windows afterwards. If an app is slow to open its windows, press the hotkey again.
Profiles are plain JSON in %APPDATA%\window-layout-manager\profiles (the "FOLDER" button opens it). They're hand-editable, with schema autocomplete in most editors.

wlm:~$ wlm --tutorial hotkeys

Global Hotkeys

Click the hotkey chip on any profile and press the combination you want. WLM records it live and warns about conflicts with other profiles or the auto-activation hotkey.

Hotkeys fire from anywhere. The WLM window doesn't need to be open.

wlm:~$ wlm --tutorial display

Display Zoom, Resolution & Arrangement

A profile can set your display scaling (the percentage in Settings → System → Display that everyone calls zoom), your resolution, and where your monitors sit, before it puts your windows back. Click the Display chip on any profile to set it up.

Every dropdown is filled from what Windows reports for that monitor. Nothing is hardcoded.

Displays are named by where they are and what size they run ("Left 4K", "Right 1080p"), because Windows reports the same "Generic PnP Monitor" for nearly every one. A virtual display says so.

  • Scaling - Pick a percentage, or Step up one / Step down one. The steps move one rung along whatever ladder that monitor supports, worked out when you press the key, which makes them the ones to put on a hotkey.
  • Resolution - Every mode the driver offers, with its refresh rate. Leave a dropdown on "Leave unchanged" and the profile won't touch it.
  • Each row shows what the monitor is set to right now, which is what you're changing from.

Arranging Your Monitors

Drag a monitor in the picture at the top and it moves, the way the numbered boxes move in Windows' own Display Settings. A monitor dropped onto another gets pushed back out. One dropped in empty space gets pulled back into contact. A short drag still just selects.

Hold Shift while dragging to snap to the nearest edge, with a line marking what the two displays now line up on. Without Shift the monitor lands exactly where you dropped it. From the keyboard, select a display and press Shift plus an arrow to nudge it 10 pixels (the step is set in Settings → Auto-activation), or Ctrl+Shift plus an arrow for a tenth of that. The presses add up. The Position fields under the picture take an exact offset. A value that would leave a display touching nothing is refused. The editor says so. Along an axis two displays already share an edge on, neither can move. The editor names the axis that's free. The primary display's fields are switched off, since it's the origin everything else is measured from. Moving the primary shifts everything else the opposite way, because Windows pins it to 0, 0.

Windows enforces three things about any arrangement and rewrites yours if you break them: the primary sits at the origin, nothing overlaps, and every display touches another. WLM settles the layout before writing it, and tells you if closing a gap means moving a display you weren't touching.

Saving the profile saves the arrangement with it. Positions are stored for every display, not just the ones you moved, because "the portrait one is on the left" means nothing without the rest. Apply now tries the whole thing on your real displays with the usual 15-second Keep-or-Revert countdown. The revert puts the arrangement back too.

Ctrl+Z and Ctrl+Y work inside the editor before anything reaches your displays. The editor names what it took back: Undid: moved a display. Holding an arrow key down is one step. Two things start the trail over, because both leave it describing a desk that's gone: a monitor arriving or leaving, and Apply now.

A chip under the picker says which of three things is true. The button beside it does the matching thing:

  • Not saved with this profile → Save this arrangement. Pins your monitors where they sit right now. This works without dragging anything, which is how you capture a desk that's already right.
  • Changed from your current arrangement → Revert. Puts the boxes back where your monitors physically are. It leaves a saved arrangement alone.
  • Saved with this profile → Remove arrangement. Drops the arrangement without touching the rest of the display step.

Changing Several Monitors Together

Ctrl+click adds or removes a monitor, Shift+click takes the run between two, the same gestures the visual editor uses for windows. Pick several and you get one set of controls that applies to all of them, offering only what every one of them can do. Where they disagree, the editor says so. Scaling reads now mixed. The control offers a "Multiple values" option that leaves each display as it is, in place of "Leave unchanged". Orientation only changes if you actually choose one. A landscape and a portrait display together don't get the second one rotated by accident.

Earlier Arrangements

The countdown covers the change you just made. History in the display editor covers the one from yesterday. WLM records your arrangement before each change it applies, whatever triggered it. Each row draws the desk as it was, with the primary picked out. Use this draws that arrangement in the editor. Nothing moves until you press Apply now. The list belongs to the monitors it describes. A layout from your desk is never offered on a different set of displays. A row naming a monitor you no longer have is greyed out and says which.

Your Windows Come with the Monitors

Swap your left and right monitors and the windows come with them, keeping the same spot on the same panel. Minimised and maximised windows are left alone. A maximised window already follows its monitor. A minimised one has no position worth keeping.

Zoom to Resolution Rules

These live in Settings → Auto-activation → Zoom to resolution rules, because they describe your hardware, not a layout. Pair a percentage with a resolution for a display. From then on, whenever that display is set to that zoom, the resolution comes with it, by a profile, a step hotkey, or anything else.

Every rule names its display and says how it finds it.

Rules are filed against the part of a display's hardware identity that doesn't change between sessions. One set for a Parsec virtual display still applies next time you connect. Two displays of the same model stay separate, because the key includes which output each one is on.

Picking a Resolution

Resolution is two dropdowns, one for size and one for refresh rate, the way Windows and NVIDIA both do it. Sizes are grouped by shape (16:9, 4:3, 21:9) and the largest one is marked. Some displays offer a lot of them (one test machine reports 227 modes). The size list has a search box at the top. Type 1440 for every mode with 1440 on either side, 2560 1440, 2560x1440, or just 25 14 for that one, or a word to search the labels. Arrow keys, Home, End, Enter, and Esc all work in the list. Pick a size that can't do your current refresh rate and WLM keeps the rate where it can, otherwise falls back to the highest that size offers and tells you it did.

The orientation dropdown sits before the resolution, because it decides what resolutions there are. Windows only reports sizes for the orientation a display is currently in. WLM works out the list for the one you pick. Flipping between landscape and portrait keeps the same physical resolution selected. Sizes are written long side first whichever way the panel faces. A rotated monitor reads 2560×1440. What's sent to Windows stays in the orientation Windows is speaking.

A mode your display doesn't currently offer is still saved, flagged not offered yet, and applies the moment the driver starts listing it. That matters for virtual displays, whose mode lists change with what the driver has been told about.

Custom Resolutions

A virtual display only offers what its driver knows about. WLM names the driver behind yours: Parsec, Apollo, spacedesk, the community Virtual Display Driver, a Remote Desktop session, a virtual machine's adapter. Parsec is the only one that publishes a way for another app to add resolutions. On a Parsec display the Custom resolutions button under the resolution list registers two of them behind one administrator prompt. Disconnect and reconnect the session and they show up in Windows and in WLM's dropdowns. On any other virtual display the same button reads About this display and says who can change the list: spacedesk takes it from the client device, Apollo builds its display to match each stream, the community driver reads a settings file of its own.

Select that one display on its own and the button is there. Where one driver runs several displays it's on any of them, because the sizes are registered with the driver. With none of that driver's displays up it appears only where a profile asks for a size the driver doesn't list, which is how you register a size before the next session.

The rows WLM didn't write are read-only, marked with a dash instead of a slot number. Parsec rewrites those itself on every connect.

Two limits worth knowing:

  • They won't appear in Parsec's own resolution picker. That list is fixed. Apply the resolution from WLM instead. Setting Parsec's host Resolution to "Keep Host Resolution" also works, since it stops Parsec overriding what WLM sets.
  • Parsec owns three of the five slots. It rewrites slots 2, 3, and 4 on every connect with your client's screen sizes. WLM only touches slots 0 and 1.

Zoom Presets

Tick Display-only preset and the profile stops being a window layout. No windows saved, no windows moved, just the scaling and resolution.

"Desk zoom" is a display-only preset on Ctrl+Alt+0.

It's still a profile. It gets a hotkey, a spot in the tray menu, the Jump List, the command palette, --load=, and wlm:// links. Display-only presets are kept out of auto-activation. One can't beat the layout profile you actually wanted.

Turning It On, and What It Can't Promise

The kill switch is under Settings → Auto-activation → Display configuration, on by default. Turn it off and a profile's display step is skipped on load. WLM says that's why.

Changing resolution uses a documented Windows API. Changing the scaling percentage doesn't, because Windows exposes none. WLM uses the same internal call the Settings app does, behind a capability check. If your build stops accepting it, the scaling controls switch off and say why. Resolution carries on working. Ask for a percentage your monitor can't do and you're told it was clamped, and to what. After every change WLM re-reads the display to check the value landed, which catches a Windows 11 24H2 bug where a resolution change on a virtual display reports success while nothing happens. Some virtual adapters, Parsec's among them, report a scaling range that disagrees with what Windows is doing. Where that happens the editor shows both numbers and says the control may not behave.

wlm:~$ wlm --tutorial visual

The Visual Editor

Switch the view to "VISUAL" for a minimap of your saved layout: monitors to scale, one tab per virtual desktop, every window draggable.

Drag to move, corner-drag to resize. Hold Shift while dragging to snap to monitor edges and to other windows.

  • Arrow keys nudge whatever is selected: 10 pixels a press, or 1 with Shift. A nudged window crosses onto the next monitor the way a dragged one does. Holding a key down is one undo step.
  • Select a window to get "Edit", "Block app", and "Remove" in the panel below the canvas. Enter edits it, x or Delete removes it.
  • Select several at once the way you select files: Ctrl+click adds or removes one, Shift+click takes everything between what you clicked and where you started, and Ctrl+Shift+click adds a run to what you already had.
  • With more than one selected, the panel offers move to monitor, set state, remove, and Group into Docking Bay. Position and size are deliberately left out, because one X applied to twelve windows stacks all twelve.
  • Drag a window between monitors and its target monitor and relative position update on their own.
  • Every window can be given its own colour from the edit dialog, so that the ones you care about stand out.
  • Edits auto-save after a beat. The "unsaved" badge tells you when a write is pending.

Reaching a Window Behind Another

The "+N" badge says something is under a window and clicking cycles through the stack. To drag the one underneath, fold the one on top: each window has a collapse control that shrinks it to its title row. "Collapse overlapping" in the legend folds every window that's covering something.

Collapsed windows in the same stack cascade instead of stacking. Every one stays clickable.

This is a viewing aid only. A collapsed window still loads at its full size. The folding is forgotten when you switch profiles.

wlm:~$ wlm --tutorial bays

Docking Bays

A Docking Bay is a named group of windows inside one profile. Arrange three windows the way you like and group them. From then on you drag, rename, and move the group as one thing, with the spacing inside it intact.

Grouping Windows into a Bay

Select two or more windows in the visual editor, then press "Group into Docking Bay" in the strip below the canvas. The name comes from the apps inside: one app names the bay after itself, two get joined with a plus ("Visual Studio Code + Google Chrome"), three or more name the first and count the rest ("Google Chrome + 2 more"). If no member has a readable app name it's called "Docking Bay" until you rename it. Click the name in the strip and type over it to rename.

The outline is worked out from its members every frame. It can't drift out of step with the windows inside it.

On the canvas a bay is a dashed cyan outline under its members, solid when the whole bay is selected. Clicks pass straight through it. In the list view a member row carries the bay's name as a chip and a mark down its left edge.

Working with a Bay

  • A plain click on any member selects the whole bay and the strip below the canvas becomes the bay strip. Ctrl+click a member to get at it on its own.
  • Drag any member and the whole bay goes with it. Hold Shift and the group snaps by its own outer edges, which is what lands it flush against a monitor edge.
  • "Move to monitor…" in the strip sends every member to that display with the offsets between them intact. The group is re-anchored at the top left of the new display, inside whatever space the taskbar leaves, because members may have come from several displays and there's no one spot to carry across. A bay too big for the display keeps its top left on screen and overhangs.
  • A bay can span two monitors, since each member picks its display from its own centre. "Move to monitor…" is how you gather it up again.
  • "Ungroup" leaves every window where it is. "Remove" drops every member from the profile. To take one member out, Ctrl+click it and remove it alone. When the last member goes the bay goes with it.
  • Select some of a bay's members and "Group into Docking Bay" splits them into a new bay. Select members of two bays and it merges them. A bay of one window is legal. Its strip gains an "Edit window" button.
  • Every one of these goes on the undo trail under its own name. History lists each on its own line.

What a Bay Doesn't Do

Resizing isn't group aware: drag a member's corner and that one window changes size. A window belongs to at most one bay. Bays don't nest. A bay belongs to its profile. A window you drag by hand while Hold mode is on keeps its bay, its colour, and its match rule.

Both members crossed together and the gap between them is unchanged. That gap is the whole point.

Docking Bays save with the profile and survive an Update. They cost nothing at load, because members go back the way any window does. In the JSON it's two fields on each window, bayId and bayTitle, repaired on the next save if a hand edit leaves them disagreeing.

Precise Edits, Undo & History

"EDIT" on a list row or "Edit" under the canvas opens exact fields for any window: desktop, monitor, state, the colour it's drawn in, and pixel-perfect position and size. Hovering a list row brings up a card with a scaled picture of where that window sits, its size, its position, and its state.

Every dialog in WLM is a real window. You can drag it onto a second monitor, resize it, and find it in alt-tab. It opens at the size its content needs and won't shrink below that. The app is disabled while a dialog is up. A stray keystroke can't land behind it. Two things stay inside the app window instead: Settings and the hotkey capture. Two more, Custom resolutions and Earlier arrangements, open from inside the display editor and are drawn in its window rather than as a third one.

How a Window Gets Recognised

Apps rewrite their titles as you work. A window saved with an exact title stops being found the moment it says something else. "Recognise by" at the bottom of the edit dialog lets each window choose:

  • App and its exact title - the default.
  • App and a title starting with... - for the part that stays put. "Inbox" still finds "Inbox (3) - Gmail".
  • App and window type, any title - for apps that rename constantly.

The looser two require the window class and type to match instead. The rule you set also applies to the last-resort match on the app alone.

  • Ctrl+Z / Ctrl+Y - Undo and redo any edit, with a labelled trail.
  • Ctrl+H or "History" - Browse and restore full saved versions of the profile. Every Update keeps a snapshot.
  • Windows tracked live (see Hold mode) also keep a per-window position history you can roll back individually.

wlm:~$ wlm --tutorial auto-activation

Monitor Binding & Auto-Activation

Bind a profile to your current monitor setup and WLM can restore it by itself whenever that setup reappears: docking the laptop, starting a Parsec session with a virtual display, plugging into the projector.

  • Triggers - On monitor change, at app launch, and a dedicated hotkey. All off by default.
  • Best-guess remap - When your monitors almost match a saved setup, WLM picks the closest mapping, applies it, and remembers the decision so it never asks twice.
  • The "Status" panel logs every decision. You can always see why a profile did or didn't fire.

wlm:~$ wlm --tutorial hold

Hold Mode

The "Hold layout" toggle (next to the hotkey chip) pins a profile as the live layout. While holding, WLM watches your windows a few times a second:

  • If an app moves or resizes its own window, it gets put straight back.
  • If you drag a window yourself, WLM records the move into the profile instead of fighting you.
  • Loading a different profile releases the hold. Explicit action always wins.
Hold is ideal for apps that "helpfully" reposition themselves after fullscreen games, RDP sessions, or monitor sleep.

wlm:~$ wlm --tutorial desktops

Virtual Desktops

On Windows 11, profiles capture which virtual desktop each window lives on. Load sends every window back to its desktop and creates missing desktops if the profile needs more than exist. The visual editor shows one tab per desktop. The per-window editor can reassign a window to any desktop, or leave it "Unmapped" to stay where it is.

wlm:~$ wlm --tutorial keyboard

Command Palette & Keyboard

Ctrl+K opens the command palette: every action and every profile, fuzzy-searchable.

  • Vim-style navigation in both panes: j/k, gg/G, / filter, Tab to switch panes. Both lists wrap at the ends.
  • On the focused profile: Enter load, r rename, d delete, n new. Moving through the profile list previews each one on the right, without loading it.
  • In the windows pane: Enter edits the window under the cursor and x removes it. The keyboard follows the mouse. A click on the canvas puts the next key there.
  • Arrow keys nudge selected windows in the visual editor, and a selected display in the display editor with Shift held. The display step is 10 pixels by default, changeable in Settings → Auto-activation.
  • ? shows the complete keyboard reference.

wlm:~$ wlm --tutorial updates

Updates

WLM checks this site's update feed on launch and on a schedule you control. When a new build is out, a badge appears in the title bar. One click downloads, verifies the file against its published size and sha256, and swaps the new build in place.

wlm:~$ wlm --tutorial blacklist

Blacklist

Keep noise out of your captures. Rules match on process name, window class, or title. "Block app" in the visual editor adds one in a click. Blacklisted windows are ignored at save and at load.

wlm:~$ wlm --tutorial companions

Companion Software

The "Companion software" tab detects complementary tools and offers one-click installs for whatever's missing: PowerToys for drag-snap zones, Parsec for remote desktop, virtual display drivers for headless monitors, PowerShell 7 for scripting. For the ones you have it reports the installed version and asks winget whether an update is waiting. Each app can also update itself in the background on a cadence you set in Settings → Updates. Most of these are system-wide packages, which Windows won't let an unelevated app update. Those come back saying they need administrator rights.

The tab draws immediately and fills in what it found a moment later.

Detection also looks at installed drivers and at what's on your PATH, since some software never registers itself in the usual place. That's how PowerShell 7 shows up.

wlm:~$ wlm --tutorial diagnostics

Diagnostics & Reporting a Bug

The "Diagnostics" tab shows the app version and the exact paths WLM reads and writes. "Copy to clipboard" grabs the whole dump. "Open profiles folder" and "Open crash log" take you straight to the files.

"Report a bug" and "Request a feature" open a short form. You see exactly what gets sent before anything leaves your machine. The diagnostics dump is optional. Your Windows username is stripped out of the paths. Issues are public. Anything you type there is too.

wlm:~$ wlm --tutorial window

Window Positions & About

The app window remembers the size and position you leave it at. Dialogs don't: each one opens at the size its content needs, every time.

Settings is a fixed panel inside the main window. It reads the same on every machine.

"About" carries the running version, the licence, and where your profiles live.

wlm:~$ wlm --tutorial cli

CLI, Links & Automation

  • WindowLayoutManager.exe --load="Coding" - Load a profile from a script, a Task Scheduler job, or a Stream Deck button. Works whether or not WLM is already running. Add --show to raise the window as well.
  • wlm://load/Coding - The same, as a clickable link, except that a link never runs the profile's post-load command. wlm://show raises the window.
  • Taskbar Jump List - Right-click the WLM taskbar icon for one-click profile loads.
  • Post-load hook - A profile's JSON can carry a postLoad command (e.g., switch an OBS scene) that runs after a successful load from the app, a hotkey, or --load.
  • WLM lives in the tray. Closing the window keeps hotkeys, Hold mode, and auto-activation running.
