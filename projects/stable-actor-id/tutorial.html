StableActorId: Set Up A Reference

References to one specific placed actor in Unreal Engine 5.8, keyed on the engine's per-placement guid, so they survive renames and the level-instance boundary where soft object paths break.

Before You Start

This page is meant to talk about setting up a stable actor reference from scratch: one actor that can be referenced, another that points at it, and the code that finds it at runtime. You'll want the StableActorId plugin in your project's Plugins folder. It's enabled by default. There's no .uproject entry to add.

Step 1: Make An Actor Referenceable

Add a UStableActorIdComponent to the actor you want to point at. In a Blueprint, use "Add Component" and pick "Stable Actor Id". In C++, create it as a default subobject: 

UPROPERTY()
TObjectPtr<UStableActorIdComponent> StableActorId;

ABeacon::ABeacon()
{
    StableActorId = CreateDefaultSubobject<UStableActorIdComponent>(TEXT("StableActorId"));
}

There's nothing to fill in. The component's only field, PlacementId, stays empty in the editor. You can also add the component to a single placed actor in the details panel, which works for engine classes like a StaticMeshActor.

Step 2: Add A Reference To Another Actor

Add an FStableActorRef property to the actor that needs to point at the first one: 

UPROPERTY(EditAnywhere, meta = (AllowedClasses = "/Script/MyGame.Beacon"))
FStableActorRef TargetBeacon;

AllowedClasses is optional. It limits the picker to those classes. Data Validation also flags a ref that points outside them. It only works on C++ properties, since a Blueprint variable can't carry that metadata.

Step 3: Pick The Target

Place both actors, select the one with the reference, and find its row in the details panel: 

 Target Beacon      [ None  ▾ ] [✕]

Open the dropdown. It's a Scene Outliner showing only actors you can point at. Level instances expand like folders. If your beacon sits inside a room you've placed three times, you'll see three entries and can pick the one you mean. Once you pick, the row shows the target's label, then the level instances it sits in, in dimmer text: 

  Target Beacon      [ BP_Beacon  Wing_A.Room_3      ▾ ] [✕]

The ✕ clears it back to "None". If the target isn't loaded, the row still shows its label and level instances, read from the World Partition actor descriptor or from the labels saved at pick time, with "not loaded" after them.

Note:

There's no eyedropper. Clicking level-instance content in the viewport selects the whole level instance. The outliner is the reliable way in.

Step 4: Resolve It At Runtime

Resolve the ref when you need the actor. Don't keep the pointer around: 

void AMySwitch::OnInteract()
{
    if (ABeacon* Beacon = UStableActorIdLibrary::ResolveStableActorRef<ABeacon>(this, TargetBeacon))
    {
        Beacon->Light();
    }
}

In Blueprint, call "Get Actor From Stable Actor Ref" and pick the class. It returns null when the ref is unset, when the target's level isn't loaded, when the target is a different class, or when more than one actor matches.

Step 5: Validate

Right-click your level in the content browser and run "Validate Data". Saving it with validate-on-save turned on works too. The check flags refs that can't resolve, like a target that lost its component or one that was moved to another level.

Going Further: Containers

Refs work in a TArray, as a TSet element, and as a TMap key or value. Each element gets the same picker row. An AllowedClasses on the container applies to every element. 

UPROPERTY(EditAnywhere)
TMap<FStableActorRef, int32> DoorKeyCodes;

If Something Looks Wrong

The row says "not loaded"
The target's level isn't loaded, which is normal under World Partition. If it still says that with the level loaded, the target was probably moved to another level or into a level instance. Re-pick it.
The picker doesn't list my actor
Check it has a UStableActorIdComponent, that it isn't a child actor, and that it matches the property's AllowedClasses.
The resolve returns null
Check the context object is in the world you expect. In PIE, pass a PIE object like this, not an editor object.
It works in the editor but not in a packaged build
Run Data Validation first. The packaged path relies on the cook bake, which hasn't been confirmed in a full packaged build at time of writing.
