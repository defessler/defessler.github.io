Plain Language

How It Works, Without The Jargon

Every actor placed in an Unreal level carries a hidden ID that the engine made up when the actor was placed. Think of it as a serial number. It's unique, it never changes, and when you place a room three times, each copy of the door inside gets its own.

A "Stable Actor Ref" is a small note that holds one of those serial numbers, plus the door's name so the note still reads sensibly when the door isn't around. When the game needs the door, the plugin looks through the actors that have the tag and hands back the one whose serial number matches.

If two actors ever had the same serial number, the plugin refuses to guess and gives back nothing. Opening the wrong door silently would be worse than opening no door, and the editor's checks tell you about the clash long before that.

For Engineers

The Technical Version

The identity is the engine's per-placement actor instance guid: the actor's ActorGuid, combined with the guids of the level instances above it. In the editor the plugin takes the engine's stamp where one exists and folds that chain itself where it doesn't, which is a level instance open for editing. Nothing is minted. 

UPROPERTY(EditAnywhere, meta = (AllowedClasses = "/Script/MyGame.Door"))
FStableActorRef TargetDoor;

if (ADoor* Door = UStableActorIdLibrary::ResolveStableActorRef<ADoor>(this, TargetDoor))
{
    Door->Open();
}

Resolution

Each UStableActorIdComponent registers with a world subsystem as its level becomes visible and leaves when it's hidden or destroyed. A resolve is a hash lookup in that set by placement id, and returns one actor or null. Refs are equal when their guids are. That lets them work as TSet elements and TMap keys.

Packaged builds

A cooked build releases the engine's instance guid before gameplay runs. So during a cooking save, the editor module writes the live guid into the component, and restores the editor copy afterwards. At runtime the plugin reads that baked value, folding the level-instance guid back in for Standalone level instances. This path is measured from a staged packaged build: five probe maps covering Embedded, Standalone, nested, classic, distance-streamed, and runtime-loaded level instances resolve every reference to the right placement, with nothing landing on a wrong actor.

Validation

UStableActorIdValidator runs under Data Validation. It indexes every loaded actor by placement id and checks each tag and each ref, including refs inside containers and components. Under World Partition it also reads the actor descriptors. That lets it tell "not loaded" apart from "gone".

Honest Limits

What It Doesn't Do

  • It points at things placed in a level, not things spawned while the game runs.
  • "Move to Level", "Create Level Instance", and "Break" give an actor a new ID. Refs to it need re-picking. Validation flags them.
  • Two placements of one room share nothing, which is the point. A ref picks one copy and never "all copies of this door".
  • Finding a door walks the tagged actors in the level. Call it when something happens, not every frame, if you have thousands of tags.

StableActorId is open source. The code, the usage reference, and the engineering records live in the repository. The wiki is the deep technical reference.
