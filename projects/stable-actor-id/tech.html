StableActorId: The Tech, And What It Costs

References to one specific placed actor in Unreal Engine 5.8, keyed on the engine's per-placement guid, so they survive renames and the level-instance boundary where soft object paths break.

Why This Page Exists

This page is meant as a quick reference on the pieces StableActorId is built from, why each one was picked, and what it costs. Check out How It Works for the design and the tutorial for setup.

The Stack, And Why Each Piece

The Engine's Instance Guid As Identity

FActorInstanceGuid already tells apart every placement of a level-instance asset, survives renames, and survives outliner moves. Reusing it means there's nothing to mint, heal, or keep unique. The cost is that the engine owns it. When the engine changes an actor's guid, as it does on "Move to Level", refs to that actor break.

A Plain Value Struct For The Ref

FStableActorRef is a USTRUCT with a guid and a label. It works anywhere a property does, in containers too. It serializes as tagged properties. Equality and hashing go by target only. WithIdenticalViaEquality makes reflection agree with C++. That keeps the details panel's duplicate check for sets and map keys in line with the hash.

A Component That Registers Itself

UStableActorIdComponent is the opt-in. It adds itself to a world subsystem in OnRegister and removes itself in OnUnregister. That ties the subsystem's contents to component registration, which follows level visibility. A resolve only looks at stable actors in loaded, visible levels. It costs a UObject per stable actor. A designer can also remove it from one placed instance without anything else noticing.

A Cook-Time Bake

FCoreUObjectDelegates::OnObjectPreSave writes the live guid into the component during a cooking save. UPackage::PackageSavedWithContextEvent and UE::Cook::FDelegates::CookFinished restore the editor copy. It runs in the editor module, since the cook commandlet runs the editor. It's the only part that can't be tested end to end without a cook.

Writes Through The Property Handle

The details row writes a pick with SetValueFromFormattedString, never into raw memory. Only the handle path rehashes a TSet or TMap after a key changes and refuses a duplicate.

Engine Data Validation

UStableActorIdValidator derives from UEditorValidatorBase. The engine registers it and runs it on save, on demand, and from the commandlet. Under World Partition it reads actor descriptors, which list every actor whether it's loaded or not.

Headless Automation

Five StableActorId.* tests run through UnrealEditor-Cmd with no window. They spawn actors into scratch worlds. They need no content.

What You Get

  • References to one specific placement, including one placement out of several of the same level-instance asset.
  • No change when an actor is renamed or moved between outliner folders.
  • A details row with an outliner picker, an AllowedClasses filter, and a readable label even when the target isn't loaded.
  • Refs that work as array elements, set elements, and map keys.
  • Validation that catches leaked bakes, shared ids, and broken refs.

Risks, Honestly

The Cooked Path Hasn't Run In A Packaged Build

The bake and the baked read are covered by tests that drive them directly. A full packaged build resolving a baked ref hasn't been run at time of writing. A cook in July 2026, against the older design, did show the hooks firing inside a World Partition cook.

Some Editor Operations Break Refs

"Move to Level", "Create Level Instance", and "Break" all copy the actor under the hood. The copy gets a new guid. Refs to the old one stop resolving. Data Validation reports these under World Partition. The editor row shows the old label with "not loaded", which looks the same as a target that just hasn't streamed in.

Runtime-Spawned Actors Can't Be Saved Targets

An actor spawned in a packaged build has no baked guid. Nothing can point at it across sessions. Refs are for placed actors.

Resolve Cost Grows With Stable Actors

A resolve walks the registered stable actors in the world. That's far cheaper than the world scan it replaced. It isn't a map lookup, though. You'll want to call it on events rather than every frame when there are thousands of stable actors.

The World Partition Broken-Ref Check Is Untested

It needs a saved World Partition map with stable actors in it. It refuses to report unless its rebuilt ids agree with every loaded stable actor. A mistake should make it quiet rather than wrong.

The Label Ships

CachedLabel and CachedLevelInstancePath cook into every configuration's data. Shipping empties them on load. They're still on disk.

When To Use This, And When Not To

Use it when one placed actor needs to point at another specific placed actor, especially across level instances, and the reference has to survive renames and reorganizing. A switch that opens one door, a spawner that targets one waypoint, and a trigger that wakes one encounter are the cases it's built for.

Skip it for references to assets, which TSoftObjectPtr already handles well, and for actors spawned at runtime. If you're only referencing actors in the same level that never move between levels, a plain actor reference may be all you need.

StableActorId targets Unreal Engine 5.8. The design records, the usage reference, and the verification log live in the repository alongside the source. The wiki is the technical reference.
