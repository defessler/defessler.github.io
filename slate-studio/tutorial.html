Ten Minutes With Slate Studio

The parts of this tool that don't work like the tools you already know. The editor is a tab away and it opens on a panel you can take apart. Read a section, then go poke at it.

Slate Studio is a visual builder for Unreal Engine Slate layouts. If you write Slate by hand you already know the loop: edit the widget chain, compile, launch, look, repeat. The declarative syntax is pleasant to read and slow to iterate on, because every look costs a compile. This tool draws your layout with the real thing while you edit, and the C++ it writes is an ordinary SCompoundWidget that it reads back again.

What's on Screen

You start on a sample panel rather than an empty sheet. There's something to change straight away.

  • Palette, Hierarchy, Properties, and Templates share the left dock, with Templates starting collapsed. Click any panel's title bar to fold it, or drag that bar to move the panel to another dock.
  • The Generated C++ pane has the right dock to itself.
  • Canvas in the middle, rulers around it, status bar underneath with the zoom stepper in it.

Only one of those is the real thing. The Document is a tree of windows and widgets. The canvas and the C++ pane are both drawn from it. Edit either one and you edited the Document, which is why they never disagree. Hold on to that and the rest of this page is mostly consequences.

Widgets Live in Slots

Slate is a box-and-slot layout. A panel like SVerticalBox owns a list of slots, each slot holds one child, and the slot (not the child) decides how much room that child gets. This is the part that trips people up coming from Figma, and it's also what makes a Slate layout resize properly for free. A widget has no position of its own. What you control is order, nesting, and slot rules.

Windows are the exception. A window has an x and a y and you drag it by its title bar, with Shift snapping it to the grid. Everything inside it flows.

Order and Nesting

Drag rows up and down in the Hierarchy, use the ↑ ↓ buttons on a row, or press Ctrl+↑ and Ctrl+↓. Order in the tree is order on screen. Drop a row onto a container to reparent it. The panels are the containers: Vertical Box and Horizontal Box stack their children, Overlay layers them, and Border and Box wrap a single child.

Slot Rules

Every widget carries its slot's settings as ordinary properties, so you edit them in the Properties panel like anything else:

  • Slot Size - "auto" gives the child exactly the room it asks for, which is AutoHeight() in the code. "fill" hands it a share of whatever is left, which is FillHeight(weight), and the weight sets the share.
  • Slot H Align and Slot V Align - where the child sits inside its slot when the slot is bigger than the child.
  • Slot padding - space around the child, one value per edge.

The sample panel uses a fill-sized Spacer to push its buttons to the bottom, which is the idiom you'll reach for constantly. There's no anchor or dock setting to hunt for. A spacer with a fill slot is how Slate spells "push everything after me to the far edge".

Dropping a Widget

New widgets come out of the palette. Click a tile to append one to the nearest container that'll take it, or drag it onto the canvas and pick the spot yourself. The indicator under the cursor tells you what the drop will do before you let go: a horizontal line inserts above or below the widget you're over, and a box around a container means the drop goes inside it.

Select It, Then Change It

Click a widget on the canvas or its row in the Hierarchy. It's one selection shown three ways: the canvas outlines it, the tree highlights the row, and the C++ pane marks the lines it produced.

Properties sits on the left under the Hierarchy. Fields differ per widget, and every widget gets the slot rules from the last section on top of its own. A green dot after a field name means you've moved it off its default. The ⟲ beside it puts that one property back.

Windows carry their own set: the title, and the position and size they open at. You can also just drag the window by its title bar and resize it by its corner grip. The document keeps up either way.

The Preview Is Real Slate

The canvas is not a picture of what Slate would draw. It's Unreal Engine 5.8's SlateCore and Slate modules compiled to WebAssembly, laying out and painting your document with the same code the engine runs, Starship styling included. If a font measures differently or a border insets by 2px, that's the engine telling you, not an approximation guessing.

Hold Space and the preview goes live: buttons press, checkboxes tick, sliders drag. Let go and you're back to editing with the selection you had. Press Tab to stay in Live mode instead.

Note: whatever you set while poking around is the preview's own state, not the Document. It never reaches your generated code.

The Code Pane Goes Both Ways

The pane on the right regenerates as you work, and it holds the whole document, root included. Each window becomes its own SCompoundWidget class, which is how UE code actually ships: you write the widget, and something else owns where it goes. That something else is in the file too: OpenStudioWindows() at the end creates each SWindow with its title, size, and position, hosts the class inside it, and hands it to the application.

The sample panel's headline and a save button come out like this:

void SAccountSettings::Construct(const FArguments& InArgs)
{
    ChildSlot
    [
        SNew(SVerticalBox)
        + SVerticalBox::Slot()
            .AutoHeight()
            [
                SNew(STextBlock)
                .Text(LOCTEXT("Account_Settings", "Account Settings"))
                .Font(FCoreStyle::GetDefaultFontStyle("Regular", 14))
            ]
        + SVerticalBox::Slot()
            .AutoHeight()
            [
                SNew(SButton)
                .Text(LOCTEXT("Save", "Save"))
                .OnClicked(this, &SAccountSettings::OnSave)
            ]
    ];
}

void OpenStudioWindows()
{
    TSharedRef<SWindow> AccountSettingsWindow = SNew(SWindow)
        .Title(LOCTEXT("Account_Settings_2", "Account Settings"))
        .ClientSize(FVector2D(380.f, 300.f))
        .ScreenPosition(FVector2D(30.f, 30.f))
        .AutoCenter(EAutoCenter::None)
        [
            SNew(SAccountSettings)
        ];
    FSlateApplication::Get().AddWindow(AccountSettingsWindow);
}

Every user-facing string is a LOCTEXT, so the file carries its own LOCTEXT_NAMESPACE pair and localizes like the rest of your project. A widget with a handler gets a member declared and defined for it, with the right delegate shape: an OnClicked returns FReply, an OnCheckStateChanged takes the new state. Copy at the top of the pane takes the lot.

And Back Again

The pane is read-only until you say otherwise. Press Edit in its header and the text becomes an editor, with Apply and Cancel where Edit was. Type C++, press Apply, and it parses back into the Document. Cancel throws the edit away. What survives a trip out and back:

  • Every property the generator writes, slot rules included, and the window frames in the opener. Move a .ScreenPosition in the text and the window moves on the canvas.
  • Handler names. The member bodies are regenerated from them, so a body you filled in belongs in your project, not in the pane.
  • Formatting inside generated blocks is normalized on the way back.
Note: nothing you type is thrown away. A chain call the tool doesn't model (a .ToolTipText, say) is kept verbatim on its widget, re-emitted after the modelled calls, and editable in the Properties panel under "Extra Code". A widget CLASS the tool doesn't know is kept whole as a Raw Slate block: the code stays byte for byte, the preview marks the spot with a placeholder, and any include it needs is yours to supply in your project. The status line under the pane says what was kept either way.

Where Your Work Lives

Saved in the browser as you go, and the tab strip above the canvas holds several projects at once. Nothing is uploaded anywhere. Switching projects starts a fresh undo stack. Ctrl+Z can't reach back into a document you left.

  • File > Export JSON writes the document to a file you can commit. Import JSON reads one back.
  • Share, top right, copies a link with the document packed into the URL. Nothing is stored on a server.
  • File > Reset to Sample puts the starting panel back. It asks before discarding what's there. Ctrl+Z undoes it anyway.
Note: because the browser does the saving, clearing site data for this domain clears your projects with it. Export anything you'd be sad to lose. The slate and imgui pages keep separate storage, so work on one never touches the other.

Templates Are Worked Examples

The Templates panel sits at the bottom of the left dock, collapsed until you click its title. It holds five worked examples: a blank window, a login form, a settings panel, an about dialog, and a status card. Each is a small document that already works, so it's a starting point and the reference for its feature at the same time. The login form shows the fill-spacer idiom, the about dialog is mostly slot alignment, and the status card nests Border, Box, and Overlay three deep.

Click a name, or its ＋, and the template's widgets land in the nearest container of your selection. Drag a row onto the canvas instead to put them where you drop. Right-click a row for the bigger moves: Apply Here replaces the current document (it asks first), and Open as Project puts the template in a new tab and leaves your document alone.

Save Current at the top of the panel adds what you built to the list, named after its first window. Export writes your custom templates to a JSON file and Import reads them back, which is how a team shares one library.

Keep Going

The fastest way to learn a feature here is to open the template that uses it and pull it apart.

  • ? opens the shortcut list, built from the same table the app dispatches on. Click any row to rebind it.
  • Ctrl+K is the command palette for anything without a key. / opens the same picker filtered over the widget types.

Some corners are rougher than others. If the editor and this page ever disagree, the editor is right.
